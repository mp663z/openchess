# T0455 identity rate-limit contract

`data/contracts/rate_limit.yaml` is a reference-only contract for admission on public `identity.register` and `identity.login`. It does not add live HTTP middleware. The existing job token bucket and billing quota have different scopes. An injected operator policy and clock drive two independent, operation-scoped fixed-window buckets: a canonical account key and a trusted-edge canonical source key. Both must have room. An admitted new attempt increments both in the same transaction as the identity effect; a denied attempt changes neither. Concurrent decisions must not over-admit. Counters persist across restart. This is a design choice for the reference, not a claim that the control-plane already implements it.

A repeated byte-identical Idempotency-Key outcome is replayed without charging a bucket; a key reused with a different canonical body conflicts without charge. This follows the source transport rule, while the namespace of public unauthenticated keys remains unresolved. Denial uses the declared `rate_limited` code and `{code, message, retryable}` shape. The source has no HTTP status or retry header for this code. It also has no declared value for `retryable`; this contract must not promise one. Do not confuse this with `quota_exhausted`.

This is not enough to ship fixtures or enforcement. The structured `unresolved` section requires a reviewed normalizer for account aliases, trusted source extraction and NAT, public idempotency namespace, concrete operator thresholds/windows, policy migration and abuse tradeoffs. Until a policy is configured and those choices are pinned, fail closed without identity effects. The reference tests exercise an injected synthetic policy and opaque keys, not a production default. In particular, no raw email, IP or credentials may enter telemetry. Existing source privacy and error-envelope rules still apply.
