## v1 failed independent review (d62a0b45)

Real bypass: approve() trusted the caller-supplied proposal["diff_hash"]
without recomputing; commit() only checked hash presence in _approvals; the
hash excluded `action`; approver_role was any caller-supplied string. The
verifier reproduced an approve-then-mutate replay that audited a destructive
action under an approved hash, and fabricated dicts with stolen hashes.

## v2 remediation

- Immutable typed Proposal (frozen dataclass): action + target/scope +
  before/after. There is no caller-supplied hash field at all.
- The hashed artifact covers the FULL proposal; canonical JSON serialization,
  no default=str (unserializable payloads raise, fail-closed).
- approve() recomputes canonical + sha256 from the live proposal,
  constant-time compares (hmac.compare_digest), and stores the canonical
  artifact bytes - not just the hash.
- commit() revalidates type, recomputes canonical + sha256, and
  constant-time compares BOTH the hash and the stored canonical bytes; the
  committed proposal must be byte-identical to the approved artifact.
- Approvers are a registry (identity -> role); unregistered identities are
  rejected and the recorded role always comes from the registry.
- Approvals remain single-use; every commit lands in the audit log with
  identity, role, action, target, and artifact hash.

Tests (tests/test_no_silent_writes.py, 13): unapproved write raises; approved
write commits and audits; binding to exact diff; action in artifact;
target/scope in artifact; before/after mutation with stale hash rejected;
fabricated-hash dict rejected; malformed proposals rejected; invalid approver
rejected + registry-sourced role; gate requires approvers; single-use;
audited artifact byte-identical to approved; approval record immutable.
Commands: `pytest tests/test_no_silent_writes.py -q`.
