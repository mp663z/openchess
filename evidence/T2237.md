# T2237 Replay harness - evidence (groundwork stage)

Implementation: backtest/replay.py
- ReplayHarness owns the event store; scoring input builders receive a read-only strictly-past view (event_time < decision_time). Labels computed from the 30-day forward view at export time, never entering scoring inputs.
- Weekly decision points; every score, every action (surfaced/held) and every 30-day label (useful/reverted/no_change) emitted into a versioned audit log (schema_version 1, JSON export).
- Leakage checks: LeakageError on any view violating causality; structural test asserts future events never reach the builder; order-shuffle test asserts identical scores/actions.

Acceptance -> tests (tests/test_replay.py, 7 tests): completeness of emitted scores/actions/labels, strict past/future separation, shuffle-invariance, label semantics (useful/reverted/no_change), deterministic export.

Scope note: this is the harness groundwork on synthetic fixtures. The full 2024-2025 replay additionally needs the corpus extract pipeline on external compute (T2714 verdict) and the T2723 full-corpus audit; board completion also requires independent verification (routed with SHA when the full replay lands).
Commands: `pytest tests/test_replay.py -q`. Environment: python 3.11, stdlib only.
