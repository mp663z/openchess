# T0072 Chess/en-passant/unit/property

## Normative requirements

1. tests/test_t0072_en_passant_property.py checks properties of the production `graph.en_passant` over 8696 seeded generated (state, move) cases and 2046 distinct states (seed 72, no new dependencies). An independent model written in the test judges them: a ray-scan attack detector (a different algorithm from the runtime's piece scan, cross-checked against it on 3000 random boards) and the contract's structured fields read from data/contracts/en_passant.yaml.
2. Properties, each checked on every case:
   - P-total: an exact state or a typed `EnPassantError` of a contract class with the contract's code; no raw escape.
   - P-atomic, P-deterministic: inputs unchanged, outputs share no object with inputs, two calls agree.
   - P-side, P-lifetime, P-delta: the turn passes; the target is set exactly by a pawn-advance of a pawn from the start rank to the to-rank on the same file, and every other move clears it; the board changes by exactly the move (the en-passant victim leaves the captured square, never the destination).
   - P-capture-sound, P-capture-complete: an en-passant outcome agrees with the preconditions and with the independent detector on the RESULTING board, and each failure class names a precondition that failed.
   - P-precedence: with several faults, the class follows the current order: grammar (target_malformed), none target (capture_precondition), occupied target square (target_inconsistent), target rank or victim (target_inconsistent), geometry (capture_precondition), pin (pinned_capture). The contract doesn't fix an order. Every order fails closed, so this pins current behaviour.
   - P-identity: `identity_value` is the target exactly when some adjacent pawn's capture succeeds through `apply` and the independent model agrees; it is the sentinel otherwise; canonicalising the target is idempotent.
   - P-mirror-colour, P-mirror-file: flipping ranks with colours, or flipping files, maps every outcome (value or class) of `apply` and `identity_value`.
   - P-turn: `turn_transition` over its whole closed domain, from the contract's turn linkage.
3. The generator reaches every class for both sides, set and unset targets, identity kept and dropped, and near misses of the set-on event (a quiet two-square pawn move, a diagonal two-rank advance, a non-pawn advance). 14 named edge rows (7 for White, each with its colour mirror): the only capturer on the a- or h-file, the target on the a- or h-file, the landed pawn as the only blocker on a file and on a diagonal, and the rank pin opened by the double removal.
4. Hostile rows (coordinator rule, 20:47), 76 of them. They cover `apply` (state and move), `identity_value` and `turn_transition`:
   - a list subclass and a dict subclass at state, occupied and move;
   - keys in three forms (plain str subclass, `__eq__` raises, renamed key whose `__hash__` collides with the field) for every state key, move key and an occupied square;
   - the three hostile str forms for every str value.
   Each row pins: typed `target_malformed` with its code and no `__cause__`, an empty hostile-call log, and the input unchanged (a fingerprint read with base methods only). 17 malformed-domain rows (exact types, values outside the closed domain) pin the same.
5. 52 one-line source mutants (the 40 from T0071 plus 12 new) each violate a pinned, exact set of properties (`EXPECTED_KILLS`). 5 equivalent edits stay green. Every property is killed by some mutant except P-atomic and P-deterministic: no one-line edit of the current copy-based source breaks them, so they stay as regression properties.

## New mutants

Prose only. `NEW_MUTANTS`, `EQUIVALENT_EDITS` and `EXPECTED_KILLS` are the authority.

- Identity file bounds: `0 <= f` made `0 < f` (a-file) and `f <= 7` made `f <= 6` (h-file).
- Set-on from-rank and to-rank checks removed.
- Adjacency without `abs` (right neighbour only).
- Pin judged on the original board; landed pawn not placed.
- Moved piece not placed; moved piece's origin kept.
- Side not passed on a non-capture.
- The input occupied map aliased.
- Availability checked for White only (colour-asymmetric, killed by P-mirror-colour among others).

Equivalent, asserted green:
- Identity bounds widened to -1..8 or removed: an off-board neighbour never holds a pawn, so the capture fails its geometry and the loop continues.
- Neighbours probed in the other order.
- Adjacency `!= 1` made `> 1`: a same-file mover square is the victim square, which already holds the enemy pawn, so the mover-piece check fails with the same class.
- Victim rank taken from the mover rank: the contract gives both sides the same rank.

## Occupied target square (coordinator ruling)

The first version of this battery found a production defect: an en-passant capture onto an occupied target square wasn't rejected. Another piece on the target was deleted, and the mover's own king on it raised a raw `StopIteration`. Ruling: fen.yaml pins target_square: empty, so an occupied target is `target_inconsistent` (illegal_position). The fix is in the two commits before this one: the T0069 reference and graph.en_passant, with T0071 rows and mutant `occupied-target-check-off`. The generator now puts a piece on the target in about 6% of states: the mover's own king in half of those, any other piece in the rest. There are 213 occupied-target en-passant cases plus the 4 reference rows. The model classes them `target_inconsistent`, right after the none-target check.
