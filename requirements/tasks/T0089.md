# T0089 Chess/FEN/implement

## Normative requirements

1. `graph.fen.parse_fen` (the shared parser every graph runtime links) is total over hostile payloads: anything that is not an exact str, including str subclasses, fails as a typed `FenError("malformed_fen")`. So does a counter beyond the interpreter's int-string limit (4300 digits), as a fresh typed FenError: not the forged object, no `__cause__`. This closes the T0088 required-external-boundary red delta.
2. Every T0087 fixture row (happy, boundary, malformed with its minimal repair, rollback) gives the pinned result, failure class and code.
3. Parity with the T0086 contract reference (`tests.test_t0086_fen_contract.parse_fen`/`emit_fen`): same outcome by value, class and code over every fixture FEN, every single-character edit, deletion and insertion of them, a seeded sweep of 12000 generated positions aimed at the position rules, and pinned rows the sweep reaches only rarely (pawn checks in both colours and on both diagonals, non-attacking pawns, occupied en-passant target and origin squares). Every accepted FEN round-trips byte for byte.
4. The T0088 red tests pass bound to the runtime. The raw-parser red delta is closed: the reference still leaks raw errors on those payloads, while the runtime raises a typed FenError.
5. Atomicity: the contract is never mutated, each parse returns fresh objects, and a rejection never changes the next parse.

## Change to graph/fen.py

- An exact-str check at the top of `parse_fen`.
- `int()` on a counter runs in a narrow `try/except ValueError`, and the failure is raised after the handler exits. The typed error is fresh: a fresh typed FenError, not the forged object, no `__cause__`. `__context__` is not asserted (wal ruling).
- Nothing else changes. Every other line is the T0086 reference logic, and parity pins it.

## Forge scope

graph/fen.py raises only `FenError`, and its one except clause names only `ValueError`. The AST test pins both sets. A forged `ValueError` raised from the counter conversion yields a fresh typed error. A forged `FenError` has no entry channel: after the exact-str check, no caller-controlled code runs (every operation is on an exact str and on contract data).

## Mutants

This list is prose only. `MUTANTS` and `EQUIVALENT_EDITS` in the test file are the authority. Each is a one-line source edit of graph/fen.py, compiled from source (no bytecode cache), and each is killed by the fixture rows, the pinned rows, the hostile battery or the parity sweep.

- Boundary: exact-str check removed or made isinstance; the int-limit handler re-raises.
- Grammar: field count, rank count, adjacent digits, digit flag not reset after a letter, any character accepted as a piece, rank sum removed or weakened to at-most, active colour, side to move inverted, leading zeros, counter minimum removed or off by one, castling order, en-passant length, file and rank.
- Position rules: white and black king counts, back-rank pawns (one side only, or white pawns only), promotion budget removed or loosened, non-mover check removed or aimed at the wrong king, castling king and rook home checks, en-passant side to move, double-advanced pawn, occupied target, occupied origin, halfmove clock.
- Attack relation: pawn attack removed or direction inverted, knight attack removed, sliders see through blockers, queen dropped from orthogonal or diagonal attackers.
- Emit: trailing empty run dropped.

Equivalent (asserted green, reason per entry in the test file): empty-field check (each field has its own non-empty guard); empty-rank check (sums to 0); counter regex off or match-not-fullmatch (the int round trip rejects every non-canonical counter); castling letter and duplicate checks (the order projection rejects both); king adjacency off or strict (the check rule rejects it); pawn and piece maxima (the promotion budget rejects both); king attack off (adjacency runs first); raising the typed error inside the int-limit handler (fresh, not forged, no `__cause__`; `__context__` is not asserted, per the wal ruling).
