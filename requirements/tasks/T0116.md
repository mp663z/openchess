# T0116 Chess/position digest/implement

## Normative requirements

1. `graph.position_digest` is total over hostile input. The rejection classes:
   - In `digest_fen`, a variant that is not an exact str (including str subclasses) fails as `unknown_variant`. The exact-str check runs before the registry lookup, so no caller `__eq__` runs.
   - A FEN that is not an exact str, or a counter over the int-string limit, fails as `malformed_position` (the linked parse_fen is total since T0089).
   - `parse_digest`/`emit_digest` fail a non-str or str-subclass text as `malformed_digest`. They never raise a raw TypeError and never return the caller's object.
   Every typed error is fresh: not a forged object, no `__cause__`. `__context__` is not asserted (wal ruling).
2. Every T0114 fixture row (happy, boundary including digest equivalences, malformed with its repair, rollback) gives the pinned digest, text, class or equivalence.
3. Parity with the T0113 contract reference (`tests.test_t0113_position_digest_contract.digest_fen`/`parse_digest`/`emit_digest`): same outcome by value, class and code. It covers:
   - more than 4000 FENs from the T0089 sweep (single-character edits of the FEN fixtures plus generated positions), for the declared variant and an unknown one;
   - 12 en-passant identity rows (capturable from either side, no adjacent pawn, rank, file and diagonal pins, own king already in check, both colours), which split both ways between "target counts" and "target ignored";
   - a digest-text sweep (every single-character edit, deletion, padding, length and prefix variant).
4. The T0115 red tests pass bound to the runtime.
5. Outputs are exact str. The cached contract documents are never shared or mutated by callers.

## Mutants

This list is prose only. `MUTANTS` and `EQUIVALENT_EDITS` in the test file are the authority. Each mutant is a one-line source edit, compiled from source. Each is killed by the fixture rows, the hostile rows, the digest-text parity or the en-passant and FEN parity. `ep-landed-pawn-not-placed` (the capturing pawn is not put on the target square before the king-safety check) is killed only by the landed-pawn blocker rows; `encode-variant-constant` (the variant component hard-coded to "standard") only by the two-entry registry row. `ep-file-lower-bound-exclusive` (`0 <= f` made `0 < f`) only by the a-file rows; `ep-file-upper-bound-short` (`f < len(files)` made `f < len(files) - 1`) only by the h-file rows; `ep-first-neighbour-decides` (the sentinel returned after the first adjacent pawn fails) only by the pinned-first-capturer rows.

- En-passant identity:
  - the none target returned as-is;
  - mover side inverted;
  - only one neighbour probed;
  - adjacent-pawn check off;
  - own pawn colour inverted;
  - captured pawn or mover kept on the board;
  - pin check off;
  - attacker side inverted;
  - check judged on the original board;
  - always the sentinel.
- Encoding:
  - castling sentinel dropped;
  - side to move constant;
  - raw target instead of the identity value;
  - field order reversed;
  - separator dropped.
- Digest:
  - prefix dropped;
  - uppercase hex.
- Inputs:
  - variant exact-str check off or isinstance;
  - registry check off;
  - variant and position classes swapped;
  - digest text exact-str check off or isinstance;
  - match or search instead of fullmatch;
  - emit returns its input unchecked.

Equivalent, asserted green:
- dropping the neighbour-file bounds check (an off-board file is never a board key, so `.get` returns None and the loop continues).
- widening the bounds to file -1 or to len(files) (same reason).
- probing the neighbours in the other order (the target is kept if any capture is legal).
