# T0125 Graph/transposition node/implement

## Normative requirements

1. `graph.transposition_node` implements `NodeError`, `NodeTable(docs=None, digest_fn=digest_fen)` with `insert`, `merge`, `records`, `serialize`, `validate_record(nc, vc, dc, ec, fc, record, digest_fn=digest_fen)`, `load_docs()` and `FAILURE_MAPPING` for data/contracts/transposition_node.yaml (contract id `chess-transposition-node`). It links only the shipped `graph.fen` and `graph.position_digest` runtimes and never imports `tests.*`.
2. Records are exactly `{variant, digest, snapshot_fen}`: registry variant id, digest in the linked format, canonical snapshot with the en-passant identity value and clocks `0 1`. Identity is the linked `canonical_fields` tuple; the digest is the bucket key only. Insert is insert-or-return-existing; a digest collision is separated by field comparison; merge freezes the source (exact list; each record must be an exact dict and is copied before validation), validates every frozen record before any insertion, then inserts the frozen records (never the caller's live records, which an oracle could rewrite) into a staged copy of the buckets that the table adopts only after every insert succeeded; a rejected insert or merge (including an oracle failure midway through the insert phase) leaves the table, its bucket dict and bucket lists unchanged. `NodeTable()` parses fresh contract documents per table. The linked parser's input rejections - `FenError` and the raw `ValueError` int() raises on a clock beyond the interpreter's integer-string limit (4300 digits) - map to `malformed_position` on insert and `malformed_node_record` on validate/merge, fresh and unchained. `other` in `merge(other)` is the caller's own argument, not an untrusted component: a raising `other.records()` propagates unchanged.
3. The injectable digest oracle is untrusted: every call runs behind an `except BaseException` boundary, and any raised error (including a forged `NodeError` of any class, `FenError`, `DigestError` of any class, `VariantError`, `ContractError`, and `BaseException` subclasses) or any output that is not an exact str in the linked digest format fails closed as a FRESH, unchained `malformed_node_record` (never the forged object, no `__context__`/`__cause__`). The forge set covers every error the module raises, re-raises or catches (AST-enumerated): `NodeError` per class, `FenError`, `ValueError`, `AssertionError`, plus the linked `DigestError` per class and `VariantError`/`ContractError`. Input failures (`unknown_variant`, `malformed_position`) are decided before the oracle is called.
4. The T0124 red battery turns green by replacing only its binding import. Every scenario stays unchanged.

## Divergence from the contract reference

The T0122 reference used to let a raising digest oracle escape raw, raise a raw ValueError on a >4300-digit clock, and merge from live source records. Coordinator ruling (Sep 24): fail-closed is correct and those were gaps in the reference. The T0122 reference follow-up closes all three: the reference now runs every oracle call behind the same `except BaseException` boundary (raised error or non-format output -> fresh `malformed_node_record`), maps the parser's raw `ValueError` to the typed class (`malformed_position` on insert, `malformed_node_record` on validate/merge), and takes frozen exact-dict copies of the source records before any oracle call. Parity cases (production == reference): `test_r2_raising_oracle_parity_fails_closed` (forge set of both modules: each module's NodeError per class, both linked FenErrors and DigestErrors, VariantError, ContractError, ValueError, AssertionError, TypeError, RuntimeError, BaseException subclasses), `test_r2_bad_oracle_output_parity_fails_closed`, `test_r2_huge_clock_parity_is_typed`, `test_r2_frozen_source_parity` (valid and malformed live rewrites). Reference mutants, run by hand with bytecode caching off (prose-only list, not a test): killed - boundary re-raises, catches Exception only, wrong failure class, output isinstance, output re.match, output check off, raw oracle on insert, raw oracle on validate, parser except without ValueError, parser fails inside its except block (chained), freeze without copy, insert from live source, validate from live source; equivalent - failing inside the oracle except block (sets only `__context__`, which the freshness rule does not assert).

With one registered variant, comparing snapshot_fen strings and comparing identity tuples give the same result (verifier-accepted equivalent). Once a second variant lands, add a test where a colliding oracle maps two variants to one digest.

## Assumption: deterministic digest oracle (documented, parked)

The injected digest oracle is assumed to be deterministic per identity. That is a trusted-input assumption, not something the table checks. Repro: under an oracle that alternates between two valid digests D and D', inserting K-vs-K twice with different clocks puts one identity into two buckets and yields two rows. The T0122 reference and production share this boundary. `test_r2_nondeterministic_oracle_behavior_is_documented` pins the current behavior as documented, not as intended semantics. Parked owner question (coordinator, Sep 24, merged with the double-bucketing item): if the injected digest function ever returns different digests for the same position, should the graph treat that as a documented trusted-input assumption, or pay extra cost to detect it (a second digest call, or field comparison across buckets)?
