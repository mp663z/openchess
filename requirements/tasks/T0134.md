# T0134 Graph/route edge/implement

## Normative requirements

1. `graph.route_edge` implements `EdgeError`, `EdgeTable(docs=None, digest_fn=digest_fen)` with `insert`, `merge`, `records`, `serialize`, `validate_record(ec, vc, dc, epc, fc, lc, nc, record, digest_fn=digest_fen)`, `load_docs()` and `FAILURE_MAPPING` for data/contracts/route_edge.yaml (contract id `chess-route-edge`). It links only the shipped `graph.fen`, `graph.position_digest` and `graph.transposition_node` runtimes and never imports `tests.*`.
2. Records are exactly `{variant, move, from_snapshot_fen, to_snapshot_fen}`: a registry variant, a move per the linked legal-moves `move_model` (square grammar, promotion enum, from/to distinct, all read from the contract), and two canonical node snapshots, each checked through the node record validator. Equality is the canonical four-tuple (variant, move, from identity, to identity); the from-digest-plus-move bucket is a lookup accelerator only. Insert is insert-or-return-existing, and the same from identity plus move with a different target is `conflicting_edge`. Merge reads the source list once, checks each record is an exact dict with exactly the record fields, copies it, validates the copy, and stages it into a copy of the buckets. The table adopts the staged buckets only when the whole merge succeeds, so a rejected insert or merge (including an oracle failure after earlier records were staged) leaves the table unchanged. A caller's live records rewritten mid-merge are never read again. `EdgeTable()` parses fresh contract documents per table. The linked parser's input rejections (`FenError`, and the raw `ValueError` on a clock beyond the integer-string limit) map to `malformed_position` on insert and to `malformed_edge_record` on validate/merge.
3. The injectable digest oracle is untrusted. Every call runs behind the node module's `except BaseException` boundary, and any raised error or any output that is not an exact str in the linked digest format fails closed as a FRESH, unchained `malformed_edge_record`. Per-module forge scope (coordinator ruling): the forge set is the classes this module raises (`EdgeError` per class) plus the classes its own except clauses name (`NodeError` per class, `FenError`, `ValueError`), AST-enumerated. `DigestError`, `AssertionError` and `BaseException` subclasses are forged as well. Input failures (`unknown_variant`, malformed move, `malformed_position`) are decided before the oracle is called.
4. The T0133 red battery turns green by switching only its binding: the import lines plus the table builder it took from the reference fixture (the merged battery built its rollback-test table from the reference, so that one test never touched production). Every scenario stays unchanged.

## Red/green transition

On parent main, switching the T0133 binding to `graph.route_edge` fails at import because the module does not exist. With this change the same switch passes all T0133 tests.

## Divergence from the contract reference

The T0131 reference calls the digest oracle unguarded in insert and validate, so a raising oracle escapes raw. Production fails closed as `malformed_edge_record`, following the coordinator's T0125 ruling. The reference also shares the T0125 v3 findings (a raw ValueError on a clock over 4300 digits; merge re-reading live source records). Production fixes both. With the default oracle the two agree on every fixture row and probe.

The injected oracle is assumed deterministic per identity, the same trusted-input assumption documented in T0125.md. Under an oracle alternating two valid digests, the same edge inserted twice from differently clocked from-positions lands in two buckets and gives two rows, in the reference and in production alike. The test pins this as documented behavior pending the parked owner question.
