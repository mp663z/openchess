# T0159 Graph/collision/fixture

## Normative requirements

1. A closed fixture, tests/fixtures/collision/cases.json, for the T0158 graph-collision contract (`graph-collision`, `/graph/collision/v1`). Its top-level keys are exactly schema, contract, contract_base_path, notes, happy, boundary, malformed and rollback. Every row is an operation script: initial inserts, then one insert, merge or bucket-key lookup, under a named oracle from a closed registry. The registry is: constant (total collision), real digest, raw (hashes clocks), stateful, raising, KeyboardInterrupt, invalid format, str subclass, non-str, reentrant, and an oracle that corrupts the receiver and then raises.
2. The rows run against the contract-derived reference table (`tests.test_t0158_collision_contract.CollisionProbe`). Nothing is re-implemented. Pinned tables were computed from that reference: records in canonical identity order, the canonical view, and bucket sizes by key.
3. Happy (6 rows): collision-free baseline; the same set under total collision; four distinct identities in one bucket (count-exact, no-merge); the same four in reverse arrival order (order-insensitivity); an equal identity with new clocks (no-fork); a merge with overlap under total collision. The guarantees are also asserted across rows: the collision-free and total-collision tables agree on view and record order.
4. Boundary (4 rows): first insert into an empty table; empty merge into an empty table; an idempotent self-merge; the real digest ignoring clocks.
5. Malformed (16 rows) cover every failure class, each with its mapped code in the closed enum, and leave the table identical by value and stored-record identity:
   - `malformed_collision_record`: bad FEN, unknown variant, non-dict, extra-field, missing-field, bad-snapshot and cross-oracle merge records.
   - `accelerator_as_identity`: a bucket-key lookup.
   - `accelerator_inconsistent`: raw and stateful divergence, raising, interrupting, invalid-format, str-subclass, non-str and reentrant oracles.
   Each row has a single-locus minimal repair (the oracle or the operation, never both), and the repaired script succeeds.
6. Rollback (4 rows): a rejected operation (divergent key under collision, a merge rejected at its second record, a receiver-corrupting oracle, a bucket-key lookup) leaves the table identical by value and stored-record identity. The valid follow-up then succeeds with its pinned table, which also equals a clean run.
7. The rows discriminate. Reference mutants each fail a pinned row: bucket-membership dedup (first writer wins), arrival-order view, no restore after rejection, and trusting a divergent key for an equal identity. The unmutated reference passes the same rows. Structure mutations are rejected, a tampered pin is detected, a valid row fails the rejection check, and the file digest is pinned.

## Requirement-to-test mapping

- R1: `test_fixture_structure`, `test_structure_mutations_fail`, `test_failure_class_coverage`, `test_fixture_digest_is_stable`.
- R2 to R4: `test_pinned_tables`, `test_guarantees_under_total_collision`, `test_tampered_pin_is_detected`.
- R5: `test_malformed`, `test_malformed_minimal_repair_is_discriminating`, `test_injected_valid_malformed_row_fails_rejection`.
- R6: `test_rollback`, `test_rollback_expect_matches_a_clean_run`.
- R7: `test_reference_mutant_fails_a_pinned_row`.

As with the other fixtures, this proves fixture/contract consistency. The runtime task must run these same rows against a separate implementation.
