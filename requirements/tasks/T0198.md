# T0198 Store/migration/unit/property

## Normative requirements

1. The battery exercises only the shipped production migration (`store.migration`, T0197). Source states are built from records made by the shipped `graph.node` runtime. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. On every seeded store-v1 state (including the empty state and every single record), `migrate` returns the exact receipt in contract order: `from_schema`, `to_schema` and `source_id` from the request; `state` equal to an independent re-digest model (same identities, variants and snapshots, `pdv2` digests); `target_id` equal to an independent graph-diff state id of that state; `migration_id` equal to an independent sha256 derivation. The oracle is called exactly once per key, in key order, with the record's variant and snapshot. Request and source are untouched by value, key order and identity, and the receipt state shares no record with the source. The result is deterministic, and distinct sources give distinct targets and ids.
3. `state_id` is insertion-order independent and matches the independent serialization; `pdv2_digest` and `derive_migration_id` match independent derivations, and the schema order matters. None of them touch their input.
4. At the target-oracle boundary, a forged typed error fails as a fresh `divergent_target` error with the mapped code, never the forged object and never the forged class: a `MigrationError` of every failure class (including a forged `divergent_target`), and the linked `graph.node` rejections: a `DigestError` of every class in the position-digest contract and a `VariantError` of every declared code. So does any other BaseException, and None, bytes, int, str subclass, source-schema digest, trailing newline, leading space, upper case, short, long or surrogate output, on the first or last key. Request and source stay untouched. Any grammar-valid target digest is accepted and lands in the state (the contract does not bind the target digest to a derivation).
5. An oracle closing over the live request and source that changes, removes and adds keys at every level is undone on the ok and failing paths, and the receipt is the unmutated one.
6. Malformed requests fail as `malformed_migration_record` before step, source and oracle, even over a corrupt source: None, list or dict-subclass requests; renamed, missing, extra, str-subclass and hash-colliding keys; str-subclass, None, bytes, unregistered, `store-v0`, upper-case, newline or leading-zero schemas; str-subclass, None, upper-case, newline, short, bytes or wrong-prefix source ids. Request malformation wins over a corrupt source at every level (a bad digest, str-subclass or colliding state or field keys, a non-dict state). A pair with no registered step (no-op or downgrade) is `unknown_migration` before source validation, even with any of those corrupt sources, None or a dict subclass.
7. Malformed sources fail as `malformed_migration_record` before the conflict check and the oracle (with a consistent or a conflicting source id), with request and source untouched: non-dict or dict-subclass states; None, list or dict-subclass records; str-subclass, colliding, int, wrong-identity or padded keys; renamed, missing, extra, str-subclass-keyed and colliding fields; str-subclass or None values; unknown or non-canonical variants; non-canonical clocks, garbage or other-position snapshots; target-schema, upper-case, newline or short digests. A source digest in the source grammar but not rederived is accepted.
8. A source id that differs from the recomputed one fails as `conflicting_source` before the oracle.

## Mutation check

Each of these one-line production mutants of `store/migration.py` turns the battery red on its own:
- Oracle boundary (the one `except BaseException` in the module): `except MigrationError: raise` ahead of the catch-all; `except MigrationError as e: raise e` for a forged `divergent_target` (the forged object passed through); `except _LINKED_REJECTIONS: _fail("malformed_migration_record")` ahead of it; `except Exception` instead of `BaseException`; and one forged-class passthrough per class, each letting exactly that class escape: `MigrationError` `malformed_migration_record`, `unknown_migration`, `conflicting_source`; `DigestError` `malformed_digest`, `malformed_position`, `unknown_variant`; `VariantError` `illegal_position`, `internal`, `malformed_request`, `unknown_variant`. Also the output type check removed.
- Derivations: state id over unsorted keys or unsorted fields; migration id with schemas swapped or the target dropped; `pdv2` without its separator; the receipt computed from the source state.
- Records: isinstance key or record; field-key type check removed; field set replaced by a length check; isinstance values or the value check removed; snapshot canonical check removed; digest `match` instead of `fullmatch` or the digest check removed; identity check removed.
- Request: isinstance request; key type check removed; key set replaced by a length or superset check; isinstance schema; registry check removed; isinstance, `match` or no grammar for the source id; step check removed.
- Source: isinstance source; the source type or key guards moved ahead of the step check; the conflict check moved ahead of record validation; record validation removed; validated against the target grammar; conflict check removed; oracle fed from the live source.
- Restore and receipt: no record restore; record `update` without `clear`; no source restore; no request restore; request update without clear; receipt fields out of order.

These mutants are equivalent and stay green:
- Oracle output: isinstance, `match` instead of `fullmatch`, or the grammar check removed. The staged state is re-validated against the target schema (exact str values, digest `fullmatch`), which rejects the same outputs with the same class. Conversely, removing that staged re-validation is equivalent: the oracle output check already guarantees exact grammar-valid digests, and variant, snapshot and keys come from the validated frozen source, so identity and cardinality cannot drift.
- The schema grammar check removed. Registry membership is stricter than the grammar.
- The conflict check reading the live request's source id, and the receipt's `source_id` read from the live request. The first read happens before the first oracle call; the second after the request is restored.
- Changing the linked rejection catch: narrowing it to `(VariantError, DigestError)` or to `(VariantError, ValueError)`, or widening it to `except Exception`. For any str variant and snapshot the linked runtime raises only `VariantError`: the variant runtime validates the variant and FEN first, against the same variant registry the position digest uses, so `digest_fen`'s `DigestError` paths are unreachable through `make_record`, and the `ValueError` paths in `record_identity` are unreachable on `make_record`'s own output. A 40,000-case seeded FEN fuzz raised no other class.
- The variant canonical check removed. The variant runtime fails closed on any non-canonical id and never coerces, so a successful `make_record` always returns the input variant.

The mutant list is prose only. There is no GENERATED-CHECKED block; each mutant was applied one at a time, with bytecode caching off, and run against this battery.
