# T0216 Store/WAL/unit/property

## Normative requirements

1. The battery exercises only the shipped production WAL (`store.wal`, T0215) plus the shipped `graph.node` and `graph.diff` runtimes. It imports nothing from `tests.*`, and it uses the WAL's public surface except where it reads `FAILURE_MAPPING` codes. Properties are deterministic and seeded.
2. Append builds the pinned chain. Each append adds exactly one entry at the 1-based position, links it to the previous entry id (or the pinned genesis), and gives it an entry id equal to an independent derivation from the contract (sha256 over sequence, op, canonical payload and prior). It returns a detached copy, keeps existing entries by identity, and leaves the request unchanged.
3. On every prefix of every seeded log, replay equals an independent model fold of put/delete: same state, same key order, a `state_id` equal to `graph.diff.state_id`, `applied`, and a head equal to the last entry id or genesis. Replay never mutates the log and never aliases returned records. Building and replaying are deterministic.
4. Put/delete semantics: deleting an absent identity is a logged no-op on state, put then delete returns to the prior state id while the head advances, and a repeated put is idempotent on state.
5. Any single tampered entry makes both replay and append fail closed with the exact class and code, leaving log and request bit- and reference-identical. The tamper table covers the sequence (shift, str, bool), the op (unknown, non-str), the entry id (flip, bad grammar), the prior link (plain relink, and a self-consistent re-derived forgery only the link check can see), extra or missing keys at the entry, payload and record levels, identity or digest swaps, non-canonical clocks a non-dict entry, dict-subclass entries/payloads/records, str-subclass values (op, entry id, prior, identity, each record field), str-subclass keys, and hash-colliding keys whose comparison raises at the entry, payload and record levels. Every one of these must come back as the typed failure, never a raw escape.
6. Malformed append requests reject with `malformed_wal_entry` or `unknown_operation`, atomically. That includes str-subclass op/identity/record fields, dict-subclass requests/payloads/records, str-subclass and colliding keys. A non-list log (tuple, None, dict, str) is `malformed_wal_entry` for both append and replay. The committed entry and the returned entry never alias the caller's request payload or record.
7. At the canonicalizer boundary, any BaseException (ValueError, KeyboardInterrupt, SystemExit, GeneratorExit) and any None, bytes, str-subclass or non-UTF-8 output fails as `divergent_canonicalization`. A well-formed but divergent string on any single call over the existing log fails as `corrupt_chain` on replay and on append. On the new entry's own call it changes only the new id, which later replay rejects. A canonicalizer closing over the caller's live request and log that adds keys at every level and inserts into the log container is fully undone (values, key order, identity at every level) on the ok path and on the failing paths of append and replay. Replay makes exactly one call per entry and append one per entry plus one. The canonicalizer's argument is detached.
8. Public `snapshot`/`restore` undo arbitrary scrambles: added keys at every level, removed keys, key-order changes, cleared dicts, and a reordered, inserted or deleted container. Values, key order and object identity are all restored.
9. Bad records reject on both the memoized path and the unbounded path on every repetition (only successes are cached).

## Mutation check

Each of these one-line production mutants of `store/wal.py` turns the battery red on its own:
- The sequence check removed, or `!=` changed to `>` (a lower sequence with a re-derived self-consistent id).
- The prior-link check removed. The prior grammar check removed.
- Exact record equality removed.
- isinstance instead of exact type for the identity, the record fields, the op (log path and append path), the entry-id/prior fields, and the entry, payload, record and request dicts.
- The exact-str key guard removed at the entry, payload, record or request level.
- The `type(log) is list` check removed from replay or from append.
- isinstance canonicalizer output. The UTF-8 check removed. A narrowed `except Exception` boundary. A shared (non-detached) canonicalizer argument.
- Restore without record clear, entry clear or container reset.
- Append's request restore without record, payload or request clear, or with no request restore at all.
- The staged entry aliasing the caller's request record. Append returning the committed entry instead of a detached copy.
- Delete as a no-op.

The equivalent controls (no memo cache, a `+ 0` edit) stay green.
