# T0217 Store/WAL/fuzz/fault

## Normative requirements

1. The battery is deterministic and seeded. It fuzzes the shipped production WAL (`store.wal`, T0215) and builds every input log from an independent model of data/contracts/wal.yaml (the entry-id derivation and the replay fold are restated in the test, never taken from production). The contract reference engine (`tests.test_t0212_wal_contract`) serves as the differential oracle.
2. Generators (1464 cases): `shape` (one structural edit at a first, middle or last entry, at the entry, payload, record or leaf level: every leaf type including bool, empty, multi-byte and unencodable str, bytes, float, huge int and containers; dropped and added keys; plain-str keys renamed at the same arity; dict subclasses; str-subclass and hash-colliding keys), `chain` (id flips, relinks, self-consistent re-derived prior and sequence forgeries, bool sequences, swaps, drops, duplicates, op, record and identity swaps, unknown ops, id and prior grammar breaks (including a trailing newline, which `$` accepts, and a leading space), same-arity renames at every level (sequencx, identitx, digesx and random plain-str keys), dict/str subclasses and colliding keys at every level, truncation), `request` (the same edits on append requests, unknown ops, identity/record mismatch, request dict subclass, same-arity renames such as {op, payloax} and {oq, payload}, and strictly larger key sets: an extra ASCII or non-ASCII request key, an extra payload key and an extra log-entry key), `container` (non-list and list-subclass logs), `canon` (a canonicalizer fault on the first, last, middle or a random call: every BaseException kind, a pre-built typed WalError of every other class, None, bytes, int, str subclass, unencodable, empty and divergent output, a scribbled argument), and `live` (a canonicalizer that edits the caller's live log and request on one call, with keys added at every level, cleared records, dropped fields, container inserts, deletes, reversals and clears, then answers honestly, raises or diverges).
3. Every case holds against production: no raw escape (only a typed `WalError` from the closed class set with its mapped code); the same outcome as the contract reference; the independently known outcome where there is one (single-call type faults are `divergent_canonicalization`, a divergent answer on an existing entry is `corrupt_chain`, a divergent answer on the new entry's call in append changes only the new id and a later replay rejects it as `corrupt_chain`, an honest answer after live edits succeeds, and happy/truncated/re-forged logs replay to the model).
4. Atomicity: a rejected call and every replay leave log and request identical by value, exact type, key order and object identity at every level. A successful append keeps every existing entry by identity, adds exactly the model's next entry, returns a detached copy and never aliases the request.
5. No poisoning: after any rejection a fresh engine still replays the clean model log to the model state. Outcomes are deterministic by value.
6. Happy logs up to 24 entries match the model on every prefix, and the boundaries (empty log, single put/delete of every record, a 64-entry log, put/delete churn) match it too.
7. Mutation check: `_probe` runs the first 48 cases of every generator against a source mutant of store/wal.py, with `WalError` and `_fail` rebound to the production class. The identity mutant must pass. Each of the 49 one-guard mutants in `MUTANTS` must fail. Each entry in `_EQUIVALENT_EDITS` (no memo cache, memo bound 0, reversed record-field set, slice-copy snapshot, a superset record-key check that exact record equality backs up, and `_LINKED_REJECTIONS` without ValueError, since the linked runtime raises VariantError/DigestError for every bad record tried) is asserted to pass.

## Requirement-to-test mapping

- R1, R2, R3, R4, R5: `test_fuzz_cases_hold` (every generator, in chunks of 48 seeds), `test_determinism_by_value`, `test_corpus_reaches_every_class_every_position_and_both_calls` (every failure class, first/middle/last positions, replay and append, every edit kind).
- R6: `test_happy_logs_match_the_model_on_every_prefix`, `test_boundaries`.
- R7: `test_identity_source_mutant_is_green`, `test_mutant_is_red`, `test_equivalent_edits_stay_green`.

## Mutants

Sequence check removed or `>`; prior-link check removed; id grammar removed, or `match`/`search` instead of `fullmatch`; key-set checks replaced by length checks at the entry, payload, record and request levels; a subset record-key check; superset key checks at the entry, payload and request levels; a typed WalError from the canonicalizer passed through; unknown-op check removed (entry and request paths); isinstance instead of exact type for the entry op, request op, sequence, entry, payload, record, request, identity, record fields, id fields and canonicalizer output; key guard removed (everywhere, and request only); exact record equality removed; identity binding removed; `except Exception` boundary; UTF-8 check removed; shared canonicalizer argument; re-derived id check removed; restore without record clear, entry clear or container reset; append without request, payload or record restore; staged record aliasing the request; returning the committed entry; delete as a no-op; log type check removed from replay or append; replay re-deriving from the live log; append sequence from the live log.
