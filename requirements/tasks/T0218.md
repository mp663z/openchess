# T0218 Store/WAL/integration/restart

## Normative requirements

1. The durable form is a JSON-lines log (one entry per line). A restart is a fresh interpreter that loads those bytes, builds a new `store.wal.WalEngine` and replays or continues the log. Expected values come from an independent model of data/contracts/wal.yaml (entry-id derivation, replay fold, `graph.diff.state_id`), and the contract reference engine (`tests.test_t0212_wal_contract`) is the differential oracle.
2. Happy path: restarting at every prefix of a six-entry history, then appending the rest, reproduces the uninterrupted log byte for byte. The same holds for a 12-process chain with one append per process. Replay never changes the durable bytes and repeats identically. Fresh-process output is identical across PYTHONHASHSEED values.
3. Boundary cases: an empty log (genesis head, applied 0, first append links to genesis), a 64-entry log, a delete of an absent identity, and a torn tail (the last 1, 2 or all entries lost). A torn tail replays to the model prefix, and appending the lost requests again reproduces the bytes.
4. Malformed: 31 tampers of the durable form, each at the first, middle and last entry, plus dropped entries. Examples: id flips, sequence edits (including self-consistent re-chained forgeries, true, float and str), unknown ops, non-str ops (1, null and ["put"]), dropped, extra and same-arity renamed keys at the entry, payload and record levels, id grammar breaks (a trailing newline, a leading space, upper case), payload swaps, identity mismatch, wrong digest, non-canonical FEN, null or list entries, duplicates, swaps and foreign splices. Replay and append after a restart reject each tamper with its pinned typed class. The in-memory log is intact, the durable bytes are unchanged, and the outcome matches the reference.
5. Rollback: rejected appends after a restart leave the log and file untouched, and a later valid append and restart continue the model. A divergent new-entry id is caught as corrupt_chain by the next process.
6. Oracle boundary: the canonicalizer is the module's only `except BaseException` boundary. Faults are injected at the first and last call of replay and at the first and new-entry call of append. The faults are a forged `WalError` of every class in `FAILURE_MAPPING`, six BaseException kinds and four bad output types. Each fails closed as a fresh (not the forged object) `divergent_canonicalization`, leaves the bytes unchanged, and does not poison the next replay. A scribbling canonicalizer is inert.
7. Mutation check: 20 source mutants of store/wal.py run through the fresh-process restart path, and each is red on its pinned target in `MUTANT_TARGETS`. They include the except-Exception boundary, WalError pass-through for all classes and for each class separately, a shared canonicalizer argument, isinstance output, no UTF-8 check, head from the first entry, append prior pinned to genesis, delete as a no-op, applied off by one, no prior-link, sequence or re-derivation check, `search` instead of `fullmatch` for id grammar, an entry key-length check, and the entry op type check removed. The identity mutant is green.

## Requirement-to-test mapping

- R1, R2: `test_restart_at_every_prefix_continues_bit_identical`, `test_process_chain_restart_after_every_append`, `test_replay_never_changes_durable_bytes_and_is_repeatable`, `test_fresh_process_output_is_deterministic_across_hash_seeds`, `test_restart_state_is_bound_to_linked_runtimes`, `test_production_matches_contract_reference_in_process`.
- R3: `test_empty_log_restart_boundary`, `test_long_log_restart_boundary`, `test_torn_tail_replays_to_prefix_and_reappend_reproduces_bytes`.
- R4: `test_tampered_durable_logs_are_rejected_typed_and_untouched`.
- R5: `test_rejected_appends_after_restart_roll_back_then_continue`, `test_divergent_new_entry_is_caught_after_restart`.
- R6: `test_boundary_faults_fail_closed_fresh_after_restart`, `test_every_wal_error_class_is_forged`, `test_scribbling_canonicalizer_is_inert_after_restart`.
- R7: `test_probes_green_in_a_fresh_process`, `test_killed_list_covers_every_mutant`, `test_mutant_is_red_on_its_target`.
