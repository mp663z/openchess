# T0225 Store/backup/unit/property

## Normative requirements

1. The battery exercises only the shipped production backup (`store.backup`, T0224), with source logs built by the shipped `store.wal` from records made by the shipped `graph.node` runtime, and it checks state ids against `graph.diff`. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. On every seeded log, `backup` returns the exact receipt, with fields in contract order and an exact-int count:
   - `head`, `state_id` and `entry_count` equal the WAL replay, and `state_id` equals `graph.diff.state_id` of an independent put/delete model;
   - `bundle` equals an independent canonical serialization;
   - `backup_id` equals an independent sha256 derivation and the public `derive_backup_id`.
   The serializer is called exactly once, with the replayed state. The log is untouched by value, key order and identity, and the result is deterministic. The empty log gives the genesis head and the empty state id.
3. Every prefix of every log backs up and verifies. `verify` returns an equal, detached copy in contract order without touching the receipt, and distinct prefixes give distinct backup ids.
4. The serializer argument is detached (mutating it never reaches the log). backup does not re-serialize: any exact UTF-8 str becomes the bundle and is bound into `backup_id`.
5. At the serializer boundary, any BaseException (ValueError, KeyboardInterrupt, SystemExit, GeneratorExit), None, bytes, int, str-subclass or non-UTF-8 output fails as `divergent_snapshot` with the log untouched. A serializer closing over the live log adds keys at every level, changes and removes values, and inserts into the container. All of it is undone on both the ok path and the failing path.
6. Any single-entry source tamper fails as `corrupt_source` before the serializer is ever called, typed and never raw, with the log untouched. The tamper set covers sequence, op, entry id and prior, extra, str-subclass and hash-colliding keys, digest swaps, str-subclass identity, and dict-subclass or non-dict entries and records. A non-list source, including a list subclass, is `malformed_backup_record`.
7. `verify` is local and total. It never touches the receipt, and every tamper rejects with its exact class and code:
   - `malformed_backup_record`: shape, dict subclass, str-subclass and colliding keys; count type (bool, float, str, int subclass, huge); negative or over-max count; bundle type, str subclass or non-UTF-8; and for each id field a str subclass, non-str, bad grammar, upper case or trailing newline;
   - `divergent_backup`: a changed bundle or count, a flipped id, head or state id, a swapped state, a genesis head with a positive count, and a zero count with a non-genesis head or non-empty state, including self-consistently re-derived forgeries.
   A self-consistently re-derived count change is accepted, because verify is local.
8. The count bound is checked from both sides: the maximum is accepted, and max+1, 2*max and -1 are rejected. The verify output is detached and in contract order even for a reordered input.

## Mutation check

Each of these one-line production mutants of `store/backup.py` turns the battery red on its own:
- Source checks: an isinstance or missing log-list check; a WAL rejection narrowed to one class; no log restore.
- Serializer: a narrowed `except Exception` boundary; isinstance serializer output.
- Receipt shape and types: the receipt key guard removed; the exact key-set check replaced by a length check (`len(receipt) != len(_FIELDS)`), killed by the same-arity renamed-key tampers (one per field); an isinstance receipt; isinstance id fields; `match` instead of `fullmatch`; an isinstance count; isinstance bundle.
- Count range: no max, `<` instead of `<=` at the max, no min.
- Consistency checks: the zero-count check removed or reduced to head-only or state-only; the genesis-with-positive-count check removed; the backup-id comparison disabled; the UTF-8 check in the id derivation removed.
- Output: verify returning the input, or returning it in input order.

Six mutants are equivalent and stay green:
- Passing the replay state (instead of a fresh copy) to the serializer. The replay state is already detached from the log.
- Dropping the serializer's own UTF-8 check. The id derivation rejects the same output with the same class.
- Taking `entry_count` from `len(log)`. It equals `applied` on every validated log.
- Widening `except _wal.WalError` to `except Exception` in `backup`. Replay of a list log raises only `WalError`, so nothing else reaches that handler.
- Changing the unencodable-input class `backup` passes to `_derive`. `head` and `state_id` come from a validated replay and match ASCII grammars, and the bundle has already passed the serializer's UTF-8 check, so that branch can't be reached from `backup`.
- Computing `state_id` from the frozen copy instead of taking the replayed `state_id`. The frozen copy holds the same records, so both give the same id.

The mutant list is prose only. There is no GENERATED-CHECKED block; each mutant was applied one at a time and run against this battery.
