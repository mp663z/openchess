# T0233 Store/restore/implement

## Normative requirements

1. `store.restore` implements `RestoreError`, `RestoreEngine(bundle_parser)` with `restore(receipt)`, `parse_bundle` (the honest parser), `derive_restore_id` and `FAILURE_MAPPING` for data/contracts/restore.yaml. Production must not import or execute `tests.*`.
2. Verify first: the receipt goes through the linked production backup (`store.backup.BackupEngine(serialize_bundle).verify`) before any parse. A malformed backup record surfaces as `malformed_restore_record`; any other verification failure as `unverified_backup`. Only names in `store.backup.__all__` are used.
3. The parser is untrusted: exactly one call on the frozen bundle; any BaseException or non-exact-dict output fails closed as `divergent_parse`. Receipt fields are frozen before the call and the receipt is restored bit-identical on every exit.
4. Every parsed entry needs an exact str key and an exact node record that validates through the shipped graph.node runtime with identity equal to the key (the same rejection set store.wal uses); the recomputed `graph.diff.state_id` must equal the receipt's. Otherwise `divergent_state`.
5. The staged state must reserialize byte-for-byte to the frozen bundle through `store.backup.serialize_bundle`, else `divergent_parse`. The result is `{restore_id, backup_id, state_id, state}` with `restore_id` derived locally.
6. The T0232 red battery turns green by replacing only its two binding lines. Every scenario, probe and mutant stays unchanged.

## Red/green transition

On parent main, switching the two T0232 binding lines to `store.restore` fails at import because the module does not exist. With this change the same switch passes all 40 T0232 tests.
