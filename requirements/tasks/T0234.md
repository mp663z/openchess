# T0234 Store/restore/unit/property

## Normative requirements

1. The battery exercises only the shipped production restore (`store.restore`, T0233). Receipts come from the shipped `store.backup` over logs built by the shipped `store.wal` from records made by the shipped `graph.node` runtime. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. On every seeded log, `restore` returns the exact record in contract order (`restore_id`, `backup_id`, `state_id`, `state`):
   - `state` equals an independent put/delete model, as an exact dict of exact-str keys to exact dict records with exact-str fields;
   - `state_id` equals the receipt's, an independent canonical derivation and `graph.diff.state_id`;
   - `restore_id` equals an independent sha256 derivation and the public `derive_restore_id`.
   The parser is called exactly once, with the receipt's bundle. The receipt is untouched by value, key order and identity. The result is deterministic, and repeated restores return fresh state objects. The empty log restores to the empty state.
3. Every prefix of every log restores, and distinct backups give distinct restore ids. `parse_bundle` is the exact inverse of the canonical serialization.
4. The output state is detached from the parser output: no shared dicts, and mutating the parser's objects afterwards never reaches the result.
5. At the parser boundary, any BaseException (ValueError, IndexError, KeyboardInterrupt, SystemExit, GeneratorExit), None, list, str or dict-subclass output fails as `divergent_parse`. A different valid canonical state fails as `divergent_state`. The receipt is untouched either way. A parser closing over the live receipt that changes, deletes, adds (including a str-subclass key) or clears keys is fully undone on both the ok path and the failing path. The output is built from the receipt values as they were before the parser ran.
6. Verify first: every receipt the linked backup verify rejects fails before the parser is called, with the receipt untouched. Shape and type rejections are `malformed_restore_record`: same-arity renamed key and missing key per field, extra, str-subclass and hash-colliding keys, dict subclass, non-dict, bool or over-max count, id grammar, str-subclass id, non-str bundle. Consistency rejections are `unverified_backup`: flipped backup id, state id or head, changed bundle or count, genesis head with a positive count.
7. Forged but verifiable receipts (self-consistent backup id, so they pass the local verify) reach every restore-side guard. With the honest parser:
   - `divergent_state`: wrong digest, non-canonical clocks, swapped keys, unknown variant, illegal position, foreign key, and a state id that belongs to another state;
   - `divergent_parse`: records in reverse order, fields in reverse order, a missing trailing newline, and an unparseable tail.
   Restore is local: a forged receipt at the maximum count restores, max+1 is `malformed_restore_record`, and a forged smaller valid state restores to exactly that state.
8. Every invalid parser output against an honest receipt is `divergent_state`: str-subclass, hash-colliding, non-str or swapped keys; dict-subclass, list, None or str records; per record field, a same-arity renamed key, str-subclass key, colliding key, missing field and str-subclass, int, None or bytes value; an extra field; a wrong digest; non-canonical clocks; a missing or extra record; and the empty state.
9. Record validation catches exactly the linked runtime's rejections. `VariantError`, `DigestError` or `ValueError` raised by `make_record` or `record_identity` is `divergent_state`. Any other exception propagates.

## Mutation check

Each of these one-line production mutants of `store/restore.py` turns the battery red on its own:
- Verify step: verify removed; the malformed/unverified mapping swapped, or collapsed to either class; the parser called before verify.
- Receipt restore: removed; done only on the failing path; `update` without `clear`.
- Parser boundary: `except Exception` instead of `BaseException`; an isinstance output check; the output type check removed.
- State loop: an isinstance key check; the key check removed; the identity-equals-key check reduced to a None check; the output record aliasing the parser's record.
- Integrity: the state id check removed; the re-serialization check removed or raising `divergent_state`.
- Output: `derive_restore_id` arguments swapped; fields out of contract order; the derivation's newline separator dropped.
- Record validation: the exact-str record-key check removed; the key-set check replaced by a length check; an isinstance field-value check; the value check removed; the exact-equality-with-derived check removed; `VariantError`, `DigestError` or `ValueError` each dropped from the linked rejections; the linked rejections widened to `Exception`.
- `parse_bundle`: the trailing empty line not dropped.
- Both record-type checks (the loop's and `_record_identity`'s) made isinstance together.

Seven mutants are equivalent and stay green:
- The loop's `type(record) is not dict` made isinstance on its own. `_record_identity` rejects a non-exact dict with the same class.
- `_record_identity`'s `type(record) is not dict` made isinstance on its own. The loop has already rejected it with the same class.
- Re-reading `receipt["state_id"]` instead of the frozen value after the parser call. The receipt is restored bit-identical before that read.
- Re-reading `receipt["bundle"]` instead of the frozen value, for the same reason.
- Re-reading `receipt["backup_id"]` for the restore id instead of the frozen value, for the same reason.
- Widening `except _backup.BackupError` around verify to `except Exception`. The linked verify raises only `BackupError` for any receipt.
- Relaxing the record key-set check to "all three fields present" (a superset check). An extra field makes the record differ from the linked `make_record` output, so the exact-equality check rejects it with the same class. The subset direction is killed: a missing field would escape as a raw KeyError.

The mutant list is prose only. There is no GENERATED-CHECKED block; each mutant was applied one at a time and run against this battery.
