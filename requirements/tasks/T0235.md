# T0235 Store/restore/fuzz/fault

## Normative requirements

1. The battery is deterministic and seeded. It fuzzes the shipped production restore (`store.restore`, T0233) and builds every input receipt from an independent model of data/contracts/backup.yaml and restore.yaml (the bundle serialization, the parser inverse, and the state-id, backup-id and restore-id derivations are restated in the test, never taken from production). The contract reference engine (`tests.test_t0230_restore_contract`) serves as the differential oracle.
2. Generators (1368 cases):
   - `receipt`: one edit per receipt field: every leaf type including bool, huge int, float, bytes, empty, unencodable and multi-byte str, and containers; dropped and added (ASCII and non-ASCII) keys; same-arity renames; str-subclass and hash-colliding keys; a dict subclass; count bounds (-1, ceiling + 1, bool, 0); a trailing newline on every field. It also makes self-consistent forgeries that re-derive the backup id over a changed head or count (restores), a changed state id (`divergent_state`), a genesis head (`unverified_backup`), or a flipped backup id.
   - `container`: non-dict and dict-subclass receipts.
   - `bundle`: a receipt that verifies (backup id re-derived) over a damaged bundle: swapped or duplicated records, reordered fields, a missing trailing newline, blank and empty lines, CR and space framing, wrong digest, mis-keyed, unknown-variant, extra- and missing-field records, a dropped record under the old state id, and unencodable text.
   - `parser`: every BaseException kind; a forged typed error of every restore class (including `divergent_parse`), every backup class, every WAL class, every position-digest class and every variant-runtime code; a real `ValueError` (named in the module's own except clause) and a real `TypeError`; non-dict, dict-subclass and empty output; str-subclass, hash-colliding and int keys; dict-subclass and None records; str-subclass and colliding field keys; dropped, added and renamed fields; str-subclass, None and bytes values; wrong, store-v2 and clock-edited records; missing, extra and swapped records; an honest state in reversed insertion order (accepted).
   - `live`: a parser that edits the caller's live receipt (adds, drops, changes and re-types keys, clears or replaces it) and then answers honestly, raises or diverges.
3. Every case holds against production:
   - No raw escape: only a typed `RestoreError` from the closed class set with its mapped code. Never a forged error object, and no explicit `__cause__` on any typed rejection. `__context__` is not asserted: no engine clears it.
   - The same outcome as the contract reference.
   - The independently known outcome where there is one.
   - At most one parser call, and exactly one on success.
   - A successful restore is equal to the model (fields in contract order, independent restore id, state equal to the parsed model), made of exact dicts, and detached from the parser output.
4. Atomicity: every call leaves the receipt identical by value, exact type, key order and object identity at every level.
5. No poisoning: after any rejection, a fresh engine still restores a clean receipt to the model. Outcomes are deterministic by value.
6. Happy receipts over seeded states restore to the model and leave the receipt untouched. Boundaries: the empty genesis receipt; every single record; the count ceiling accepted and one past it malformed; an empty state under a non-genesis head; a non-empty state with count 0 is `unverified_backup`.
7. Mutation check: `_probe` runs the first 48 cases of every generator against a source mutant of store/restore.py, with `RestoreError` and `_fail` rebound to the production class. The identity mutant must pass. Each of the 47 mutants in `MUTANTS` must fail. Each entry in `_EQUIVALENT_EDITS` must pass.

## Requirement-to-test mapping

- R1 to R5: `test_fuzz_cases_hold` (every generator, in chunks of 48 seeds), `test_determinism_by_value`, `test_corpus_reaches_every_class_and_every_edit` (every failure class, including from the probe slice alone, and every edit kind, tamper, fault and scramble).
- R6: `test_happy_receipts_restore_to_the_model`, `test_boundaries`.
- R7: `test_identity_source_mutant_is_green`, `test_mutant_is_red`, `test_equivalent_edits_stay_green`.

## Mutants

Parser boundary (the one `except BaseException` in the module):
- `except RestoreError: raise` ahead of the catch-all, and `except Exception` instead of `BaseException`.
- `except ValueError: raise` and `except TypeError: raise` ahead of the catch-all; the typed failure re-raised `from` a caught `RestoreError`.
- One forged-class passthrough per class: every `RestoreError` class (a forged `divergent_parse` is caught by object identity), every `BackupError` class, every `WalError` class, every `DigestError` class and every `VariantError` code.
- The linked rejections passed through.
- isinstance output, or the output type check removed.

Verification: removed; every backup rejection mapped to `malformed_restore_record`; every backup rejection mapped to `unverified_backup`.

Receipt restore: removed; `update` without `clear`; restored only on the failing path.

State validation: isinstance key; the key/record type check removed; identity binding reduced to validity; the field-key type guard removed; the field set replaced by a length check; isinstance values; exact record equality removed; the state-id check removed.

Round-trip: removed, or failing as `divergent_state`.

Result: staged records aliasing the parser output; restore-id arguments swapped; fields out of order.

Equivalent edits (asserted green):
- A superset field-key check. Exact record equality with the linked derivation rejects an extra field the same way.
- isinstance for the record in `restore`. `_record_identity` repeats the exact-dict check.
- Parsing the live `receipt["bundle"]`. The parser runs before anything can touch the receipt.
- The state-id check reading the live receipt. The receipt is restored before that read.

## Forge scope

Per module: every class store/restore.py raises itself plus every class named in its own except clauses (`RestoreError`, `BackupError`, `VariantError`, `DigestError`, `ValueError`). `DiffError` raised through `state_id` belongs to graph.diff's battery (T0181), since restore never catches it by name.
