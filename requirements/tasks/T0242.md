# T0242 Store/rollback/implement

## Normative requirements

1. `store.rollback` implements `RollbackError`, `RollbackEngine(tail_archiver)` with `rollback(log, request)`, `archive_tail`, `derive_rollback_id`, `GENESIS` and `FAILURE_MAPPING` for data/contracts/rollback.yaml. Production must not import or execute `tests.*`.
2. Source validation goes through the linked production WAL (`store.wal.WalEngine.replay`); any WAL rejection surfaces as `corrupt_source`. Input preservation uses the WAL's public `snapshot` / `restore` helpers, never its private names.
3. The request is an exact dict whose keys are checked as exact str before the set compare; `target_sequence` is an exact int in [0, len(log)] or the rollback fails `unknown_target`.
4. The tail archiver is untrusted: exactly one call on a deep-detached copy of the frozen tail; any BaseException, non-exact-str, wrong-grammar or non-UTF-8 output, or a token that is not byte-exact to `archive_tail(frozen tail)`, fails closed as `divergent_archive`.
5. A rejected rollback leaves log and request bit- and reference-identical; a committed rollback removes exactly the tail in place (same list, same surviving entry objects) and returns the receipt with `rollback_id` derived locally.
6. The T0241 red battery turns green by replacing only its two binding lines. Every scenario, probe and mutant stays unchanged.

## Red/green transition

On parent main, switching the two T0241 binding lines to `store.rollback` fails at import because the module does not exist. With this change the same switch passes all 48 T0241 tests.
