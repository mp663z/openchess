# T0243 Store/rollback/unit/property

## Normative requirements

1. The battery exercises only the shipped production rollback (`store.rollback`, T0242). Source logs are built by the shipped `store.wal` from records made by the shipped `graph.node` runtime. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. For every target from 0 to the log length on every seeded log, `rollback` returns the exact receipt in contract order:
   - `from_head` is the last entry id (genesis for an empty log), and `to_head` is the entry id at position target-1 (genesis at 0);
   - `truncated_count` is an exact int equal to length minus target;
   - `archive_token` equals an independent length-framed sha256 derivation and the public `archive_tail`;
   - `rollback_id` equals an independent derivation and the public `derive_rollback_id`.
   The archiver is called exactly once, with a plain copy of the tail. The commit keeps the same list object, holding exactly the original prefix: same values, and the same entry, payload and record objects. The prefix replays through the WAL to `to_head` with `applied == target`. The request is untouched. The result is deterministic, and distinct targets give distinct rollback ids.
3. Boundaries: the empty log rolls back to 0 with genesis heads and the empty-tail token. target = length is a no-op with equal heads. target = 0 truncates everything to genesis. The surviving prefix keeps its chain and accepts new appends that chain from `to_head`.
4. The archiver argument is detached: mutating it at every level never reaches the log or the receipt.
5. At the archiver boundary, any BaseException, None, bytes, int, str subclass, trailing newline, upper case, wrong prefix, surrogate, or grammar-valid but wrong token fails as `divergent_archive`, with the log and request untouched. An archiver closing over the live log and request adds keys at every level, changes and removes values, and inserts into and deletes from both containers. All of it is undone on both exits, and the commit truncates the restored log.
6. Malformed requests fail as `malformed_rollback_record` before validation or archiving, even over a corrupt log. This covers renamed, missing, extra, str-subclass and hash-colliding keys, dict subclass, list or None requests, and bool, int-subclass, float, str or None targets. A non-list log, including a list subclass, is `malformed_rollback_record`.
7. Target bounds are checked from both sides: -1, -n-1, n+1, n+2 and huge values of either sign are `unknown_target` before the archiver runs, with the log untouched. 0, 1, n-1 and n are accepted.
8. Any single-entry source tamper fails as `corrupt_source` before the archiver runs, typed and never raw, with the log untouched. This holds even when the target is also out of range, because validation comes first. The tamper set is the same one as T0216/T0225.
9. `archive_tail` matches the independent derivation on every suffix, without touching its input, and distinct suffixes give distinct tokens.

## Mutation check

Each of these one-line production mutants of `store/rollback.py` turns the battery red on its own:
- Log and request shape: isinstance log, or the log check removed; isinstance request; the exact-str key check removed; the key-set check replaced by a length check, a subset check or a superset check; isinstance target, or the target check removed.
- Source validation: the WAL rejection narrowed to one class; replay removed; the bounds check moved ahead of replay.
- Bounds: no minimum; no maximum; `>=` at the maximum; `<=` at the minimum.
- Archiver boundary: no deep copy of the tail; `except Exception` instead of `BaseException`; isinstance output, or the type check removed; the token binding to `archive_tail` removed.
- Input restore: no log restore; no request restore; request `update` without `clear`; restore only on the failing path.
- Derivation: the tail taken from the live log instead of the frozen copy; `from_head` from the first entry, or genesis for a single entry; `to_head` off by one or taken from the next entry's prior id; count off by one; `derive_rollback_id` arguments swapped, or a separator dropped; receipt fields out of order.
- Commit: no truncation; truncation by rebuilding the list from copies; off by one; truncation before archiving.
- `archive_tail`: no length framing; the prior entry id or the FEN dropped; the domain tag dropped.

Seven mutants are equivalent and stay green:
- `match` instead of `fullmatch` on the token grammar. A token with trailing text can never equal the local `archive_tail` token, so the binding check rejects it with the same class.
- The token grammar check removed, for the same reason: any accepted token must equal the local token, which is in the grammar.
- The token's UTF-8 check removed. A non-UTF-8 string fails the ASCII grammar and the binding first.
- Taking `from_head` from the live log instead of the frozen copy. The log is restored bit-identical before that read, and the read comes before the truncation.
- Truncating at the live `request["target_sequence"]` instead of the frozen target. The request is restored before the commit.
- Widening `except _wal.WalError` around replay to `except Exception`. WAL replay is total: it raises only `WalError` for any list log.
- Taking `to_head` from the next entry's prior id with guarded edges (`frozen[target]["prior_entry_id"] if target < len(frozen) else (frozen[-1]["entry_id"] if frozen else GENESIS)`). On every WAL-valid chain, an entry's prior id is the previous entry's id, and the target == length edge falls back to the last entry id. The unguarded next-entry-prior mutant listed above differs at that edge and is killed.

The mutant list is prose only. There is no GENERATED-CHECKED block; each mutant was applied one at a time, with bytecode caching off, and run against this battery.
