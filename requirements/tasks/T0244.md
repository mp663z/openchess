# T0244 Store/rollback/fuzz/fault

## Normative requirements

1. The battery is deterministic and seeded. It fuzzes the shipped production rollback (`store.rollback`, T0242). Every input log and request comes from an independent model of data/contracts/wal.yaml and rollback.yaml: the entry-id, archive-token and rollback-id derivations are restated in the test, never taken from production. The contract reference engine (`tests.test_t0239_rollback_contract`) is the differential oracle.
2. Generators (984 cases):
   - `request`: every target leaf type, including bool, float, str, bytes, str subclass, containers and huge ints of both signs; an int subclass; targets below 0 and above the log length; the accepted edges 0 and len; dropped, added (ASCII and non-ASCII) and same-arity renamed keys; str-subclass and hash-colliding keys; a dict subclass; None and list requests. Malformed requests also run over a corrupt log.
   - `container`: non-list and list-subclass logs.
   - `source`: one tamper at the first, middle or last entry: id and prior flips, re-derived sequence shifts, bool/float sequences, inner drops, swaps, duplicates, unknown and re-derived flipped ops, digest swaps, extra, str-subclass and colliding keys, dict-subclass entries and payloads, colliding record keys, str-subclass identities and non-dict entries. Each runs with an in-range or out-of-range target.
   - `archiver`: faults at the genesis, middle and tip (empty tail) targets. These cover every BaseException kind; a forged typed error of every rollback class (including `divergent_archive`) and every WAL class; a real `UnicodeEncodeError` (a class the module names in its own except clause) and a real `TypeError`; None, bytes, int, list, str subclass, upper-case, trailing-newline, leading-space, short, surrogate and wrong-prefix output; a grammar-valid flip; the token of a shorter, longer or empty tail; an honest answer; and an honest answer followed by editing the argument at every level.
   - `live`: an archiver that edits the caller's live log (append, delete, clear, reverse, entry and record edits) and request (target change, added key, clear), then answers honestly, raises or diverges.
3. Every case holds against production:
   - No raw escape: only a typed `RollbackError` from the closed class set with its mapped code. Never a forged error object, and never one chained as `__cause__`. `__context__` is not asserted: no engine clears it.
   - The same outcome as the contract reference, and the independently known outcome where there is one.
   - At most one archiver call.
4. Atomicity and commit:
   - A rejected call leaves log and request identical by value, exact type, key order and object identity at every level.
   - A successful rollback truncates exactly the tail, keeps every surviving entry by identity and leaves the request untouched. It returns the model receipt in contract order, after exactly one archiver call whose argument equals the model tail and shares no object with the log.
5. No poisoning: after any rejection, a fresh engine still rolls a clean log back to the model. Outcomes are deterministic by value.
6. Happy logs of up to 11 entries roll back to the model at every target, and the result replays through the linked WAL. Boundaries: the empty log (target 0 only; -1 and 1 are `unknown_target`), and a 64-entry log at 0, 1, 63 and 64 with 65 rejected and the log untouched.
7. Mutation check: `_probe` runs the first 48 cases of every generator against a source mutant of store/rollback.py, with `RollbackError` and `_fail` rebound to the production class. The identity mutant must pass. Each of the 46 mutants in `MUTANTS` must fail. Each entry in `_EQUIVALENT_EDITS` must pass.

## Requirement-to-test mapping

- R1 to R5: `test_fuzz_cases_hold` (every generator, in chunks of 48 seeds), `test_determinism_by_value`, `test_corpus_reaches_every_class_and_every_edit` (every failure class, including from the probe slice alone; every tamper, fault and scramble; archiver faults at genesis, middle and tip; malformed requests over a corrupt log).
- R6: `test_happy_rollbacks_match_the_model_at_every_target`, `test_boundaries`.
- R7: `test_identity_source_mutant_is_green`, `test_mutant_is_red`, `test_equivalent_edits_stay_green`.

## Mutants

- Archiver boundary (the one `except BaseException` in the module):
  - `except RollbackError: raise` ahead of the catch-all; `except Exception` instead of `BaseException`.
  - One forged-class passthrough per class: every `RollbackError` class (a forged `divergent_archive` is caught by object identity) and every `WalError` class.
  - `except UnicodeEncodeError: raise` and `except TypeError: raise` ahead of the catch-all; the typed failure chained `from` the archiver's error.
  - A WAL error reported as `corrupt_source`.
  - isinstance output, or the output type check removed; the binding to the local tail token removed.
  - The frozen tail passed without a copy (caught by the argument-scribbling archiver); the live log tail passed instead.
- Request: log type check removed; isinstance request; key guard removed; key set replaced by a length or superset check; isinstance target, or the target type check removed.
- Order: target checked before source; request target checked after source.
- Source: WAL replay removed, or narrowed to one class.
- Bounds: lower bound removed; `>=` upper bound; upper bound removed.
- Restore: no log restore; no request restore; request `update` without `clear`; restore only on the failing path.
- Commit and receipt: truncation removed or off by one; to-head off by one; from-head from the first entry; token without length framing or without the prior id; rollback-id heads swapped; receipt fields out of order.

Equivalent edit (asserted green): the truncated count read from the live log. The log is restored before that read.
