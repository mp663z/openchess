# T0252 Store/export/unit/property

## Normative requirements

1. The battery exercises only the shipped production export (`store.export`, T0251). Source logs are built by the shipped `store.wal` from records made by the shipped `graph.node` runtime. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. On every seeded log, `export` returns the exact receipt in contract order:
   - `head` and `state_id` equal the WAL replay, and `state_id` equals `graph.diff.state_id` of an independent put/delete model;
   - `record_count` is an exact int equal to the number of live records, and `format` is the requested format;
   - `document` equals an independent canonical rendering and the public `render_document`;
   - `export_id` equals an independent sha256 derivation and the public `derive_export_id`.
   The exporter is called exactly once, with a plain dict copy of the model state and the format. Log and request are untouched by value, key order and identity. The result is deterministic.
3. Every prefix of every log exports, and distinct prefixes give distinct export ids. The empty log exports with the genesis head, the empty state id and an empty document. An emptied state under a non-genesis head gets a different id.
4. `render_document` matches the independent rendering on every model and on a non-ASCII, escape-heavy state. It never touches its input. Every line parses back to its record. Any format outside the closed list (`jsonl-v1` only) raises ValueError. `derive_export_id` matches direct vectors, including non-ASCII documents, hashing the UTF-8 bytes.
5. The exporter argument is detached: mutating it at every level never reaches the log or the receipt.
6. At the exporter boundary, a forged typed error fails as `divergent_export` with the mapped code and never surfaces as the forged class: an `ExportError` for every failure class other than `divergent_export`, and a `WalError` of every class. So does any other BaseException, and None, bytes, int, list, str subclass or surrogate output fails as `divergent_export`, with log and request untouched. So does any exact str other than the canonical rendering: a trailing space, a changed separator, reordered lines, or another state's document. An exporter closing over the live log and request adds keys at every level, changes and removes values, and inserts into and deletes from both containers. All of it is undone on both exits.
7. Malformed requests fail as `malformed_export_request` before format, source or exporter, even over a corrupt log. This covers renamed, missing, extra, str-subclass and hash-colliding keys, dict subclass, list or None requests, and str-subclass, bytes, None, int or list formats. A non-list log, including a list subclass, is `malformed_export_request`.
8. An exact str format outside the closed list (case, whitespace, newline, version and other-name variants) is `unsupported_format`, before source validation, even over a corrupt log. The exporter never runs.
9. Any single-entry source tamper fails as `corrupt_source` before the exporter runs, typed and never raw, with the log untouched. The tamper set is the same one as T0216/T0225/T0243.

## Mutation check

Each of these one-line production mutants of `store/export.py` turns the battery red on its own:
- Log and request shape: isinstance log, or the log check removed; isinstance request, or the request check removed; the exact-str key check removed; the key-set check replaced by a length check, a subset check or a superset check; isinstance format, or the format type check removed.
- Format: the closed-list check removed; moved after replay; loosened to a prefix match.
- Source validation: the WAL rejection narrowed to one class.
- Exporter boundary: the frozen state passed to the exporter without a copy; `except Exception` or `except ValueError` instead of `BaseException`; `except ExportError: raise` ahead of the catch-all (a forged typed error passed through); `except _wal.WalError: _fail("corrupt_source")` ahead of the catch-all (a forged WAL error reported as corrupt source); isinstance output, or the type check removed; the binding to `render_document` removed.
- Input restore: no log restore; no request restore; request `update` without `clear`; restore only on the failing path.
- Receipt: the count taken from the log length, or off by one; head and state id swapped; `derive_export_id` arguments swapped, the format dropped from it, or its input encoded as ASCII with non-ASCII characters dropped; fields out of order.
- `render_document`: records unsorted; record keys unsorted; default separators; `ensure_ascii=True`; no trailing newline; the format check removed.

Four mutants are equivalent and stay green:
- Widening `except _wal.WalError` around replay to `except Exception`. WAL replay is total: it raises only `WalError` for any list log.
- Passing the replayed state (instead of a fresh copy) to the exporter. The replay state is already detached from the log, and the binding is computed on the separate frozen copy.
- Dropping the exporter output's UTF-8 check. A non-UTF-8 string can never equal the canonical rendering of validated records, so the binding rejects it with the same class.
- Taking the receipt's `format` from the live request instead of the frozen value. The request is restored before that read.

The mutant list is prose only. There is no GENERATED-CHECKED block; each mutant was applied one at a time, with bytecode caching off, and run against this battery.
