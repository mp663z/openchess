# T0253 Store/export/fuzz/fault

## Normative requirements

1. The battery is deterministic and seeded. It fuzzes the shipped production export (`store.export`, T0252). Every input log and request comes from an independent model of data/contracts/wal.yaml and export.yaml: the entry-id, state-id, canonical jsonl-v1 document and export-id derivations are restated in the test, never taken from production. The contract reference engine (`tests.test_t0248_export_contract`) is the differential oracle.
2. Generators (898 cases):
   - `request`: every format leaf type (None, bool, int, float, bytes, str subclass, list, dict, tuple) and exact strings outside the closed list (case, whitespace, NUL, newline, underscore and non-ASCII near misses, the empty string); a str-subclass format of a listed and an unlisted value; a dict-subclass format; dropped, added (ASCII and non-ASCII) and same-arity renamed keys; str-subclass and hash-colliding keys, alone and next to the real key; a dict subclass; None and list requests. Every rejected request, malformed and unsupported, also runs over a corrupt log.
   - `container`: non-list and list-subclass logs.
   - `source`: one tamper at the first, middle or last entry: id and prior flips, re-derived sequence shifts, bool/float sequences, inner drops, swaps, duplicates, unknown and re-derived flipped ops, digest swaps, extra, str-subclass and colliding keys, dict-subclass entries and payloads, colliding record keys, str-subclass identities and non-dict entries.
   - `exporter`: every fault over a random log, a state emptied by deletes, and the empty log. Faults: every BaseException kind; a forged typed error of every class the module and its linked modules can raise (every `ExportError` class including `divergent_export`, every `WalError` class, every `DiffError`, `DigestError` and `VariantError` class, and `ContractError`; store/export.py defines no private error classes); a real `UnicodeEncodeError` (named in the module's own except clause) and a real `TypeError`; None, bytes, int, list and str-subclass output; extra or missing final newline, CRLF, spaced separators, reversed order, BOM, surrogate, an extra record, a dropped record; ASCII-escaped and honest output (accepted); and an honest answer followed by editing the argument at every level.
   - `live`: an exporter that edits the caller's live log (append, delete, clear, reverse, entry and record edits) and request (format change, added key, clear), then answers honestly, raises or diverges.
3. Every case holds against production:
   - No raw escape: only a typed `ExportError` from the closed class set with its mapped code. Never a forged error object, and no explicit `__cause__` on any typed rejection. `__context__` is not asserted: no engine clears it.
   - The same outcome as the contract reference, and the independently known outcome where there is one.
   - At most one exporter call, and none on a request or source rejection.
4. Read-only and atomic: on every exit, success included, log and request are identical by value, exact type, key order and object identity at every level. A successful export returns the model receipt in contract order with exact str fields, after exactly one exporter call whose argument is an exact dict equal to the model state, sharing no record with the log, with the exact format string.
5. No poisoning: after any rejection, a fresh engine still exports a clean log to the model. Outcomes are deterministic by value.
6. Happy logs of up to 11 entries export to the model at every prefix, twice. `render_document` equals the model rendering and rejects unlisted formats. Boundaries: the empty log (genesis head, empty document), a state emptied by deletes (log tip head, zero records), every record live, a 64-entry log, and near-miss formats rejected as `unsupported_format`.
7. Mutation check: `_probe` runs the first 48 cases of every generator, and every exporter fault once, against a source mutant of store/export.py, with `ExportError` and `_fail` rebound to the production class. The identity mutant must pass. Each of the 61 mutants in `MUTANTS` must fail. Each entry in `_EQUIVALENT_EDITS` must pass.

## Requirement-to-test mapping

- R1 to R5: `test_fuzz_cases_hold` (every generator, in chunks of 48 seeds), `test_determinism_by_value`, `test_corpus_reaches_every_class_and_every_edit` (every failure class, including from the probe slice alone; every tamper, fault and scramble; every exporter fault at all three spots; malformed and unsupported requests over a corrupt log).
- R6: `test_happy_exports_match_the_model_at_every_prefix`, `test_render_document_is_closed_and_canonical`, `test_boundaries`.
- R7: `test_identity_source_mutant_is_green`, `test_mutant_is_red`, `test_equivalent_edits_stay_green`.

## Mutants

This list is prose only; `MUTANTS` in the test file is the source of truth.

- Exporter boundary (the one `except BaseException` in the module):
  - `except ExportError: raise` ahead of the catch-all; `except Exception` instead of `BaseException`.
  - `except UnicodeEncodeError: raise` and `except TypeError: raise` ahead of the catch-all; the typed failure chained `from` the exporter's error.
  - One forged-object passthrough per class, 24 in all: every `ExportError` class (a forged `divergent_export` is caught by raised-object identity), every `WalError`, `DiffError`, `DigestError` and `VariantError` class, and `ContractError`.
  - A WAL error reported as `corrupt_source`.
  - isinstance output, or the output type check removed; the binding to the local rendering removed.
  - The frozen state passed without a copy, or with only a shallow copy (both caught by the argument-scribbling exporter).
- Request: log type check removed or isinstance; isinstance request; key-type guard removed; key set replaced by a length or superset check; isinstance format, or the format type check removed; closed-list check removed, or loosened to strip and lower-case.
- Order: format list checked after source; the whole format check after source.
- Source: WAL replay narrowed to one class.
- Commit: log restore removed; request restore removed; request restored without clearing; restore only on failure.
- Receipt: count from the log length; export-id inputs swapped or the document dropped; head and state id swapped; field order changed.
- Rendering: identities unsorted; record keys unsorted; spaced separators; no line terminator.

## Equivalents (asserted green)

- `render-ensure-ascii`: every reachable document is ASCII (hex identities, validated standard FENs).
- `encode-check-off`: the binding compares against the canonical rendering, which never carries a surrogate, so every unencodable output already fails the binding.
- `render-format-ignored`: the engine rejects unlisted formats before rendering; the public function's own check is pinned directly by `test_render_document_is_closed_and_canonical`.
- `count-from-replayed-state`: the frozen state is a by-value copy of the replayed state.
