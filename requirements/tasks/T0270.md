# T0270 Store/corruption/unit/property

## Normative requirements

1. The battery exercises only the shipped production corruption scan (`store.corruption`, T0269). Source logs are built by the shipped `store.wal` from records made by the shipped `graph.node` runtime, then corrupted at a seeded position. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. Every seeded log gets the exact receipt in contract order. The seeds cover corrupt suffixes of 0 to 3 entries; the corrupt entry is one of 13 in-domain but WAL-invalid shapes, followed by honest-looking entries. `max_loss` is anywhere from the suffix length up.
   - `verified_count` equals an independent linear longest-prefix search with the linked WAL; production uses a binary search.
   - `verified_head` equals the WAL replay of that prefix. The replayed `state_id` equals `graph.diff.state_id` of an independent put/delete model.
   - Both counts are exact ints.
   - A non-empty suffix gives verdict `salvaged`, with a `quarantine_token` equal to an independent canonical-encoding derivation and the public `quarantine_suffix`. An empty suffix gives `clean` with a null token.
   - `scan_id` equals an independent sha256 derivation (null token as `-`) and the public `derive_scan_id`.

   The sink is called exactly once per salvage and never on a clean scan. Verified entries stay in place by identity and value, and only the suffix is removed. The request is untouched. The result is deterministic. A salvaged log then scans clean with the same head.
3. Everything from the first corrupt entry onward is quarantined, including honest entries after it. A second corruption later never moves the prefix. These give the expected receipts: the empty log, an all-corrupt log, and an emptied state under a non-genesis head.
4. The loss bound is inclusive. `max_loss` equal to the suffix length, one more, or 10**30 salvages. Every smaller value fails as `excessive_loss` with no sink call and inputs untouched.
5. `canonical_encoding` matches an independent type-tagged, length-framed encoder (byte length for strs, sorted keys, counts for lists and dicts) on every domain value. It returns a detached copy with sorted keys, never touches its input, and distinct values never share an encoding. `quarantine_suffix` and `derive_scan_id` match direct vectors, including the `qrn1|` domain tag.
6. The sink argument is detached. Mutating or extending it never reaches the log or the receipt, and no quarantined container is shared with the caller.
7. At the single `except BaseException` oracle boundary (the quarantine sink), a forged typed error fails as `divergent_quarantine` with the mapped code, never as the forged class:
   - a `CorruptionError` for every other class (`malformed_corruption_record`, `excessive_loss`);
   - a linked `WalError` of every class in `store.wal.FAILURE_MAPPING`.

   Everything below also fails as `divergent_quarantine`, with log and request untouched:
   - any other BaseException: `ValueError`, `KeyboardInterrupt`, `SystemExit`, `GeneratorExit`;
   - None, bytes, int, list or str-subclass output;
   - near-miss tokens: upper hex, a trailing newline, a leading space, a surrogate, another prefix, a flipped digit, the token of a shorter, longer or reversed suffix, a JSON-encoded token and an undomained token.

   A clean scan never calls any of these sinks.
8. A sink closing over the live log and request adds keys at every level, changes and removes values, and inserts into, reverses and deletes from both containers. All of it is undone on both exits. On success exactly the suffix is then removed, and the quarantined entries are restored too.
9. Malformed requests fail as `malformed_corruption_record` before the log, the domain, the loss check or the sink, even over an out-of-domain log. The tampers:
   - keys: renamed, missing, extra (ASCII and non-ASCII), str-subclass or hash-colliding;
   - request type: dict subclass, list or None;
   - `max_loss` values: negative, bool, int-subclass, float, str, None or list.

   A non-list log, including a list subclass, is `malformed_corruption_record`.
10. The scan domain covers the whole log.
    - Quarantined: depth exactly MAX_DEPTH (for values and keys), ints of exactly MAX_INT_BITS bits (either sign), multi-byte text, bare scalars.
    - `malformed_corruption_record`, anywhere in the log (inside a verified entry, as the corrupt entry, after it or at the end), before the loss check and the sink, with the log untouched:
      - depth MAX_DEPTH + 1, MAX_INT_BITS + 1 bits, huge ints;
      - any float (including integral, NaN and float subclasses);
      - surrogates in values or keys;
      - int, None, str-subclass or colliding keys;
      - str/int/dict/list subclasses, tuples, bytes, sets, objects;
      - aliases and cycles, including an alias across entries.

## Mutation check

Each of these one-line production mutants of `store/corruption.py` turns the battery red on its own:
- Request and log shape:
  - isinstance request; the length check dropped; the exact-str key guard removed or isinstance; the `max_loss` name check dropped;
  - isinstance `max_loss`, or its type check removed; `<= 0`, or the sign check removed;
  - the log type check removed.
- Domain: depth `>=` or `+ 1`; int bits `>=` or `+ 1`; isinstance for int, str or container kinds; surrogates passed through; the alias/cycle check removed; the dict key check removed.
- Encoding: keys unsorted or reversed; str framed by character length; ints without a length frame; bool tags swapped; lists or dicts without a count; no `qrn1|` domain tag.
- Scan id: a null token not rendered as `-`; verdict dropped; counts swapped.
- Detection: the full-log shortcut always taken; the binary search returning the bad bound; the midpoint test inverted; the empty prefix not mapped to genesis.
- Loss and clean: a clean scan calling the sink; `>=` for the loss bound, or the check removed.
- Sink boundary (forged typed errors, one mutant each at the `except BaseException` boundary):
  - `except CorruptionError: raise` ahead of the catch-all (a forged error passed through);
  - `except CorruptionError as error: _fail(error.failure_class)` (a forged error remapped to its own class);
  - `except _wal.WalError: raise` (a forged WAL error escaping raw);
  - `except _wal.WalError: _fail("malformed_corruption_record")` and `_fail("excessive_loss")` (a forged WAL error remapped).
- Other sink mutants: `except Exception`; isinstance output; the byte-exact binding removed; the frozen suffix passed without a copy; the suffix taken from the live log.
- Restore: no log restore; `update` without `clear`; no request restore; request `update` without `clear`; nested containers not snapshotted; restore only on the failing path.
- Commit and receipt: the suffix not removed, or removed one entry late; head and count fields swapped; a salvage labelled `clean`.

Six mutants are equivalent and stay green:
- isinstance for the log type check. A list subclass then fails the exact-type domain encoding with the same class, before anything else runs.
- isinstance for dict keys in the domain encoding. A str-subclass key then fails the exact-type scalar encoding of the key.
- Dropping the token grammar check, or using `match` instead of `fullmatch`, or dropping the output UTF-8 check. The canonical token always fits the grammar and is ASCII, so the byte-exact binding rejects every string these checks would. The masking is one-way: dropping the binding is red, because grammar-valid strings (a flipped digit, another suffix's token) are not the byte-exact token.
- Taking the lost count from the live log. It is read before any sink call, when the log still has its frozen length.

The mutant list is prose only. There is no GENERATED-CHECKED block. Each mutant was applied one at a time, with bytecode caching off, and run against this battery.
