# T0279 Store/crash resume/unit/property

## Normative requirements

1. The battery exercises only the shipped production crash resume (`store.crash_resume`, T0278). Source logs are built by the shipped `store.wal` from records made by the shipped `graph.node` runtime, then torn at a seeded position. It imports nothing from `tests.*`. Properties are deterministic and seeded.
2. On every seeded torn log (tail of 0 to 3 entries; the tear is one of 13 WAL-invalid but canonical-JSON shapes, followed by honest-looking entries), with any checkpoint from 0 up to the surviving prefix, `resume` returns the exact receipt in contract order:
   - the surviving prefix length equals an independent longest-prefix search with the linked WAL;
   - `head` and `state_id` equal the WAL replay of that prefix, and `state_id` equals `graph.diff.state_id` of an independent put/delete model;
   - `resumed_count` and `discarded_count` are exact ints;
   - `quarantine_token` equals an independent derivation and the public `quarantine_tail`;
   - `resume_id` equals an independent sha256 derivation over head, state id, both counts and the token.
   The sink is called exactly once, including for an empty tail, with the canonical tail. The surviving entries stay in place by identity and value, only the tail is removed, and the request is untouched. The result is deterministic, and resuming the resumed log discards nothing and keeps head and state. The checkpoint is not part of the receipt.
3. Everything from the first tear onward is discarded, including honest entries after it. The empty log, an all-torn log and an emptied state under a non-genesis head give the expected receipts.
4. `quarantine_tail` matches direct vectors: domain separation, character-length framing, sorted keys, compact separators, UTF-8 bytes for non-ASCII text. Order and framing change the token. It never touches its input.
5. The sink argument is detached: mutating or extending it never reaches the log or the receipt, and no discarded container is shared with the caller.
6. At the sink boundary, a forged typed error fails as `divergent_quarantine` with the mapped code, never as the forged class: a `ResumeError` for every other failure class, and a `WalError` (`corrupt_chain`, `malformed_wal_entry`). So does any other BaseException (`ValueError`, `KeyboardInterrupt`, `SystemExit`, `GeneratorExit`), and None, bytes, int, list or str-subclass output. So does any exact str that is not the byte-exact token: upper hex, a trailing newline, a leading space, another prefix, a flipped digit, and the token of the empty, a shorter, a longer, a reversed or an ASCII-escaped tail. Log and request are untouched.
7. A sink closing over the live log and request adds keys at every level, changes and removes values, and inserts into, reverses and deletes from both containers. All of it is undone on both exits. On success exactly the tail is then removed, and the discarded entries are restored too.
8. Malformed requests fail as `malformed_resume_record` before the checkpoint, source or sink, even over an inadmissible log. This covers renamed, missing, extra (ASCII and non-ASCII), str-subclass and hash-colliding keys; a dict subclass, list or None request; and a bool, int-subclass, float, str, None or list checkpoint, including a negative checkpoint that carries an extra key or is an int subclass. A non-list log, including a list subclass, is `malformed_resume_record`.
9. A negative checkpoint is `unknown_checkpoint` before the source is read, even over an inadmissible log. The sink never runs.
10. Admission of the torn tail:
    - These are quarantined: depth exactly MAX_DEPTH, ints of exactly MAX_INT_DIGITS digits (either sign), finite floats, multi-byte text, bare scalars and strings.
    - These fail as `malformed_resume_record` before the sink, with the log untouched, whether as the tear itself or after it: depth MAX_DEPTH + 1, MAX_INT_DIGITS + 1 digits, huge ints, NaN or infinity, surrogates in values or keys, int, str-subclass or colliding keys, str/int/float/dict/list subclasses, tuples, bytes, sets, objects, aliases and cycles.
    - An inadmissible value inside an acknowledged entry is `corrupt_source`, and inside a torn one it is `malformed_resume_record`.
    - The linked WAL itself rejects every inadmissible value wherever it sits in an honest entry.
11. A tear at or before the checkpoint, and any checkpoint past the prefix or past the log, is `corrupt_source` before the sink, with the log untouched.

## Mutation check

Each of these one-line production mutants of `store/crash_resume.py` turns the battery red on its own:
- Log and request shape: isinstance log, or the log check removed; isinstance request, or the request check removed; the exact-str key guard removed; the key-set check replaced by a length check, a subset check or a superset check; isinstance checkpoint, or the checkpoint type check removed.
- Checkpoint: `<= 0` for the negative check, or the check removed; `>=` for the past-the-log check; `<=` for the prefix check, or the check removed.
- Admission: the tail admission check removed; depth `>=` or `> MAX_DEPTH + 1`; the alias/cycle check removed; digit bound `<` or `+ 1`; the finite-float check removed; the UTF-8 check removed; isinstance for str, int, float or container kinds.
- Sink boundary: the frozen tail passed without a copy; the live tail used as the frozen tail, or a shallow copy of it; `except Exception`; `except ResumeError: raise` ahead of the catch-all; isinstance output; the byte-exact binding removed; the sink skipped for an empty tail.
- Restore: no restore; restore only on the failing path; `update` without `clear`; no log snapshot; no request snapshot; nested containers not snapshotted.
- Commit and receipt: the tail not removed, or removed one entry late; replay up to the checkpoint instead of the prefix; the shortest prefix instead of the longest; head and state id swapped in the resume id, or the token dropped from it; the discarded count from the log; head and state id fields swapped.
- Token: `ensure_ascii=True`; unsorted keys; default separators; no length frame; byte-length frame; no domain tag.

Six mutants are equivalent and stay green:
- Dropping the past-the-log check. The prefix never exceeds the log, so the prefix check rejects the same checkpoint with the same class before any sink call.
- Dropping the token grammar check, or using `match` instead of `fullmatch`. The canonical token always fits the grammar, so the byte-exact binding rejects every string the grammar would. The two checks mask each other one way only: the binding alone decides the outcome, so a grammar mutant stays green, while dropping the binding is red because many grammar-valid strings (a flipped digit, another tail's token) are not the byte-exact token.
- Dropping the admission cap on the prefix search, or setting it one entry late. The linked WAL rejects every inadmissible value wherever it sits in an entry (R10), so the longest prefix is the same.
- isinstance for keys in the admission walk. A str-subclass key still fails the exact-type scalar check that follows.

The mutant list is prose only. There is no GENERATED-CHECKED block. Each mutant was applied one at a time, with bytecode caching off, and run against this battery.
