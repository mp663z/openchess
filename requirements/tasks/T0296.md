# T0296 Jobs/idempotency/implement

## Normative requirements

1. `server.jobs_idempotency` implements `IdempotencyError`, `JobsIdempotencyEngine` with `apply(state, ledger, request)`, `request_fingerprint`, `derive_receipt_id`, `QueueError` (the composed queue's own error, re-exported) and `FAILURE_MAPPING` for data/contracts/jobs_idempotency.yaml (contract id `jobs-idempotency`), composing `server.jobs_queue` (contract id `jobs-queue`). Grammars, record fields, outcome values and the failure mapping are loaded from the contract file, never restated. Production must not import or execute `tests.*`.
2. Validation order is request first (`malformed_idempotency_request`, the payload checked through the linked queue contract), then the queue state (`corrupt_queue`), then the receipt ledger bound to the live state (`corrupt_ledger`: exact receipt shape, ASCII-fullmatch grammars, receipt ids re-derived, unique keys, contiguous sequences from zero, prior/state chaining, and the last receipt naming the live state). Key types are checked as exact strs before any set or hash comparison; the graph-disjointness pin rejects a request that shares a container with the state or the ledger.
3. The caller-supplied fingerprinter is UNTRUSTED: it is called exactly once, only after request, state and ledger validate, on a DETACHED copy of the frozen request; any BaseException, non-exact-str, wrong-grammar, UTF-8-inencodable or request-divergent output fails closed as `divergent_fingerprint`. Reference-preserving snapshots of the state, ledger and request are taken before the call and restored in a finally, so an oracle rewriting the live inputs through a captured closure cannot corrupt them.
4. Deduplication is key-then-fingerprint: a seen key with a byte-exact fingerprint mismatch rejects `key_conflict`; a match replays the stored receipt as a fresh copy, committing nothing. Otherwise the queue transition stages on the frozen state and commits with its receipt together LAST; a queue rejection propagates UNWRAPPED with the queue contract's own code (the contract pins the propagated CODES, not the error-class identity), committing nothing. A rejected call leaves the state, the ledger and the request bit-identical.
5. The T0295 red battery turns green by replacing only its three binding lines (`QueueError`, `JobsIdempotencyEngine`, `IdempotencyError`). The battery is amended ahead of the switch in this change - QueueError derived through the binding instead of the T0284 import, and the reference-source mutants (`_source_mutant`: identity, equivalent edits, `_SM` edits) scoped to the reference substrate with a skip under the production binding, splitting the class-based mutants (which subclass the BOUND engine) out so they keep running under both bindings. The amendment is behavior-preserving under the reference binding: 86 passed before and after. Under the production binding the battery runs 72 passed and 14 skipped; the 14 reference-substrate skips are replaced by production-source mutants in `tests/test_t0296_idempotency_runtime.py`.
