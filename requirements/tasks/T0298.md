# T0298 Jobs/idempotency/fuzz/fault

## Normative requirements

1. Seeded differential fuzz of `server.jobs_idempotency.JobsIdempotencyEngine` against the T0293 reference engine as oracle (both driven with the honest contract fingerprinter): hostile requests (every field over the hostile-value tuple, non-dict requests, missing/extra fields, unknown op, op key smuggled inside the payload), hostile ledgers (9 mutation families: non-list ledgers, hostile/missing/extra receipt fields, sequence edits, duplicate keys, tampered receipt ids, reversed chain, truncation), and hostile states (6 mutation families over the linked queue contract). Per case both engines must agree on the outcome word and canonical receipt, or on the error type name plus `failure_class` plus `code`; end state and ledger must be canonically identical; the request must be canonically unchanged; a rejection must leave state and ledger canonical-identical (total rejection).
2. Fault injection: request payloads, stored state payloads and ledger receipts built from objects whose hooks raise (Boom/BoomDict/BoomList/BoomStr) must be rejected with the pinned typed failure (`malformed_idempotency_request` for request payloads, `corrupt_queue` for stored state payloads, `corrupt_ledger` for ledger receipts) without production running any caller code: every hostile hook appends to an external tripwire list before raising, and the list is asserted empty after the expected refusal, so a hook whose raise was swallowed is still caught. State, ledger and request are fingerprinted before and after with a hook-free canonical form (exact builtin containers walked structurally; hostile objects, including dict/list/str subclasses, compared as type tags only - no hook can run, no internals are read). Hostile fingerprint oracles fail closed on both engines: raising `KeyboardInterrupt`/`SystemExit`/`GeneratorExit`/`RuntimeError`, or returning a non-str, a bad-grammar token, a well-formed but unbound token, or a lone-surrogate token, each reject as `divergent_fingerprint` with `__cause__` None and inputs canonical-identical. An argument-mutating oracle (clearing the detached payload copy, returning the honest token of the cleared copy) is called exactly once and rejects `divergent_fingerprint` with `__cause__` None and all inputs canonical-identical on both engines; a closure-mutating oracle cannot corrupt the caller's live objects on either engine. A late internal fault after the staged queue transition leaves state, ledger and request canonical-identical.
3. Boundary differentials: payload nesting at `MAX_DEPTH` accepts and `MAX_DEPTH + 1` rejects; payload integers at 4000 digits accept and 4001 reject; idempotency keys at 128 grammar-valid characters accept, and 129 characters, a leading dot, the empty string, an embedded space and a non-ASCII key reject.
4. Happy and rollback streams: valid idempotent streams (30 seeds x 120 steps: fresh keys, replays, key conflicts, all four ops, lease lapses) agree per step on the full outcome tuple. Rollback windows (20 seeds x 100 steps) pin the content-addressed detection boundary exactly as implemented: truncating the ledger across a state-changing receipt rejects `corrupt_ledger`; truncating only a state-neutral (replay) suffix or the whole ledger is undetectable and accepted (genesis). No stronger rollback guarantee is claimed.

## Scope and limitations (disclosed, not claimed otherwise)

- The differential oracle is the T0293 reference engine, which shares the linked `QueueEngine` and contract-loaded helpers with production by design; the differential is therefore not wholly independent. The comparison per case runs each engine on its own deep copy of the inputs; the composition builder and the persistent stream driver are production-run.
- `_canon`/`_safe_canon` tag scalars by exact type (False is not 0; huge ints compare by hex) and compare hostile objects as type tags only: no internals, no identity proof, and no alias/cycle witness generators. No universal identity or population guarantee is claimed.
- Rollback detection is content-addressed: truncation across a state-changing receipt rejects `corrupt_ledger`; truncating only a state-neutral (replay) suffix or the whole ledger is undetectable and accepted (genesis). No stronger rollback guarantee is claimed.
