# T0298 Jobs/idempotency/fuzz/fault

## Normative requirements

1. Seeded differential fuzz of `server.jobs_idempotency.JobsIdempotencyEngine` against the T0293 reference engine as oracle (both driven with the honest contract fingerprinter): hostile requests (every field over the hostile-value tuple, non-dict requests, missing/extra fields, unknown op, op key smuggled inside the payload), hostile ledgers (9 mutation families: non-list ledgers, hostile/missing/extra receipt fields, sequence edits, duplicate keys, tampered receipt ids, reversed chain, truncation), and hostile states (6 mutation families over the linked queue contract). Per case both engines must agree on the outcome word and canonical receipt, or on the error type name plus `failure_class` plus `code`; end state and ledger must be canonically identical; the request must be canonically unchanged; a rejection must leave state and ledger canonical-identical (total rejection).
2. Fault injection: request payloads, stored state payloads and ledger receipts built from objects whose hooks raise (Boom/BoomDict/BoomList/BoomStr) must be rejected (`malformed_idempotency_request`, `corrupt_queue` or `corrupt_ledger`) without production running any caller code, leaving inputs canonical-identical. Hostile fingerprint oracles fail closed on both engines: raising `KeyboardInterrupt`/`SystemExit`/`GeneratorExit`/`RuntimeError`, or returning a non-str, a bad-grammar token, a well-formed but unbound token, or a lone-surrogate token, each reject as `divergent_fingerprint` with `__cause__` None and inputs canonical-identical. Argument-mutating and closure-mutating oracles are inert and produce identical results on both engines. A late internal fault after the staged queue transition leaves state, ledger and request canonical-identical.
3. Boundary differentials: payload nesting at `MAX_DEPTH` accepts and `MAX_DEPTH + 1` rejects; payload integers at 4000 digits accept and 4001 reject; idempotency keys at 128 grammar-valid characters accept, and 129 characters, a leading dot, the empty string, an embedded space and a non-ASCII key reject.
4. Happy and rollback streams: valid idempotent streams (30 seeds x 120 steps: fresh keys, replays, key conflicts, all four ops, lease lapses) agree per step on the full outcome tuple. Rollback windows (20 seeds x 100 steps) pin the content-addressed detection boundary exactly as implemented: truncating the ledger across a state-changing receipt rejects `corrupt_ledger`; truncating only a state-neutral (replay) suffix or the whole ledger is undetectable and accepted (genesis). No stronger rollback guarantee is claimed.

## Requirement-to-test mapping

- R1: `test_every_request_field_rejects_or_matches_oracle_on_hostile_values` (3 fields x 4 templates x 18 values), `test_non_dict_requests_are_malformed_and_total` (18), `test_missing_and_extra_request_fields_are_malformed`, `test_unknown_op_and_op_smuggled_in_payload_are_malformed`, `test_hostile_ledgers_match_oracle_and_never_mutate_on_reject` (40 seeds x 25), `test_stale_compositions_reject_corrupt_ledger_then_repaired_accepts`, `test_empty_ledger_is_a_genesis_boundary_on_both_engines`, `test_hostile_states_match_oracle_and_never_mutate_on_reject` (30 seeds x 25).
- R2: `test_faulting_or_hostile_payloads_rejected_without_running_caller_code` (10), `test_faulting_state_payloads_rejected_without_running_caller_code` (10), `test_faulting_ledger_receipt_rejected_without_running_caller_code`, `test_hostile_oracles_fail_closed_on_both_engines` (8 oracles x 2 engines), `test_argument_mutating_oracle_is_inert_on_both_engines`, `test_closure_mutating_oracle_cannot_corrupt_inputs_on_either_engine`, `test_late_internal_fault_leaves_state_ledger_and_request_untouched`.
- R3: `test_payload_depth_and_int_boundaries_match_oracle`, `test_key_grammar_boundaries_match_oracle`.
- R4: `test_valid_idempotent_streams_match_oracle` (30 seeds x 120 steps), `test_streams_with_random_rollback_windows_match_oracle` (20 seeds x 100 steps).
