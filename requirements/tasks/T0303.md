# T0303 Jobs/cancel/fixture

## Requirements

1. tests/fixtures/cancel/cases.json is a closed fixture for the T0302 jobs-cancel contract: 4 happy, 12 boundary, 40 malformed and 3 rollback rows, one per line. Pinned cancellation records come from the T0302 reference cancel.
2. Every row is pinned by name, a semantic manifest, per-row type-exact edge checks and absolute type-exact scalar anchors, plus a canonical sha256. The semantic closure anchors every accepted-side request absolutely - the happy/boundary requests, each malformed row's minimal repair, each rollback follow-up, every scalar type-exactly and each payload by its pd1 preimage - and the rollback expected record the same way. Each malformed or rejected request is tied to its anchored counterpart type-exactly at every non-locus field. Its declared defect locus is pinned exactly where the defect is a single value (the extra field's note value, every renamed, boundary and lease locus, the surrogate payloads), and constrained semantically where any value meeting the constraint realizes the same defect: the 4001-digit payload int and the 65-deep payload chain intentionally accept any value meeting the pinned type and bound, and their literal row values are digest-pinned. Substituted, swapped, dropped or duplicated rows, and retypes at anchored or non-locus fields - including joint retypes applied consistently to both a malformed request and its repair, or with the record digests recomputed to match - fail the semantic closure on its own, without the digest table. The canonical sha256 of each parsed row pins the remaining literal content (the constraint-locus values, the why text); it compares parsed canonical JSON, not source whitespace or key order. Execution re-derives the pinned records. Every pinned cancelled_at and decision_id equals the hand-built contract preimage.
3. Malformed rows cover every failure class (malformed_cancel_request, corrupt_job, job_not_cancellable), including same-arity renamed-key rows on the request and on the job, now/seq/priority one past each bound and one below each floor, a job_id with a trailing newline, lease fields on a non-leased job, a done job at attempts 0 and past max_attempts, a dead job below max_attempts, payload depth 65, a 4001-digit payload int that passes the bit pre-screen (10**4000), a lone surrogate in a payload value and in a payload key. Corrupt non-cancellable jobs pin job integrity ahead of the cancellable check. Each row has a single-locus minimal repair that cancels, except that a corrupt done/dead job's repair (declared in minimal_repair.expect_failure) is still not cancellable and fails job_not_cancellable. Rejections are fresh typed errors with retryable false, and the input stays type-exactly unchanged. Validation order is request shape, then job integrity, then the cancellable check.
4. Rollback rows cover every failure class. The rejected request stays type-exactly identical, and the valid follow-up cancels as pinned.
5. Hostile-type rows are derived from every accepted request (56 requests, 84 variants each):
   - hostile containers (dict-subclass, lying dict, list-subclass) on the request, the job and the payload;
   - str-subclass keys in 3 forms on every request and job field;
   - str-subclass, eq-raises, repr-raises and nested values on the str fields, and int-subclass, bool and float values on the int fields, of the request and the job;
   - payload values JSON cannot store: NaN, inf, an aliased container, int / str-subclass / eq-raises keys, and str-subclass, repr-raises, int-subclass, float-subclass and tuple values.
   Each must fail typed, run no user code and leave the input unchanged.
6. Every one of the 38 T0302 reference mutants turns this fixture red. So do 13 extra fixture-level mutants covering the op, job-type and requester checks, the now/seq/priority floors, the job_id grammar, the status enum, the free-lease owner/expiry checks, the lease-expiry floor, the payload-key scalar check and the payload digest input. The T0302 equivalent edit keeps it green.
