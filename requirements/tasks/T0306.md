# T0306 Jobs/cancel/unit/property

## Normative requirements

1. `tests/test_t0306_cancel_unit_property.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_cancel.cancel` (T0305) with unit rows and seeded properties, where rollback is proven for a pure callable with fresh requests and no persistent engine state. It adds no production code.
2. Seeded and hostile-value sweeps compare production with an independent model written from the contract (hand-built grammar and bound checks, a bounded payload walk, hand-built `pd1:`/`cd1:` digests; no shared code with production), type-exact (a bool is not an int): same record, or same failure class with the mapped code, `retryable` false, no cause or context. Determinism, ID-binding, container-sharing, rollback, and lowered-limit units call production directly.
3. Every call leaves the request unchanged, checked as a serialized-value comparison (a JSON or repr snapshot; it can invoke hooks and is not a hostile-identity proof), and returns a record that shares no container with it.
4. Every request and job bound is pinned on both sides, hostile values (bool, float, NaN, bytes, tuple and object roots, str and int subclasses, inert str-subclass keys, missing, extra and non-str keys, payload aliases and cycles, lone surrogates) are refused with the right class at every field, and the failure precedence is request shape, then job integrity, then status.

## Mutation check

Review history: the first adjudication claimed 2 behavior-equivalent survivors, including `ensure_ascii=True` -> `False` in the canonical encoder with the note "every encoded string is ASCII by grammar". That survivor note was false: payload JSON strings may be non-ASCII, and the flip changes both digests for such payloads (independent review FAIL witness). The same review showed a bool-for-int `priority` retype survived all tests because the model comparison used plain `==`. Both are fixed in this revision by `test_unicode_payload_digest_pins_the_ascii_escaped_preimage`, the type-exact `_typed` comparator, `test_typed_comparison_catches_a_bool_retype`, and exact accepted-result field-type pins in the harness.

Re-run after those fixes: 91 single-token mutants of `server/jobs_cancel.py` (comparison, boolean, return, offset, operator and integer-literal swaps) were run author-side against this file alone, stopping at each mutant's first failing test; the generator and records are not checked in, so this census is author-run, not independently certified. 83 mutants are killed by semantic outcomes (82 assertion, 1 wrong typed refusal); the `ensure_ascii` flip is now among the assertion kills. 7 are killed only by a raw exception: each is a wrong-accept sabotage (a guard flipped so a hostile value passes validation) whose wrongly-admitted input crashes downstream (TypeError/AttributeError/ValueError) before any record exists to compare; re-running each without stopping found no assertion failure. The 1 survivor is behavior-equivalent: `MAX_INT_BITS` 13288 -> 13289 widens only the bit-length pre-screen (every int it newly admits has more than 4000 decimal digits and is rejected by the exact digit check).
