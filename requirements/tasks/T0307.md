# T0307 Jobs/cancel/fuzz/fault

## Normative requirements

1. `tests/test_t0307_cancel_fuzz_fault.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_cancel` under seeded fuzz and injected faults, with the contract's reference implementation (`tests.test_t0302_cancel_contract`) as the differential oracle. It adds no production code.
2. Every valid case is mutated at every reachable path with 52 hostile value factories (every gated type, boundary ints and strings, armed objects whose every hook fails the test, attribute bombs, lying dicts, cycles, 100000-deep and wide values), keys are dropped, added and replaced by non-str or armed keys, and oversize ints run under a lowered `sys.set_int_max_str_digits`. Production and the reference must return the same record (type-exact: a bool is not an int) or the same failure class and code, with `retryable` false and no cause or context.
3. A rejected call leaves its input structurally identical, checked with an iterative, hook-free snapshot (a structural-value comparison, not a hostile-identity proof). An accepted call leaves its request identical. Production never runs caller code: any hook of an armed object fails the test.
4. A fault injected at each sha256 step (payload digest and decision id, the only post-validation steps) propagates, leaves the input untouched, and the next call returns the baseline outcome; rejected requests never reach the digest step. Pathological shapes (100000 levels deep, 100000 wide, 5 MB strings, 100000-digit ints) are handled in bounded time without recursion.
5. Cancel-specific seeded lifecycle streams (ready or leased, then terminal after a cancellation lands) are compared with the oracle step by step, and every status, lease and clock edge is swept against the oracle (see the mapping). Streams are sequences of fresh requests to a pure callable; there is no persistent engine state.

## Requirement-to-test mapping

- Differential fuzz (oracle: the contract reference): `test_bases_are_valid_for_both_engines_and_agree`, `test_every_path_of_every_valid_case_rejects_or_matches_the_oracle_on_hostile_values`, `test_dropping_any_key_or_adding_any_key_matches_the_oracle`, `test_seeded_multi_mutation_fuzz_matches_the_oracle`, `test_every_field_boundary_value_matches_the_oracle`, `test_every_string_field_boundary_matches_the_oracle`, `test_key_order_never_changes_the_outcome_and_runs_are_deterministic`.
- Fault objects and hostile shapes (no caller code, always typed, input untouched): `test_armed_objects_at_every_path_never_run_caller_code_and_fail_typed`, `test_armed_and_nasty_keys_in_every_dict_are_refused_without_running_hooks`, `test_non_dict_and_hostile_top_level_requests_are_total`, `test_hundred_thousand_deep_and_wide_values_at_every_field_fail_typed_in_bounded_time`, `test_huge_ints_never_hit_a_str_conversion_under_a_lowered_interpreter_limit`.
- Injected faults: `test_a_fault_at_any_digest_step_leaves_input_untouched_and_the_next_call_is_clean`, `test_rejected_requests_never_reach_the_digest_step`.
- Module-specific streams and sweeps: `test_plain_str_subclass_keys_with_valid_names_and_values_are_refused_like_the_oracle`, `test_status_and_lease_streams_match_the_oracle_and_stay_terminal`, `test_every_status_lease_and_clock_edge_matches_the_oracle`.

## Mutation check

91 single-token mutants of `server/jobs_cancel.py` (comparison, boolean, return, offset, operator and integer-literal swaps; comments and docstrings not mutated) were run author-side against this file alone, stopping at each mutant's first failing test; the generator and records are not checked in, so this census is author-run, not independently certified. 69 mutants are killed by semantic outcomes (an assertion or an oracle mismatch, including armed-hook "caller code ran" failures, which this sweep does not split out). 15 are killed only by a raw exception: each is a wrong-accept sabotage whose wrongly-admitted input crashes downstream before any record exists to compare; re-running each without stopping found no assertion failure, and they are not counted as semantic kills.

7 survivors, each manually verified by hand-running a distinguishing input: 1 is behavior-equivalent — `MAX_INT_BITS` 13288 -> 13289 widens only the bit-length pre-screen (a 13289-bit int has more than 4000 decimal digits and is rejected by the exact digit check). The other 6 are genuine gaps of this file alone, not claimed equivalent: the exact nesting-depth boundary (`MAX_DEPTH` 64 -> 65, depth counter `1` -> `0`, `depth >` -> `>=`) and the exact 4000-digit / pre-screen boundary (`MAX_INT_DIGITS` 4000 -> 4001, `<=` -> `<`, `bit_length >` -> `>=`) are swept with distant values here (70 and 100000 deep, 639 and 5000 digits) but not at the exact edge; those exact edges are pinned by the T0306 unit rows (`test_payload_depth_and_int_digits_are_exact`).
