# T0308 Jobs/cancel/integration/restart

## Normative requirements

1. `tests/test_t0308_cancel_integration_restart.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_cancel` across process restarts. It adds no production code.
2. Production `cancel` is a pure callable: it persists nothing, and this battery claims no durability guarantee for it. What is persisted is the test harness's own stream of decision records (the `cd1`-addressed receipts themselves, not just their ids), written as canonical JSON under tmp_path with an atomic replace. A restart executes the production source anew in an isolated module namespace (the canonical module in sys.modules is never reloaded or mutated; `test_a_restart_never_touches_the_canonical_production_module` pins that) and the stream continues. Sampled streams (12 seeds restarted at every step, 10 with one random cut point, 3 with four steps each run in a real child interpreter) must give the same outcomes (type-exact: a bool is not an int) and the same durable log as an uninterrupted run and as the contract's reference implementation (`tests.test_t0302_cancel_contract`), the differential oracle. The real child interpreter loads the durable log, runs its step on the actual request object (with its own before/after input check), and returns the updated durable log, which must equal the in-process continuation type-exactly.
3. Replaying the same seeded stream after restarts (6 seeds) gives identical outcomes, and decision ids are one per distinct request within the finite generated request domain of those seeds (no universal injectivity claim). Only the restart battery (T0353 family) mixes the real queue engine into its streams; this battery does not.
4. Every `_outcome` call passes the actual request object and asserts that same object is structurally identical after the call (a serialized-value snapshot, not a hostile-identity proof), accepted and refused alike; the scribble canary test pins that this assertion is load-bearing on both paths. One disclosed exception: the Unicode preimage row makes one direct production call outside `_outcome` on a test-literal input. Forged or malformed requests are refused with the oracle's failure class and code and the stream then continues: after the refusal window a valid follow-up on the reloaded file succeeds, matches the oracle, and advances the persisted log by one record. They are built from request fields only: cancel carries no previous record, so no digest-recomputed forgery family exists here (that family is T0326/T0344's). A truncated durable file is a host-level JSON error and never reaches the engine; the test restores the captured last-good bytes by hand (no automatic recovery is claimed) and the restored file stays usable.
5. Boundary rows pin the exact bounds a restarted engine can reach, with the oracle as the expected value: status in {ready, leased, done, dead}; attempts in {-1, 0, 1, MAX_ATTEMPTS, MAX_ATTEMPTS+1}; now in {-1, 0, 1, MAX-1, MAX}; seq in {-1, 0, MAX-1, MAX}; priority in {-1, 0, 9, 10}; leased rows cross lease_expires_at in {50, 100, 150} against those clocks. Persisted canonical JSON pins ascii-escaped encoding with a non-ASCII payload preimage row, round-tripped through the real save/load file path.

## Revision history (author summaries, not verbatim reviewer quotes)

- r1 (cc2e6f5c): FAILed by both independent reviewers. Summary of the grounded findings: `_outcome` snapshotted the original request but passed a deepcopy into the callable, so the purity assertion could not observe production (both reviewers reproduced with outcome-preserving scribble mutants on the accepted and refused paths); the durable log stored only decision-id strings, not the decision records R2 describes; the Unicode record round-trip was in-memory, not through the save/load file; the real child interpreter parsed but never used its durable JSON argument and never returned a continued log; the refused-step test had no valid follow-up after the refusal window; the "every bound edge" grid covered only a finite subset (no below/above-range numeric refusal edges, no done/dead statuses, fixed lease expiry); the truncated-file clean path mixed `cancel` and `CancelError` from two different fresh module instances; uniqueness and restore claims were broader than what the tests establish. r2 fixes each: actual-argument purity with a permanent scribble canary, records persisted in the log and round-tripped through the real file, the child continues and returns the durable log, a valid oracle-compared follow-up after refusals, the widened both-sides grid (statuses, attempts, now, seq, priority, lease-expiry crossings), one fresh module per truncated-file continuation, and narrowed claims (finite-domain uniqueness, manual restore, disclosed direct-call exception). The mutation census below was re-run in full against the r2 harness before delivery.

## Mutation check

Two author-run sweeps against this file alone (re-run against the r2 harness after the r1 census), stopping at each mutant's first failing test; the generator and records are not checked in, so these tallies are author-run, not independently certified. Raw-crash kills (a wrong-accept sabotage whose wrongly-admitted input crashes downstream before any record exists) are classified by the extracted exception type (KeyError/AttributeError/TypeError) at the first failing test and kept separate from semantic kills; every survivor was verified by an actual cross-file run, not by inspection.

Family 1 (the standard single-token set: comparison, boolean, return, offset, operator and integer-literal swaps; comments and docstrings not mutated): 91 mutants. 61 semantic kills, all plain outcome assertions (0 armed-hook or tripwire kills - this battery uses hook-free subclasses and no armed machinery, per the T0317 pattern). 5 raw-crash kills, kept separate. 25 survivors of this file alone: this battery sweeps bounds relative to contract literals and carries a thin hostile-payload surface by design, so production validation mutants outside its reach survive here; 24 of the 25 were verified killed by actual cross-file runs against the T0306 exact unit rows (each killing test recorded: `test_now_bound_is_exact`, `test_payload_depth_and_int_digits_are_exact`, `test_non_dict_requests_are_malformed`, `test_ready_record_is_exact_and_ordered`, `test_engine_matches_independent_model_on_random_requests`, `test_lowered_int_str_limit_fails_closed`, `test_payload_hostile_scalars_are_corrupt`, `test_hostile_payload_roots_are_corrupt`, `test_lease_invariants_are_exact`). The remaining survivor, `MAX_INT_BITS` 13288 -> 13289, is behavior-equivalent (pre-screen widening only; every int it newly admits has more than 4000 decimal digits and is rejected by the exact digit check), the same adjudication as T0306 and T0307; it also survives the T0306+T0307 cross-file run, which is what behavior-equivalence predicts. The widened r2 grid and canary rows now kill 8 mutants that survived the r1 harness (the L47/L48 lease-invariant rows and the L168-L171 engine rows).

Family 2 (identity/None/membership swaps, `fullmatch` -> `match`, `type(` -> `isinstance(`, per the T0317 precedent): 31 mutants. 16 semantic kills, all plain outcome assertions. 13 raw-crash kills, kept separate. 2 survivors of this file alone, both verified killed by actual cross-file runs: `fullmatch` -> `match` by `test_requester_and_worker_grammar_is_exact`, and the payload-walk `None` -> `0` by `test_ready_record_is_exact_and_ordered` (this battery's payloads carry no `None`, T0306's base payloads do).
