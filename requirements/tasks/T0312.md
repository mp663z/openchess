# T0312 Jobs/retry/fixture

## Requirements

1. tests/fixtures/retry/cases.json is a closed fixture for the T0311 jobs-retry contract: 4 happy, 9 boundary, 24 malformed and 3 rollback rows, one per line. Pinned records come from the T0311 reference decide.
2. Every row is pinned by name, a semantic manifest, a per-row edge check and a canonical sha256. Substituted, swapped, dropped, duplicated or retyped rows fail the semantic closure on its own, without the digest table.
3. Malformed rows cover every failure class (malformed_retry_request, invalid_retry_policy, clock_overflow). Same-arity renamed-key rows (now renamed to jitter; the policy's max_delay_ms renamed to jitter_ms) pin exact key-set equality, not just the field count. Each row has a single-locus minimal repair that decides. Rejections are fresh typed errors with retryable false, and the input stays type-exactly unchanged.
4. Rollback rows cover every failure class. The rejected request stays type-exactly identical, and the valid follow-up decides as pinned.
5. Hostile-type rows are derived from every accepted request (52 requests, 52 variants each):
   - hostile containers on the request and the policy;
   - str-subclass keys in 3 forms on every request and policy field;
   - str-subclass, eq-raises and repr-raises values on the str fields;
   - int-subclass and bool values on the int fields and the policy fields.
   Each must fail typed, run no user code and leave the input unchanged.
6. Every one of the 17 T0311 reference mutants turns this fixture red. So do 20 extra fixture-level mutants covering the key-set and type/grammar guards, the bound edges, the clock edge and precedence. The T0311 equivalent edit keeps it green.

7. A timeout failure is pinned at the last retry (attempt 4 retries, attempt 5 is dead), not only at attempt 2.
