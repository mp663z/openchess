# T0314 Jobs/retry/implement

## Normative requirements

1. `server.jobs_retry` implements `RetryError`, `decide(request)` and `FAILURE_MAPPING` for data/contracts/retry.yaml (contract id `jobs-retry`). Production must not import or execute `tests.*`.
2. The request is checked first (`malformed_retry_request`), then the policy (`invalid_retry_policy`), then the clock (`clock_overflow`): exact types only, dict keys checked as exact strs before any set comparison, job id by ASCII fullmatch, attempts 1..max_attempts, now 0..2**53-1, base_delay_ms 1..3600000, multiplier 1..10, max_delay_ms base..86400000.
3. A permanent failure or attempts == max_attempts is `dead` with null delay and retry_at; otherwise the decision is `retry` after min(max_delay_ms, base_delay_ms * multiplier ** (attempts - 1)) ms at now + delay (timeout behaves as transient, no jitter). A retry_at past 2**53-1 is `clock_overflow`, never clamped. The decision id is `rd1:` plus the sha256 of the contract preimage. Errors are fresh typed RetryErrors with no cause or context; the request is never changed.
4. The T0313 red battery turns green by replacing only its two binding lines. Every row, probe and mutant stays unchanged.
