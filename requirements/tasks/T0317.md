# T0317 Jobs/retry/integration/restart

## Normative requirements

1. `test_t0317_retry_integration_restart.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_retry` across process restarts. It adds no production code.
2. The durable value of the engine is persisted as canonical JSON under tmp_path (atomic replace), the production module is imported anew, and the stream continues. A seeded stream restarted at every step, at a random cut point, and with steps run in a real child interpreter must give the same outcomes and the same durable value as an uninterrupted run and as the contract's reference implementation (`tests.test_t0311_retry_contract`), which is the differential oracle.
3. Replaying the same stream after restarts gives identical outcomes, and receipt identifiers are one per distinct receipt.
4. A forged or torn durable value (missing, retyped, out-of-bound or re-digested fields) is refused with the oracle's failure class and code, leaves its input structurally identical, and the next valid request still succeeds. A truncated durable file is a host-level JSON error and never reaches the engine; the last good file stays usable.
5. Boundary rows pin the exact bounds a restarted engine can reach, with the oracle as the expected value.

## Mutation check

69 single-token mutants of `server/jobs_retry.py` were run against the first revision of this file alone, stopping at each mutant's first failing test: comparison, boolean, return, offset, operator swaps, integer-literal swaps including the literals 0 and 1, and the arithmetic swaps `-`/`+`, `*`/`//`, `*`/`-`, `**`/`*`, `%`/`//`. Comment and docstring text is not mutated. 59 were killed, 2 are crash-only and are not counted as kills (`operations[1]` and `operations[2]` in the contract loader raise IndexError at import time, so no test runs), and 8 survived. Seven of the survivors were real validator gaps (the first revision only reached request and policy bounds through the fuzzed durable stream): `MAX_MULTIPLIER` 10 to 11, the `_keys_are` and `_request_ok` `return False` to `return True`, the policy `base_delay_ms` and `multiplier` lower bounds 1 to 0, and the policy `and` to `or` on the multiplier and `max_delay_ms` conjuncts. Two rows were added: `test_every_policy_bound_edge_survives_a_restart_like_the_oracle` and `test_non_mapping_wrong_key_and_subclass_requests_and_policies_match_the_oracle`. Each of the 7 gap mutants was re-run by hand one at a time against the full file and now fails an oracle assertion (probe results are in the delivery artifacts). The 1 remaining survivor is behavior-equivalent: `ensure_ascii=True` to `False` (every digested string is ASCII by grammar). Post-fix totals were not re-run through the full sweep, so only the first-revision manifest (69 mutants: 59 killed, 2 crash-only, 8 survivors) is an exact tally.

These are author-run tallies and are not independently certified. A kill here includes a failure raised by an armed object's hook or a reference-oracle mismatch; the sweep does not split those from other assertion kills. The exact-key predicate mutant `type(k) is str` to `isinstance(k, str)` is not in the mutator's operator set; the non-mapping row replaces the key `op` and the policy key `multiplier` with a hook-free `str` subclass of the same text and requires the oracle's refusal.
