# T0323 Jobs/progress/implement

## Normative requirements

1. `server.jobs_progress` implements `ProgressError`, `report(request)` and `FAILURE_MAPPING` for data/contracts/progress.yaml (contract id `jobs-progress`). Production must not import or execute `tests.*`.
2. The request is checked first (`malformed_progress_request`), then the previous record's integrity (`corrupt_previous_record`), then the chain (`progress_conflict`): exact types only, dict keys checked as exact strs before any set comparison, job id and worker by ASCII fullmatch, total 1..2**53-1, done 0..total, now 0..2**53-1, previous null or an exact record whose shape, bounds, percent_bp and `pg1:` progress_id all recompute.
3. The chain requires the same job, worker and total, a previous that is not complete, done not below the previous done (equal is a heartbeat) and now not before the previous reported_at. The record carries percent_bp = floor(done * 10000 / total), previous_id and the `pg1:` progress_id over the contract preimage. Errors are fresh typed ProgressErrors with no cause or context; the request is never changed.
4. The T0322 red battery turns green by replacing only its two binding lines. Every row, probe and mutant stays unchanged.

- R1: `test_r2_production_imports_no_test_code`, `test_r3_public_surface`.
- R2, R3: `test_r4_every_fixture_request_agrees_with_the_reference` and `test_r5_production_and_reference_agree_on_hostile_variants` (every fixture request, and every field and nested field replaced by junk, dropped or given a sibling: same record or same failure class and code as the T0320 reference, request unchanged, no cause or context), `test_r5_hostile_subclasses_fail_closed_without_running_caller_code`, plus the full T0322 battery bound to `server.jobs_progress`.
- R4: `test_r1_red_battery_switch_is_exactly_the_two_binding_lines` (switched back, the file hashes to the T0322 battery as landed; the oracle import stays and carries one extra F401 noqa).

## Mutation check

82 single-token production mutants (comparison, boolean, return, offset, operator and integer-literal swaps) were run against the T0322 battery plus the runtime proof, stopping at each mutant's first failing test. 81 mutants are killed and none of them by a raw crash: a kill counts only when the first failure is a semantic outcome, which is an assertion (46) or a wrong typed refusal or detected caller-code run (35). Raw exceptions (TypeError, KeyError, AttributeError and the like) are tallied separately and there were 0 of them, so no mutant relies on a crash. The 1 survivors are stated as behavior-equivalent or non-code: `ensure_ascii` in the canonical encoder (every encoded string is ASCII by grammar).

## Red/green transition

On main, switching the two T0322 binding lines to `server.jobs_progress` fails at import because the module does not exist. With this change the same switch passes all T0322 tests.
