# T0326 Jobs/progress/integration/restart

## Normative requirements

1. `test_t0326_progress_integration_restart.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_progress` across process restarts. It adds no production code.
2. The durable value of the engine is persisted as canonical JSON under tmp_path (atomic replace), the production module is imported anew, and the stream continues. Sampled streams (12 restarted at every step, 10 with one random cut point, 3 with four steps each run in a real child interpreter) must give the same outcomes and the same durable value as an uninterrupted run and as the contract's reference implementation (`tests.test_t0320_progress_contract`), which is the differential oracle.
3. Replaying the same seeded stream after restarts (6 seeds) gives identical outcomes, and receipt identifiers are one per distinct receipt. Only the restart battery (T0353) mixes the real queue engine into its streams.
4. Forged or malformed inputs are refused with the oracle's failure class and code, leave their input structurally identical, and the next valid request still succeeds. They are built from the persisted value when it is a previous record or a queue state (fields dropped or retyped, digest not recomputed), and from the request fields otherwise (retry and dead-letter carry no previous record). Digest-recomputed forgeries are generated where a previous record exists (T0326, T0344) and not elsewhere. A truncated durable file is a host-level JSON error and never reaches the engine; the last good file stays usable.
5. Boundary rows pin the exact bounds a restarted engine can reach, with the oracle as the expected value.

## Mutation check

119 single-token mutants of `server/jobs_progress.py` were run against the first revision of this file alone, stopping at each mutant's first failing test: comparison, boolean, return, offset, operator swaps, integer-literal swaps including the literals 0 and 1, and the arithmetic swaps `-`/`+`, `*`/`//`, `*`/`-`, `**`/`*`, `%`/`//`. Comment and docstring text is not mutated. 83 were killed, 2 are crash-only and are not counted as kills (`operations[1]` and `operations[2]` in the contract loader raise IndexError at import time, so no test runs), and 34 survivor entries remained (30 distinct source edits; the sweep lists the `MAX_TOTAL` and `MAX_NOW` literal edits twice). The survivors were gaps in the request and previous-record validators, which the first revision only reached through fuzz-built streams: the `MAX_TOTAL` and `MAX_NOW` literal edges, the `and` to `or` swaps on the `op`, `job_id`, `worker`, `total`, `done` and `now` request conjuncts and on the `op`, `job_id`, `worker`, `total`, `previous_id` and `progress_id` previous-record conjuncts, the request validator `return False`, and the `total` lower bound 1 to 0. Rows added: `test_every_request_field_edge_survives_a_restart_like_the_oracle` (every request field at bound and out-of-bound values, one field at a time, plus missing keys), `test_forged_previous_records_with_a_recomputed_digest_survive_a_restart_like_the_oracle` (each previous field altered with the `progress_id` recomputed by the reference, so only the named defect is present), `test_a_zero_total_is_refused_like_the_oracle` and `test_trailing_newlines_in_identifiers_are_refused_like_the_oracle`. Each of the 30 distinct survivor edits was re-run by hand one at a time against the full file. 28 now fail an oracle assertion. One is behavior-equivalent: `ensure_ascii=True` to `False` (every digested string is ASCII by grammar). One is crash-only and is not counted as a kill: the `total` lower bound 1 to 0 survives every outcome assertion because a request with `total` 0 and `done` 0 reaches the percent computation and raises a foreign `ZeroDivisionError` instead of the typed refusal; `test_a_zero_total_is_refused_like_the_oracle` fails on that crash (tagged FOREIGN-EXCEPTION), and no semantic outcome difference exists for it. Post-fix totals were not re-run through the full sweep, so only the first-revision manifest (119 mutants: 83 killed, 2 crash-only, 34 survivor entries) is an exact tally.

A second sweep with an identity/None/membership operator set (`is not None` to `is not 0`, `is`/`is not`, `in`/`not in`, `None` to `0`, `True`/`False`, `fullmatch` to `match`, `type(` to `isinstance(`) was run on the pre-newline-row file: 52 mutants, 50 killed, 2 survivors: `ensure_ascii` (equivalent) and `fullmatch` to `match` in the grammar helper (the contract grammars end in `$`, which `match` lets through before a trailing newline). The newline rows were added for that survivor and the mutant was re-run by hand and now fails oracle assertions in three tests; the identity sweep was not repeated in full.

These are author-run tallies and are not independently certified. A kill here includes a failure raised by an armed object's hook or a reference-oracle mismatch; the sweep does not split those from other assertion kills, except where a crash is stated above. Forged previous records here are generated with a recomputed digest (the reference's own digest function), unlike the retry battery.
