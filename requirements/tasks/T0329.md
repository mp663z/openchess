# T0329 Jobs/dead letter/contract

## Normative requirements

1. data/contracts/dead_letter.yaml is the normative contract. tools/dead_letter_contract_lint.py pins it exactly and binds max_attempts, the job_id grammar, job_fields, the priority and payload bounds and the dead status to data/contracts/queue.yaml.
2. `bury {op, job, reason, now}` buries only a job that satisfies every queue job invariant and has status dead. Precedence: request shape (malformed_bury_request), then job integrity (corrupt_job), then dead status (job_not_dead).
3. The entry is exactly `{op, job_id, seq, priority, payload_digest, attempts, reason, buried_at, entry_id}`. payload_digest and entry_id use the exact pd1/dl1 preimages stated in the contract. The payload itself is never copied.
4. Every rejection is a fresh typed error with retryable false. No user code runs on hostile input, and the input is left unchanged.
5. Provisional, pending the owner's ruling on the permanent-dead attempt count: a permanent-failure job with attempts below max_attempts is refused as corrupt_job. A permanent-failure job at attempts == max_attempts buries normally.

## Recorded tension (owner batch)

- data/contracts/retry.yaml `semantics.permanent`: `a-permanent-failure-is-dead-at-any-attempt-count`.
- data/contracts/queue.yaml `semantics.dead_letter`: `a-claimable-job-whose-attempts-reached-max-attempts-becomes-dead-and-is-skipped`. The queue state invariant holds a dead job only at attempts == `state.max_attempts` (5).
- Coordinator ruling: no sibling changes now; fail closed (R5). The owner picks between (a) relaxing the queue invariant to attempts <= max_attempts when the last failure is permanent, or (b) recording permanent failures with attempts forced to max_attempts. This contract follows whichever is picked.

## Not covered (flagged)

Redrive of a cancelled job, and deduplication of repeated burials, need the T0293/T0302 semantics (parked).
