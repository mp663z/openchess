# T0334 Jobs/dead letter/fuzz/fault

## Normative requirements

1. `tests/test_t0334_dead_letter_fuzz_fault.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_dead_letter` under seeded fuzz and injected faults, with the contract's reference implementation (`tests.test_t0329_dead_letter_contract`) as the differential oracle. It adds no production code.
2. Every valid case is mutated at every reachable path with 52 hostile value factories (every gated type, boundary ints and strings, armed objects whose every hook fails the test, attribute bombs, lying dicts, cycles, 100000-deep and wide values), keys are dropped, added and replaced by non-str or armed keys, and oversize ints run under a lowered `sys.set_int_max_str_digits`. Production and the reference must return the same record or the same failure class and code, with `retryable` false and no cause or context.
3. A rejected call leaves its input structurally identical, checked with an iterative, hook-free snapshot. An accepted call leaves its request identical. Production never runs caller code: any hook of an armed object fails the test.
4. A fault injected at each sha256 step (the only post-validation step) propagates, leaves the input untouched, and the next call returns the baseline outcome; rejected requests never reach the digest step. Pathological shapes (100000 levels deep, 100000 wide, 5 MB strings, 100000-digit ints) are handled in bounded time without recursion.
5. Module-specific seeded streams are compared with the oracle step by step and checked against independent invariants (see the mapping).

## Requirement-to-test mapping

- Differential fuzz (oracle: the contract reference): `test_bases_are_valid_for_both_engines_and_agree`, `test_every_path_of_every_valid_case_rejects_or_matches_the_oracle_on_hostile_values`, `test_dropping_any_key_or_adding_any_key_matches_the_oracle`, `test_seeded_multi_mutation_fuzz_matches_the_oracle`, `test_every_field_boundary_value_matches_the_oracle`, `test_every_string_field_boundary_matches_the_oracle`, `test_key_order_never_changes_the_outcome_and_runs_are_deterministic`.
- Fault objects and hostile shapes (no caller code, always typed, input untouched): `test_armed_objects_at_every_path_never_run_caller_code_and_fail_typed`, `test_armed_and_nasty_keys_in_every_dict_are_refused_without_running_hooks`, `test_non_dict_and_hostile_top_level_requests_are_total`, `test_hundred_thousand_deep_and_wide_values_at_every_field_fail_typed_in_bounded_time`, `test_huge_ints_never_hit_a_str_conversion_under_a_lowered_interpreter_limit`.
- Injected faults: `test_a_fault_at_any_digest_step_leaves_input_untouched_and_the_next_call_is_clean`, `test_rejected_requests_never_reach_the_digest_step`.
- Module-specific streams and sweeps: `test_plain_str_subclass_keys_with_valid_names_and_values_are_refused_like_the_oracle`, `test_random_jobs_match_the_oracle_and_buried_entries_bind_their_payload`, `test_every_status_attempt_and_lease_combination_matches_the_oracle`, `test_exact_bit_and_digit_edges_match_the_oracle`, `test_payload_depth_and_digit_sweeps_match_the_oracle`.

## Mutation check

146 single-token mutants of `server/jobs_dead_letter.py` were run against the first revision of this file alone, stopping at each mutant's first failing test: comparison, boolean, return, offset, operator swaps, integer-literal swaps including the literals 0 and 1, and the arithmetic swaps `-`/`+`, `*`/`//`, `*`/`-`, `**`/`*`, `%`/`//`. Comment and docstring text is not mutated. 137 were killed, 2 are crash-only and are not counted as kills (`operations[1]` and `operations[2]` in the contract loader raise IndexError at import time, so no test runs), and 7 survived. The survivors were real gaps, not equivalents, except one: `attempts >= 1` to `>= 0` in the leased-job check (twice, same row), `attempts < 1` to `< 0` for done jobs, the matching `return False` to `True`, `MAX_BITS` 13288 to 13287, and `bit_length() > MAX_BITS` to `>=`. Two rows were added: `test_every_status_attempt_and_lease_combination_matches_the_oracle` (every status, attempts -1 to 7 and eight lease shapes against the oracle) and `test_exact_bit_and_digit_edges_match_the_oracle` (10**4000-1, 2**13287, 2**13288 and their negatives, bare, in a list and in a dict). Each of those six mutants was re-run by hand against these rows and fails an oracle or digit-bound assertion, giving 143 kills of 146. The one remaining survivor, `MAX_BITS` 13288 to 13289, is behavior-equivalent: any int of 13289 bits is at least 2**13288, which already has 4001 digits and is refused by the digit check.

These are author-run tallies and are not independently certified. A kill here includes a failure raised by an armed object's hook ("caller code ran"); the sweep does not split those from oracle-mismatch and assertion kills. The exact-key predicate mutant `type(k) is str` to `isinstance(k, str)` is not in the mutator's operator set, so `test_plain_str_subclass_keys_with_valid_names_and_values_are_refused_like_the_oracle` replaces every existing str key of the request and of every nested dict with a hook-free `class PlainStr(str)` of the same text and value and requires the oracle's refusal with the same class and code (pure outcome mismatch, not a hook fault).
