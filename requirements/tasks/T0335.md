# T0335 Jobs/dead letter/integration/restart

## Normative requirements

1. `test_t0335_dead_letter_integration_restart.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_dead_letter` across process restarts. It adds no production code.
2. The durable value of the engine is persisted as canonical JSON under tmp_path (atomic replace), the production file is executed anew in an isolated module namespace (the canonical module in sys.modules is never reloaded or mutated; `test_a_restart_never_touches_the_canonical_production_module` pins that), and the stream continues. Sampled streams (12 restarted at every step, 10 with one random cut point, 3 with four steps each run in a real child interpreter) must give the same outcomes and the same durable value as an uninterrupted run and as the contract's reference implementation (`tests.test_t0329_dead_letter_contract`), which is the differential oracle.
3. Replaying the same seeded stream after restarts (6 seeds) gives identical outcomes, and receipt identifiers are one per distinct receipt. Only the restart battery (T0353) mixes the real queue engine into its streams.
4. Forged or malformed inputs are refused with the oracle's failure class and code, leave their input structurally identical, and the next valid request still succeeds. They are built from the persisted value when it is a previous record or a queue state (fields dropped or retyped, digest not recomputed), and from the request fields otherwise (retry and dead-letter carry no previous record). Digest-recomputed forgeries are generated where a previous record exists (T0326, T0344) and not elsewhere. A truncated durable file is a host-level JSON error and never reaches the engine; the last good file stays usable.
5. Boundary rows pin the exact bounds a restarted engine can reach, with the oracle as the expected value.

## Mutation check

146 single-token mutants of `server/jobs_dead_letter.py` were run against this file, stopping at each mutant's first failing test: comparison, boolean, return, offset, operator swaps, integer-literal swaps including the literals 0 and 1, and the arithmetic swaps `-`/`+`, `*`/`//`, `*`/`-`, `**`/`*`, `%`/`//`. Comment and docstring text is not mutated. 143 were killed, 2 are crash-only and are not counted as kills (`operations[1]` and `operations[2]` in the contract loader raise IndexError at import time, so no test runs), and 1 survived: `MAX_BITS = 13288` to `13289`, behavior-equivalent because the digit cap (`MAX_DIGITS`) refuses first at that bit length, as documented for the T0332 runtime battery. The sweep ran while the file lacked its last revision (the hook-free subclass row and the isolated-namespace restart helper, added afterwards); those changes can only add kills, so no survivor was added by them, but the tallies describe the earlier file and no post-fix full re-sweep was run.

A second sweep with an identity/None/membership operator set (`is not None` to `is not 0`, `is`/`is not`, `in`/`not in`, `None` to `0`, `True`/`False`, `fullmatch` to `match`, `type(` to `isinstance(`) ran against the final file: 76 mutants, 74 killed, 2 survivors: in the digit-cap check the first `ok = False` is overwritten on the next line (behavior-equivalent), and the `ok = False` inside `except ValueError` is unreachable only at the default interpreter integer-to-string conversion limit (4300 digits), which is what the tests run under; it is classified crash-only, not equivalent, at non-default limits (with `sys.set_int_max_str_digits(640)` and a 10**999 payload that mutant accepts and then fails with a foreign ValueError in canonical serialization). The suite does not run at a lowered limit. Exact-type predicates: every `type(x) is T` site in the production file was swapped to `isinstance(x, T)` one at a time against the final file (9 sites, lines 69, 73, 80, 81, 126, 141, 143, 144, 159): 8 fail the file, each by an outcome mismatch with the oracle (for the `request["job"]` site the mismatch is the failure class, not an accepted result), and 1 is behavior-equivalent, the payload-key check `type(key) is not str` at line 126, because `_scalar_ok` on the same clause already refuses any str subclass; `test_payload_dict_keys_that_are_str_subclasses_are_refused_like_the_oracle` pins the refusal; `test_hook_free_subclasses_at_every_path_are_refused_like_the_oracle` replaces every value, container and dict key of sampled valid requests with a hook-free subclass of the same value and requires the oracle's outcome.

These are author-run tallies and are not independently certified. A kill here includes a failure raised by an armed object's hook or a reference-oracle mismatch; the sweep does not split those from other assertion kills.
