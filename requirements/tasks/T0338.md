# T0338 Jobs/limit/contract

## Normative requirements

1. data/contracts/limit.yaml is the normative contract. tools/limit_contract_lint.py pins it exactly and binds the limit key grammar to the worker grammar in data/contracts/queue.yaml.
2. `admit {op, key, cost, now, policy, previous}` decides one token-bucket admission. Precedence: request shape (malformed_limit_request), then policy (invalid_limit_policy), then cost within capacity (malformed_limit_request), then previous-record integrity (corrupt_previous_bucket), then chain consistency (limit_conflict), then clock (clock_overflow). First failure wins.
3. Refill is exact integer arithmetic: gained = floor((now - updated_at) / refill_ms). Below capacity the partial refill is kept (updated_at advances by gained * refill_ms). At capacity, tokens = capacity and updated_at = now. Admit when refilled >= cost; deny otherwise with retry_after_ms = (cost - refilled) * refill_ms - (now - updated_at).
4. The record is exactly `{op, key, capacity, refill_ms, cost, decision, tokens, updated_at, retry_after_ms, previous_id, limit_id}`. limit_id uses the exact lm1 preimage stated in the contract. previous_id links the chain.
5. Every rejection is a fresh typed error with retryable false. No user code runs on hostile input, and the input is left unchanged.

## Fail-closed readings (spec silent; stated in the contract rule text)

- cap: at capacity no partial refill is banked.
- cost: a cost above capacity can never be admitted, so it is malformed_limit_request, never a deny.
- identity: key, capacity and refill_ms must equal the previous record; a policy change starts a fresh bucket (previous = null), it is never migrated.
- clock: now equal to the previous updated_at is accepted; earlier is limit_conflict.
- overflow: a deny whose now + retry_after_ms would pass 2^53-1 is clock_overflow, never clamped. It is measured from now, not from the carried updated_at.
- integrity: a previous record must satisfy the decision invariants (cost <= capacity and decision in {admit, deny}; admit: tokens <= capacity - cost, retry null; deny: tokens < cost, 0 < retry <= (cost - tokens) * refill_ms, updated_at + retry within the clock) and its limit_id must recompute.

## Not covered (flagged)

Idempotent replay of the same admit, and fairness across keys, need the T0293/T0302 semantics (parked).
