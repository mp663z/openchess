# T0339 Jobs/limit/fixture

## Requirements

1. tests/fixtures/limit/cases.json is a closed fixture for the T0338 jobs-limit contract: 4 happy, 14 boundary, 51 malformed and 5 rollback rows, one per line. Pinned bucket records come from the T0338 reference admit and chain through previous: each linked step's previous is exactly the prior pinned record.
2. Every row is pinned by name, a semantic manifest, a per-row edge check and a canonical sha256. Substituted, swapped, dropped, duplicated, retyped or second-defect rows fail the semantic closure on its own, without the digest table. Every pinned limit_id equals the hand-built contract preimage of its record.
3. Happy and boundary rows cover a fresh full bucket, drain then deny, a banked partial refill (updated_at advances by whole refills), the cap that drops a partial token (updated_at moves to now), cost equal to capacity, capacity 1 and 1000000, refill_ms 86400000, now 2**53-1, equal now, a floored gain (retry exactly 1), retry counting the elapsed partial, deny edges where now + retry_after_ms is exactly 2**53-1 (with base equal to now and with base trailing now), a 64-character key and a policy change starting a fresh chain.
4. Malformed rows cover every failure class (malformed_limit_request, invalid_limit_policy, corrupt_previous_bucket, limit_conflict, clock_overflow), including:
   - same-arity renamed-key rows on the request, the policy and the previous record;
   - cost, now, capacity and refill_ms one past each bound and at each floor, and cost above capacity (malformed, never a deny);
   - tampered previous records (tokens edited, limit_id edited);
   - self-consistent forged previous records, each with a recomputed limit_id: op, decision 'hold' on a deny record, admit with retry, admit tokens past cost, deny retry past its window, deny retry overflowing 2**53-1, cost past capacity, cost 0, tokens -1, key grammar, and capacity, refill_ms and updated_at past bound;
   - key, capacity and refill_ms mismatches and a clock regression;
   - clock overflow one past the edge, after a banked partial refill (measured from now, not updated_at), and well past it.
   Each row has a single-locus minimal repair that is decided. Rejections are fresh typed errors with retryable false, and the input stays type-exactly unchanged. Validation order is request shape, policy, cost within capacity, previous-record integrity, chain, then clock overflow.
5. Rollback rows cover every failure class. The rejected request stays type-exactly identical, and the valid follow-up is decided as pinned.
6. Hostile-type rows are derived from every accepted request (93 requests; 54 variants for a request with no previous, 126 to 134 for a chained one):
   - hostile containers (dict-subclass, lying dict, list-subclass) on the request, the policy and the previous record;
   - str-subclass keys in 3 forms on every request, policy and previous-record field;
   - str-subclass, eq-raises, repr-raises and nested values on the str fields, and int-subclass, bool, float and float-subclass values on the int fields, of the request, the policy and the previous record (including a non-null previous_id and retry_after_ms).
   Each must fail typed, run no user code and leave the input unchanged.
7. Every one of the 42 T0338 reference mutants turns this fixture red through executed rows. So do 16 extra fixture-level mutants covering the op, key-grammar (including fullmatch weakened to match), policy/previous type, cost/now/capacity/refill floors, previous-record op, the updated_at bound, the previous deny overflow check, both ends of the previous deny retry window, the previous refill_ms floor, and the capacity cap at exact equality. The 5 T0338 equivalent edits keep it green.
