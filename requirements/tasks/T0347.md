# T0347 Jobs/restart/contract

## Normative requirements

1. data/contracts/restart.yaml is the normative contract. tools/restart_contract_lint.py pins it exactly and binds the worker grammar, the state_id grammar, max_jobs and max_attempts to data/contracts/queue.yaml.
2. `restart(state, {op, worker, now})` validates the request shape first (malformed_restart_request), then every queue state and job invariant (corrupt_queue). First failure wins.
3. Every job leased by the worker with now strictly before its lease expiry returns to ready with no lease owner or expiry. Nothing else changes: other workers' leases, expired leases, ready/done/dead jobs, next_seq, job order, ids, seqs, priorities, payloads and attempts all stay as they were.
4. The receipt is exactly `{op, worker, restarted_at, released, prior_state_id, state_id, restart_id}`. released lists job ids in seq order and may be empty. prior_state_id and state_id are the queue contract's own qs1 digests (non-ASCII kept). restart_id uses the exact rst1 preimage stated in the contract.
5. The new state is committed last, in place. A rejected restart leaves the state and the request bit-identical. Every rejection is a fresh typed error with retryable false, and no user code runs on hostile input.
6. Restarting twice releases nothing the second time, and the state_id is unchanged.

## Fail-closed readings (spec silent; stated in the contract rule text)

- attempts: kept, as on a queue nack. A restart never refunds or charges an attempt.
- expired: a lease at or past expiry is left untouched, because the queue claim can already reclaim it.
- dead: a released job at max_attempts returns to ready. Dead-marking stays with the queue claim.
- integrity: a state that breaks any queue invariant is corrupt_queue and is never repaired.

## Not covered (flagged)

Fencing a restart against a stale worker epoch, and cancelling jobs held by a restarted worker, need the T0293/T0302 semantics (parked).
