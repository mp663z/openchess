# T0353 Jobs/restart/integration/restart

## Normative requirements

1. `test_t0353_restart_integration_restart.py` proves happy, boundary, malformed and rollback behavior of the production `server.jobs_restart` across process restarts. It adds no production code.
2. The durable value of the engine is persisted as canonical JSON under tmp_path (atomic replace), the production module is imported anew, and the stream continues. Sampled streams (12 restarted at every step, 10 with one random cut point, 3 with four steps each run in a real child interpreter) must give the same outcomes and the same durable value as an uninterrupted run and as the contract's reference implementation (`tests.test_t0347_restart_contract`), which is the differential oracle.
3. Replaying the same seeded stream after restarts (6 seeds) gives identical outcomes, and receipt identifiers are one per distinct receipt. Only the restart battery (T0353) mixes the real queue engine into its streams.
4. Forged or malformed inputs are refused with the oracle's failure class and code, leave their input structurally identical, and the next valid request still succeeds. They are built from the persisted value when it is a previous record or a queue state (fields dropped or retyped, digest not recomputed), and from the request fields otherwise (retry and dead-letter carry no previous record). Digest-recomputed forgeries are generated where a previous record exists (T0326, T0344) and not elsewhere. A truncated durable file is a host-level JSON error and never reaches the engine; the last good file stays usable.
5. Boundary rows pin the exact bounds a restarted engine can reach, with the oracle as the expected value.

## Mutation check

149 unique single-token mutants of `server/jobs_restart.py` (sha256 5d1559f8, unchanged throughout) were run against the 43-case battery as of test-file hash 775000be, stopping at each mutant's first failing test: comparison, boolean, return, offset, operator swaps, integer-literal swaps including the literals 0 and 1, and the arithmetic swaps `-`/`+`, `*`/`//`, `*`/`-`, `**`/`*`, `%`/`//`. Comment and docstring text is not mutated. 126 were semantic kills (0 syntax-only), 17 are crash-only and are not counted as kills (runtime exceptions from mutant incompatibility - TypeError on None/int comparisons and unsupported operands, KeyError, IndexError - not behavioral assertions), and 6 survived. Independent owner probes on the pinned source characterized all 6: one (L54, `MAX_BITS` 13288 to 13289) is behavior-equivalent, because every integer with bit length 13289 is at least 2^13288 and therefore has 4001 digits, which the `MAX_DIGITS` 4000 check rejects - the digit guard rejects exactly the range the relaxed pre-screen admits (boundary cases 2^13288, 2^13289-1, negatives, 10^4000 +/-1 confirmed). The other five were real coverage gaps, closed by named rows added to this battery: L113 (UTF-8 validation bypass on lone surrogates) by `test_payloads_with_lone_surrogate_strings_are_refused`, L135 (non-str scalar dict keys) by `test_payloads_with_non_str_scalar_keys_are_refused`, L203 (non-ASCII or '+' payload content changing the queue-state id) by `test_state_id_pinned_for_non_ascii_and_plus_payload_state`, and L74/L207 (receipt canonical bytes and restart-id encoding) by `test_restart_id_pinned_for_non_ascii_and_plus_receipt_fields`. Reachability note: every public-path receipt field is ASCII-grammar-constrained (op constant, worker grammar `^[A-Za-z0-9._:-]{1,64}$`, restarted_at int, released job ids ASCII, qs1 hex state ids), so no in-domain receipt carries non-ASCII or '+'; L74/L207 are helper-level gaps closed by synthetic-record pins, while L113/L135/L203 are reachable in-domain through enqueue payloads. The qs1 and rst1 pin rows assert the digest helpers' canonical bytes directly on synthetic states and records (the pinned states are not valid public states); they prove the helpers' bytes, not public state validation, while the two refusal rows exercise the public restart path. After strengthening (47 cases, test-file hash deeac902), each of the five single mutants was re-applied one at a time and killed (1 failed, 46 passed each, no collateral failures; owner-verified). The main-sweep tallies above describe the 775000be battery, where the gaps were found; the extra sweep below describes the final deeac902 battery directly.

A second sweep with an identity/None/membership operator set (`is not None` to `is not 0`, `is`/`is not`, `in`/`not in`, `None` to `0`, `True`/`False`, `fullmatch` to `match`, `type(` to `isinstance(`) ran against the final 47-case battery (test-file hash deeac902): 82 mutant records, 50 semantic kills, 11 syntax-only kills (the harness records a mutant that does not parse as killed; a SyntaxError is not a behavioral kill), 19 crash-only, and 2 surviving equivalents - counts corrected with row 43 reclassified from the corrupt survivor record to killed, the immutable raw row retained. Across both sweeps 231 records were run; by the (line, original, mutant) union key they are 203 unique mutants with 28 overlap, the extra sweep contributing 54 marginal new mutants (owner-computed union; the two sweeps ran different batteries, 775000be and deeac902, so records are not merged by line alone). L102 (`ok = False` to `ok = True` in the int branch of `_scalar_ok`) is behavior-equivalent: the try body reassigns `ok` on every integer path, so the initializer is a dead store. L106 (`ok = False` to `ok = True` in the `except ValueError` branch) is equivalent only under the deployment-default int-to-str digit limit of 4300: any int large enough to trip that limit exceeds `MAX_BITS` and is rejected at the bit guard first, so the branch is unreachable in effect; with a lower configured limit (below 4001 digits) the mutant could be non-equivalent, so this equivalence is conditional on the deployment limit. L136 (`return False` to `return True` in the dict-key guard) is not a genuine survivor: during the run the author accidentally restored the production file mid-cycle (01:15:24), and the battery's per-case module re-reads mixed mutant and original content, producing one corrupt row. Two independent clean reruns (the owner's and a full isolated re-run of all 36 sweep rows in the interference window) killed L136 and reproduced the other 35 classifications exactly; the incident closure is this bounded observation - the classification difference is confined to row 43 by reproduction - and is not a proof that no other execution interference occurred. Exact-type predicates: the sweep's `type(` to `isinstance(` swap covered all 10 `type(` call sites (the 8 exact-type predicate sites at lines 78, 82, 89, 90, 135, 150, 166, 187, plus the two bare `type()` calls at 96 and 128); every one is crash-only because the swap produces a one-argument `isinstance` call, so the swap itself carries no behavioral signal. Subclass acceptance is instead pinned behaviorally: `test_hook_free_subclasses_at_every_path_are_refused_like_the_oracle` replaces every value, container and dict key of sampled valid requests with a hook-free subclass of the same value and requires the oracle's outcome.

The receipt-identifier row checks `restart_id` only: it is content-addressed on the full receipt record, so distinct receipts in a stream receive distinct identifiers by construction (a digest collision aside, which the test does not claim to exclude). `state_id` is content-addressed on the post-restart queue state and legitimately recurs across distinct receipts, so it is not in the identifier set. Exact-head reviewer E accepted this narrowing at the prior head on the content-addressing recurrence argument above (concrete recurrence evidence, not an inference from green tests); reviewer D has not reported and dual review of the current head is pending.

These are author-run tallies and are not independently certified. A kill here includes a failure raised by an armed object's hook or a reference-oracle mismatch; the sweep does not split those from other assertion kills.
