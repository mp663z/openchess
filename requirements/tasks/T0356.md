# T0356 Privacy/sensitive flag/contract

This task pins the per-collection sensitive flag that gates cloud-model
egress, following product-report-v5 section 445: "Cloud-model access is
collection-scoped and off for sensitive preparation by default."

- `data/contracts/sensitive_flag.yaml` is the contract, id `privacy-sensitive-flag`.
- `tools/sensitive_flag_contract_lint.py` is the exact structured lint. It
  uses the closed envelope, closed failures and closed errors.
- `tests/test_t0356_sensitive_flag_contract.py` holds the lint and its
  mutation rows, plus a reference engine derived from the YAML with
  happy, boundary, malformed and rollback rows.

## Fail-closed readings where the spec is silent

1. **Default.** The spec does not say which collections count as
   "preparation". An unknown or unset flag reads sensitive, so cloud is off
   by default for every collection. Local is always allowed.
2. **Egress.** Cloud is allowed only when the flag is exactly `false`. The
   verdict is read from current state at send time and is never cached.
3. **Lowering.** Going from true to false needs a user approval token,
   `apv1:` plus sha256 over `collection_id|expected_revision|false`. It is
   bound to one collection and one revision. Its source is the user-approval
   surface only, never model output or imported content.
4. **Raising.** Going from false to true needs no approval and applies
   before the next verdict.
5. **Concurrency.** Compare-and-set on `expected_revision`. A mismatch maps
   to `conflict`.
6. **Rollback.** Rollback restores the prior value under the same rules. So
   rolling back a raise is a lowering and needs approval. Rollback at
   revision 0 restores the default (true), which is a no-op.
7. **Same value.** A same-value set is a no-op and the revision stays
   unchanged.

## Deferred (flagged, not specified here)

Retry and idempotency-key semantics (T0293) and cancel semantics (T0302)
are out of scope (`role.not_scope`). Redaction, BYOM terms, local model
choice and delete belong to their own contracts (T0392, T0383, T0374, T0401).

## Errors

The failure classes are malformed_flag_request, unknown_collection,
stale_revision, approval_missing and egress_blocked. They map to
malformed_request, unknown_collection, conflict, approval_required and
cloud_off. `internal` is the only retryable code.

## Hostile rows

The battery covers the three entry points: verdict, transition and
rollback. It uses these request forms:

- a dict subclass, a list and a str as the request;
- str, list and dict subclasses for every value;
- extra keys in 3 forms: plain, `__eq__` raises, and `__hash__` collides;
- a missing key for each field;
- a bytes key;
- int or None for the bool field;
- bool, negative, float or str for the revision;
- grammar edges for the id (63, 64 and 65 hex characters, uppercase,
  trailing newline) and for the destination.

Each row pins `malformed_request`, an empty hostile-call log, the flag
state unchanged and the request unchanged (keys by identity).

## Kill check

This list is prose only. It uses one-line mutants of the reference engine
with bytecode caching off.

Killed (14): default_open, no_approval_check, no_cas, bool_as_int,
str_sub_ok, dict_sub_ok, key_type_skip, rev_bool_ok, rev_neg_ok,
approval_unbound, rollback_default_false, noop_bumps, dest_any,
grammar_search.

Equivalent (1): truthy_egress (`bool(state[0])` in place of
`state[0] is not False`). Stored state is always an exact bool because
transitions reject non-bool values, so the mutant cannot be told apart.
