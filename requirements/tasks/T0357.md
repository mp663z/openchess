# T0357 Privacy/sensitive flag/fixture

## Requirements

1. `tests/fixtures/sensitive_flag/cases.json` is a closed fixture for the T0356 sensitive-flag contract: 8 happy, 14 boundary, 52 malformed and 8 rollback rows, one per line. Each row is a scenario replayed in order on one store. Pinned results come from the T0356 reference `FlagStore`.
2. Every row is pinned by name manifest, a per-row sha256 digest and a replay checked against the pinned results. A substituted, swapped, dropped, duplicated or retyped row fails the closure, with or without the digest table. A silent retype that keeps replay green is caught by the digest table alone.
3. Malformed rows cover all seven failure classes. Each has a single-locus minimal repair that commits. Rejections are typed `FlagError` values with the pinned code, and the request and the store stay unchanged.
4. Boundary rows pin the revision edge (2**63-2 commits to 2**63-1, a change at 2**63-1 is `revision_exhausted`, a same-value set there is a no-op), the check order at the edge (approval and empty history come before exhaustion), the approval binding to collection and revision, and the sha256 known answer for `col1:a...a|0|false`. The `seed` step exists only to reach the revision edge.
5. Rollback rows cover every failure class: the rejected request leaves the state unchanged and the valid follow-up commits as pinned.
6. Hostile-type variants are derived from every accepted verdict, transition and rollback request: dict and list containers, str-subclass, eq-raises and hash-colliding keys, dropped, extra and int keys, str-subclass, eq-raises, repr-raises and bytes values, and bool, int-subclass, float and str for the bool and int fields. Each fails `malformed_flag_request`, runs no user code and leaves the input and the store unchanged.
7. 22 reference mutants (approval ignored or unbound, default open, re-register resets, no compare-and-set, same-value bumps, history not pushed, rollback pushes or skips approval, saturation and wrap, unknown reads open, cached verdict, subclass and bool leniency, precedence swaps) each turn the fixture red by a pinned mismatch or a failed hostile variant. 15 fixture edits are each caught by the closure, in both digest and closure-only modes.

## Test mapping

- R1, R2: `test_fixture_structure_and_closure`, `test_param_ids_equal_manifest_names`, `test_fixture_edits_are_detected`, `test_digest_table_detects_a_silent_retype`.
- R3: `test_malformed_rejects_typed_and_leaves_inputs_unchanged`, `test_malformed_minimal_repair_succeeds`, `test_rejections_are_fresh_typed_errors`, `test_failure_class_and_enum_coverage`.
- R4: `test_pinned_scenarios`, `test_approval_known_answer_row`, `test_validation_precedence_rows`.
- R5: `test_rollback_rows`, `test_walk_back_rows_never_reapply_an_undone_value`.

- R7: `test_reference_is_green`, `test_reference_mutants_turn_the_fixture_red`.
