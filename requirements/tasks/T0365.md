# T0365 Privacy/cloud-off/contract

## Normative requirements

1. `data/contracts/cloud_off.yaml` (`privacy-cloud-off`, `/privacy/cloud-off/v1`) is a closed contract: exact envelope, closed failure model and closed error enum, pinned field by field by `tools/cloud_off_contract_lint.py`. It owns one install-wide cloud mode and the install-level egress verdict. It does not own collection flag state (T0356 `sensitive_flag.yaml`), redaction, BYOM provider terms, the hosted-BYOM payload schema, local-model choice, delete, or retry idempotency.
2. Record: `install_id` (`^ins1:[0-9a-f]{64}$`), `cloud_mode` (exact str `off` or `on`), `revision` (exact int 0 to 2^63-1, never bool, derived by the switch). The switch holds no history.
3. Default: an unknown or unset install reads `off`. Registering a known install is a no-op; it never resets mode or revision.
4. Egress: `local` is always allowed, whatever the mode and whatever the collection. `cloud` is allowed only when the mode is exactly `on` AND the collection's T0356 flag reads exactly false. An unknown collection reads sensitive. The mode is checked before the flag, so a flag can never open cloud while the switch is off. Both refusals map to the one user-facing code `cloud_off` (`cloud_mode_off`, `collection_sensitive`). The verdict is read from current state at send time, one verdict per send, never cached.
5. Transitions: `on -> off` needs no approval and applies before the next verdict (kill switch; a well-formed opt-in on a turn-off is ignored). `off -> on` needs an opt-in `^opt1:[0-9a-f]{64}$` equal to sha256 over install id, expected revision and target `on`, from the user settings surface only. Setting the current mode is a no-op with the revision unchanged, even without an opt-in. Compare-and-set on `expected_revision`. A transition at revision 2^63-1 fails typed, never saturates or wraps.
6. Precedence: malformed request (every grammar and exact-type check, including str/dict/list/int subclasses, non-str keys, a real key replaced by a str subclass, `__eq__`-raising and hash-colliding extra keys, and a malformed opt-in) before unknown install, before stale revision, before the same-value no-op, before opt-in missing, before revision exhausted.
7. Rollback: there is no history operation. A rejected transition or verdict leaves switch state, flag state and the input unchanged (rolled back whole). Undoing `on` is a turn-off; undoing `off` is a fresh opt-in, and an old opt-in can never be replayed because it is bound to its revision.
8. Errors: `malformed_request`, `unknown_install`, `conflict`, `approval_required`, `cloud_off`, `revision_exhausted`, `internal`; only `internal` is retryable. Every raised error is fresh (`__cause__` is None).

## Fail-closed readings (spec silent; owner batch)

Sources: ADR-0004 `external_providers` (hosted-byom `opt_in: true`, `default: off`; invariants `hosted-byom-opt-in-only`, `full-loop-offline-on-desktop`) and product report v5 section 12 ("Cloud-model access is collection-scoped and off for sensitive preparation by default").

- The cloud mode is install-wide and defaults to off; unknown installs read off (R3).
- Cloud egress needs BOTH the install switch on and the collection flag exactly false; the switch is checked first (R4).
- Local egress is never gated, so the full loop stays offline-capable (R4).
- Turning cloud on needs a bound user opt-in; turning it off never needs approval (R5).
- No rollback/history operation: reverting an "off" would re-open cloud, so it must be a fresh opt-in (R7).
- An opt-in present on a turn-off is ignored if well-formed, malformed if not (R5, R6).

Deferred and flagged, not in this contract: retry idempotency and cancel (T0293/T0302), the hosted-BYOM payload schema and `never_receives` list, provider terms (T0383), redaction (T0392), local model (T0374), delete (T0401).

- R1: `test_contract_lints_clean`, `test_error_model_is_closed_and_consistent`, `test_linked_documents_exist_and_agree`, `test_lint_rejects_mutation[*]`.
- R2-R3: `test_register_defaults_off`, `test_reregister_never_resets_mode_or_revision`, `test_register_hostile_ids`.
- R4: `test_default_blocks_cloud_even_for_an_open_collection`, `test_local_is_always_allowed`, `test_turn_on_with_bound_opt_in_opens_cloud_for_an_open_collection`, `test_cloud_on_still_blocks_a_sensitive_or_unknown_collection`, `test_switch_is_checked_before_the_flag`, `test_unknown_install_reads_off_even_when_another_install_is_on`, `test_verdict_is_read_at_send_time_never_cached`.
- R5: `test_turn_off_needs_no_opt_in_and_applies_before_the_next_verdict`, `test_well_formed_opt_in_on_turn_off_is_ignored`, `test_same_value_is_noop`, `test_turn_on_without_a_bound_opt_in_is_refused`, `test_an_opt_in_is_bound_to_its_install_both_ways`, `test_an_old_opt_in_is_never_reusable`, `test_stale_revision_is_conflict`, `test_stale_revision_edges_after_transitions`, saturation tests at max and max-1.
- R6: `test_hostile_request_fails_closed_typed[*]` (each row pins the typed failure, an empty hostile-call log, switch and flag state unchanged, and the input unchanged by key identity, value type and value), `test_malformed_opt_in_precedes_unknown_and_stale`, `test_unknown_precedes_stale_and_stale_precedes_opt_in`, `test_unknown_install_on_transition`, `test_unapproved_turn_on_at_max_revision_is_opt_in_missing`, `test_same_value_at_max_revision_is_a_noop`.
- R7: `test_undoing_on_is_turn_off_and_undoing_off_needs_a_fresh_opt_in`, `test_rejected_transition_leaves_everything_unchanged`, `test_refused_verdict_changes_nothing`.
- Discrimination: `MUTANTS` is an executable table of 36 one-edit mutants of the reference engine; `test_source_mutant_is_killed` runs each on a copy of the battery (kill-check section stripped, no `-k`) and requires rc 1 with all 193 tests run; `test_identity_mutant_is_green` requires rc 0 with exactly 193 passed. No equivalent mutant was found.

The reference engine composes the T0356 reference `FlagStore` (imported, not re-implemented), so the collection-flag semantics stay owned by T0356.
