# T0374 Privacy/local-model/contract

## Normative requirements

1. `data/contracts/local_model.yaml` (`privacy-local-model`, `/privacy/local-model/v1`) is a closed contract: exact envelope, closed failure model and closed error enum, pinned field by field by `tools/local_model_contract_lint.py`. It owns one install-wide local large-model mode, the local inference verdict (tier, host, destination) and the reference-claim status. It does not own the cloud mode or collection flags (T0365, T0356), BYOM provider terms, redaction, model weights download, chess evidence, delete, or retry idempotency.
2. Record: `install_id` (`^ins1:[0-9a-f]{64}$`), `large_model` (exact str `off` or `on`), `revision` (exact int 0 to 2^63-1, never bool, derived by the install), `reference_claims` (exact str `valid` or `suspended`, derived, never caller-set). The install holds no history.
3. Default: an unknown or unset install reads `off` with claims `valid`. Registering a known install is a no-op; it never resets mode, revision or claims.
4. Verdict: the `small` tier is always available on the `desktop` host with no opt-in. The `large` tier is available only while the mode is exactly `on` and only on `desktop`. `web` and `server` never run a model of either tier. Any non-local destination is refused, whatever the mode and whatever the cloud mode. The verdict never reads or changes the cloud mode, is read from current state at invocation time, and is never cached. Every allowed verdict reports the current `reference_claims`.
5. Claims: turning the large model on suspends the reference-machine p95 claims; turning it off restores them.
6. Transitions: `on -> off` needs no approval and applies before the next verdict (a well-formed opt-in on a turn-off is ignored). `off -> on` needs an opt-in `^lmo1:[0-9a-f]{64}$` equal to sha256 over install id, expected revision and target `large-on` (matching `local_model.yaml` `opt_in.binding`), from the user settings surface only. The distinct target keeps a T0365 cloud opt-in (target `on`) from ever opening the local large model. The preimage is byte-exact: the UTF-8 bytes of `install_id` verbatim, `|`, `expected_revision` as ASCII decimal (no sign, no leading zeros, zero is `0`), `|`, `large-on`, with no leading or trailing separator (for example `ins1:<64-lowercase-hex>|0|large-on`); the token is `lmo1:` plus the 64 lowercase hex digits of its sha256. `local_model.yaml` `opt_in.preimage` and `opt_in.digest` state the same, pinned by the lint. Setting the current mode is a no-op with the revision unchanged, even without an opt-in. Compare-and-set on `expected_revision`. A transition at revision 2^63-1 fails typed, never saturates or wraps.
7. Precedence on transitions: malformed request (every grammar and exact-type check, including str/dict/list/int subclasses, non-str keys, a real key replaced by a str subclass, a same-arity renamed key, `__eq__`-raising and hash-colliding extra keys, and a malformed opt-in) before unknown install, before stale revision, before the same-value no-op, before opt-in missing, before revision exhausted. Precedence on verdicts: malformed, then `egress_requested`, then `host_not_desktop`, then `large_model_off`.
8. Rollback: there is no history operation. A rejected transition or verdict leaves model state and the input unchanged (rolled back whole). Undoing `on` is a turn-off; undoing `off` is a fresh opt-in, and an old opt-in can never be replayed because it is bound to its revision.
9. Errors: `malformed_request`, `unknown_install`, `conflict`, `approval_required`, `local_only`, `host_refused`, `model_unavailable`, `revision_exhausted`, `internal`; only `internal` is retryable. Every raised error is fresh (`__cause__` is None).

## Fail-closed readings (spec silent; owner batch)

Sources: ADR-0004 `external_providers.local-large-llm` (`mode: local`, `opt_in: true`, `default: off`, payload none/local only, `suspends_reference_claims: true`) and `operations.model-inference: desktop`; ADR-0005 `capabilities.models.compute_owner: desktop`; product report v5 section 14.

- The small tier is always on, but only on desktop (R4).
- The large tier runs only when the mode is exactly `on`, and only on desktop; unknown installs read off (R3, R4).
- A local model never egresses: any non-local destination is refused regardless of the cloud mode, and the verdict works with cloud off (R4).
- Reference claims are suspended exactly while the large model is on (R5).
- No rollback/history operation: undoing `off` must be a fresh opt-in (R8).
- An opt-in present on a turn-off is ignored if well-formed, malformed if not (R6, R7).
- At revision 2^63-1 even the turn-off is refused with `revision_exhausted`; the revision never saturates or wraps (R6).

Deferred and flagged, not in this contract: model weights download and its integrity check, retry idempotency and cancel (T0293/T0302), BYOM terms (T0383), redaction (T0392), delete (T0401).

- R7: `test_hostile_request_fails_closed_typed[*]` (each row pins the typed failure, an empty hostile-call log, model state unchanged, and the input unchanged by key identity, value type and value), `test_precedence_egress_then_host_then_mode`, `test_malformed_opt_in_precedes_unknown_and_stale`, `test_unknown_precedes_stale_and_stale_precedes_opt_in`, `test_unknown_install_on_transition`, `test_unapproved_turn_on_at_max_revision_is_opt_in_missing`, `test_same_value_at_max_revision_is_a_noop`.

- Discrimination: `MUTANTS` is an executable table of 50 one-edit mutants (including `opt_sep`, `opt_trailing_sep`, `opt_field_order`, `opt_rev_padded`, `opt_encoding` on the preimage) of the reference engine; `test_source_mutant_is_killed` runs each on a copy of the battery (kill-check section stripped, no `-k`) and requires rc 1 with all 321 tests run; `test_identity_mutant_is_green` requires rc 0 with exactly 321 passed. `EQUIVALENT` (run green by `test_equivalent_edit_stays_green`): `state[0] != "on"` -> `state[0] == "off"` in `reads_off`, since the stored mode is only ever exact `off` or `on`.
