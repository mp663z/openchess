# T0375 Privacy/local model/fixture

## Requirements

1. `tests/fixtures/local_model/cases.json` is a closed fixture for the T0374 local-model contract: 8 happy, 18 boundary, 105 malformed and 9 rollback rows. Each row is a scenario replayed in order on one fresh world, the T0374 reference `LocalModels`. Pinned results come from that reference.
2. Every row is pinned by a name manifest, a per-row sha256 digest and a replay checked against the pinned results. A substituted, swapped, dropped, duplicated or retyped row fails the closure, with or without the digest table. A silent retype that keeps replay green is caught by the digest table alone.
3. Malformed rows cover all eight failure classes, each with a minimal repair that succeeds. Rejections are typed `ModelError` values with the pinned code (`local_only`, `host_refused`, `model_unavailable`, `approval_required`, `conflict`). The request and the model state stay unchanged.
4. Boundary rows pin the revision edge (MAX-1 commits to MAX, a change at MAX is `revision_exhausted` for turn on and for the off switch, a same-value set at MAX is a no-op), the check order (malformed, unknown install, stale, same-value no-op, opt-in, exhaustion), the verdict order (malformed, egress, host, large-model mode), the opt-in binding to install and revision, the sha256 known answer for `ins1:<1*64>|0|large-on`, the off switch needing no opt-in, a verdict read at invocation time, and an unknown install reading large off.
5. Product rules are pinned: the small tier is available in both modes on desktop, the large tier only while on and only on desktop, web and server never run a model, any non-local destination is refused whatever the mode, and reference claims read `suspended` exactly while the large model is on, on every record and verdict.
6. Opt-in preimage variants (target `on`, `large-off`, colon separator, trailing separator, leading zero, plus sign, uppercase target, utf-16) are each `opt_in_missing`. Grammar violations (prefix, length, case, type, trailing newline) are `malformed_model_request`, including on a turn off. Tier, host and destination values outside their closed sets are malformed, and malformed beats egress.
7. Rollback rows cover every failure class: the rejected request leaves the model state unchanged and the follow-up behaves as pinned.
8. Hostile-type variants are derived from every accepted verdict and transition request (dict and list containers, str-subclass, eq-raises and hash-colliding keys, dropped, extra and int keys, str-subclass, eq-raises, repr-raises, bytes and empty values, bool, int-subclass and float revisions). Each fails `malformed_model_request`, runs no user code and leaves the input and the state unchanged.
9. 34 reference mutants (default on, re-register reset, opt-in ignored or unbound, off switch needing opt-in, no compare-and-set, same-value bumps or needing opt-in, saturation and wrap, exhaustion order, unknown reads on, off not applied, every verdict-order swap, egress or web or server allowed, small needing opt-in, large always available, claims wrong, cached verdict, tier unvalidated, subclass and bool leniency) each turn the fixture red by a pinned mismatch or a failed hostile variant. 16 fixture edits are each caught by the closure, in both digest and closure-only modes.
