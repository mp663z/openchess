# T0383 Privacy/BYOM/contract

## Normative requirements

1. `data/contracts/byom.yaml` (`privacy-byom`, `/privacy/byom/v1`) is a closed contract: exact envelope, closed failure model and closed error enum, pinned field by field by `tools/byom_contract_lint.py`. Per install and provider it owns the acceptance of the provider terms the adapter exposes, and the composed hosted-BYOM send verdict with its closed payload gate. It does not own the cloud mode or collection flags (T0365, T0356), provider key storage, provider adapters, provenance and token limits (T1691), redaction (T0392), local model (T0374), delete (T0401), or retry idempotency (T0293/T0302).
2. Record: `install_id` (`^ins1:[0-9a-f]{64}$`), `provider_id` (`^prv1:[a-z0-9]{1,32}$`), `accepted_terms` (null or a `trm1:` digest, derived, never caller-set), `revision` (exact int 0 to 2^63-1, never bool). No history. Registering a known provider is a no-op.
3. Terms: an exact dict of `retention_days` (exact int 0-3650, never bool), `region` (exact str `^[a-z]{2}$`) and `trains_on_inputs` (exact bool), from the provider adapter at send time. Digest: `trm1:` plus the lowercase hex sha256 of the byte-exact preimage: `retention_days` as ASCII decimal (no sign, no leading zeros), `|`, `region` verbatim, `|`, `true` or `false`, UTF-8, no leading or trailing separator (example `30|eu|false`).
4. Send: allowed only when (a) the payload passes the closed schema, (b) the T0365 cloud verdict for this install and collection allows cloud (cloud mode exactly on and the T0356 flag exactly false; composed, never re-owned), and (c) the adapter's current terms digest equals the accepted digest. The verdict returns only `verdict` and `terms_digest`, is read at send time and never cached.
5. Payload (ADR-0004 `hosted-byom.payload_schema`): an exact dict with exact str keys, a subset of `fen`, `moves`, `task`, `max-tokens`, always with `fen` and `task`. `fen`: exact str, 1-128 chars, each 0x20-0x7e. `moves`: exact list, 0-512 items, each an exact str of 1-16 chars, each 0x21-0x7e. `task`: one of `delta-explanation`, `error-diagnosis`, `weekly-plan`, `review-conversation`. `max-tokens`: exact int 1-4096, never bool. Anything else is `payload_rejected`, so `account-keys`, `full-corpus` and `sync-keys` can never be sent.
6. Transitions: accepting terms (including switching from other accepted terms) needs an approval `byt1:` plus the lowercase hex sha256 of the byte-exact preimage: `install_id`, `|`, `provider_id`, `|`, the `trm1:` digest of the terms being accepted, `|`, `expected_revision` as ASCII decimal, UTF-8, no leading or trailing separator. Revoking (`terms: null`) needs no approval and applies before the next send; a well-formed approval on a revoke is ignored, a malformed one is malformed. Accepting the digest already accepted, or revoking with none accepted, is a no-op with the revision unchanged. Compare-and-set on `expected_revision`. A transition at revision 2^63-1 fails typed.
7. Precedence. Send: malformed envelope (including collection id and terms) before `payload_rejected`, before `cloud_mode_off`, before `collection_sensitive`, before `terms_not_accepted`, before `terms_changed`. Transition: malformed (envelope, terms, revision, approval) before `unknown_provider`, before `stale_revision`, before the same-value no-op, before `approval_missing`, before `revision_exhausted`.
8. Rollback: no history operation. A rejected transition or send leaves terms state, switch state, flag state and inputs unchanged. Undoing an accept is a revoke; undoing a revoke is a fresh approval (an old approval is bound to its revision).
9. Errors: `malformed_request`, `payload_rejected`, `unknown_provider`, `conflict`, `approval_required`, `cloud_off` (both cloud refusals), `terms_required` (`terms_not_accepted` and `terms_changed`), `revision_exhausted`, `internal`; only `internal` is retryable. Every raised error is fresh (`__cause__` is None).

## Fail-closed readings (spec silent; owner batch)

Sources: ADR-0004 `external_providers.hosted-byom` (opt-in, default off, `invocation_additional_properties: false`, payload schema, `never_receives`, `relay_plaintext: false`) and invariant `hosted-byom-opt-in-only`; product report v5 section 12 rights matrix ("adapters expose retention/region/training terms; default off for prep") and section 14.

- Terms are accepted per install and per provider, by digest; any change to any terms field lapses the acceptance (`terms_changed`) until a fresh approval (R3, R4).
- The terms shape (retention in days 0-3650, two-letter lowercase region, a training bool) is this contract's reading of "retention/region/training terms" (R3).
- `fen` must be non-empty and printable ASCII; move items must be non-empty printable ASCII without spaces (R5). The ADR gives only maximums.
- The payload is checked before any state, so a bad payload never reveals cloud or terms state (R7).
- The cloud gate is checked before terms, so terms never open cloud (R7).
- An unknown provider reads not accepted (R4).
- At revision 2^63-1 even a revoke is refused with `revision_exhausted` (R6).

Deferred and flagged, not in this contract: provider key storage and the adapter call itself (T1691), token limits and credit accounting, retry idempotency and cancel (T0293/T0302), redaction (T0392), delete (T0401).

- R8: `test_undoing_accept_is_revoke_and_undoing_revoke_needs_a_fresh_approval`, `test_rejected_transition_leaves_everything_unchanged[*]`, `test_refused_send_changes_nothing[*]`.
- Discrimination: `MUTANTS` is an executable table of 79 one-edit mutants of the reference engine; `test_source_mutant_is_killed` runs each on a copy of the battery (kill-check section stripped, no `-k`) and requires rc 1 with all 462 tests run; `test_identity_mutant_is_green` requires rc 0 with exactly 462 passed. `EQUIVALENT` (run green by `test_equivalent_edit_stays_green`): moving the terms check after the revision check, since both raise `malformed_byom_request` before any state is read.

The reference engine composes the T0365 reference `CloudSwitch` and the T0356 reference `FlagStore` (imported, not re-implemented).
