# T0392 Privacy/redaction/contract

## Normative requirements

1. `data/contracts/redaction.yaml` (`privacy-redaction`, `/privacy/redaction/v1`) is a closed contract: exact envelope, closed failure model and closed error enum, pinned field by field by `tools/redaction_contract_lint.py`. It owns the redaction rules and the redaction marker for free text bound for a log line or an error message. It does not own the hosted-BYOM payload schema or provider terms (T0383), the cloud mode or collection flags (T0365, T0356), provider key storage, telemetry collection policy, local model (T0374), delete (T0401), or retry idempotency (T0293/T0302).
2. Request: an exact dict with exact str keys `text` and `secrets`, nothing else. `text`: an exact str of any length (the content rules decide redaction). `secrets`: an exact list of 0 to 64 items, each an exact str of 1 to 4096 characters, from key storage. Secrets are never stored, returned or logged.
3. Outcome: the output is the text verbatim (the same object) or exactly the marker `redacted`, never a partial mask. The text is redacted when any one of these holds:
   - it is longer than 1024 characters (1024 is kept);
   - it holds any character outside 0x20-0x7e (so line breaks, tabs, control characters and all non-ASCII are redacted);
   - its casefold contains the casefold of any secret;
   - it holds a run of 32 or more characters each in `[A-Za-z0-9+/=_%-]` (31 is kept).
4. The rules are order-free: one hit redacts. The output never says which rule fired or which secret matched. The engine is stateless: one verdict per call, never cached.
5. Precedence: a malformed request (every shape and exact-type check, including str/dict/list subclasses, non-str keys, a real key replaced by a str subclass, a same-arity renamed key, `__eq__`-raising and hash-colliding extra keys, an empty or over-long secret and over 64 secrets) fails typed `malformed_redaction_request` -> `malformed_request` before any content rule runs, calls no caller method and leaves the input unchanged.
6. Sink fallback: at a sink, a malformed request emits the marker, never the raw text, and never raises.
7. Rollback: there is no state to roll back. A malformed call raises typed with inputs unchanged; a sink emits only the marker.
8. Stable: redacting an output again with the same secrets returns it unchanged.
9. Errors: `malformed_request`, `internal`; only `internal` is retryable. Every raised error is fresh (`__cause__` is None).

## Fail-closed readings (spec silent)

Sources: ADR-0004 (`hosted-byom.never_receives: [account-keys, full-corpus, sync-keys]`, invariant `server-never-content-or-keys`), `ai-sdk/README.md` ("Prompts, retries, cost tracking, and redaction live here."), and the T0476 precedent (a secret echoed in a control-plane error message makes the message `redacted`). None of them defines the rules, so each rule below is our own fail-closed reading. Each is stated in `redaction.yaml` `semantics.readings` and pinned by the lint.

- Whole message: a partial mask leaks length, position and neighbours, so the whole text is replaced by the marker (the same `redacted` word T0476 uses).
- Charset: non-ASCII text, including legitimate Unicode names and multi-line text, is redacted whole. This also closes log injection through line breaks.
- Secret case: matching is case-insensitive by casefold (so `straße` matches `STRASSE`, and the Kelvin sign matches `k`). This over-redacts by design.
- Token run: unregistered keys, base64 or hex blobs, digests and install ids are redacted even when no secret was passed.
- Not detected (stated gap): a short secret that is split by other characters, or encoded outside the run charset, is not caught. Callers must pass every secret they hold.
- Marker: the marker is a public constant. It is emitted even when it contains a short secret (for example the secret `red`), and it leaks nothing.

Deferred and flagged, not in this contract: retry idempotency and cancel (T0293/T0302), where redaction is wired into the ai-sdk and server sinks (later redaction fixture/implement tasks), telemetry collection policy.

## Requirement-to-test mapping

- R1: `test_contract_lints_clean`, `test_error_model_is_closed_and_consistent`, `test_linked_documents_exist_and_agree`, `test_lint_rejects_mutation[*]` (34 mutations, including every reading and the marker value).
- R2: `test_max_length_secret_is_accepted`, `test_max_secret_count_is_accepted`, `test_empty_secret_list_keeps_clean_text`, `test_secret_bounds_are_malformed[*]` (empty, 4097 characters, 65 items, empty first or last).
- R3: `test_clean_text_is_returned_verbatim[*]` (identity, including all of 0x20-0x7e), `test_marker_known_answer`, `test_length_edges[*]` (0, 1023, 1024 kept; 1025 redacted), `test_long_text_is_redacted_even_when_clean_otherwise`, `test_out_of_range_character_redacts[*]` (0x00, 0x1f, 0x7f, 0x80, LF, CR, tab, é, U+200B, emoji at start, middle, end, alone), `test_printable_edges_are_kept[*]` (0x20, 0x21, 0x7d, 0x7e), `test_secret_anywhere_any_case_redacts[*]`, `test_uppercase_secret_matches_lowercase_text`, `test_secret_match_is_casefold_not_lower[*]`, `test_every_secret_is_checked[*]`, `test_no_secret_hit_keeps_text`, `test_secret_longer_than_text_keeps_text`, `test_text_inside_secret_is_not_a_hit`, `test_one_character_secret_is_honoured[*]`, `test_token_run_edges[*]` (31 kept; 32, 33, 64 redacted; alone, start, middle, end), `test_each_run_character_joins_the_run[*]`, `test_other_characters_break_the_run[*]`, `test_unregistered_install_id_and_digest_are_redacted`.
- R4: `test_output_never_names_the_rule_or_secret`, `test_verdict_is_stateless_and_never_cached`, `test_inputs_are_never_mutated_on_the_happy_path`.
- R5: `test_hostile_request_fails_closed_typed[*]` (each row pins the typed failure, an empty caller-method log, and the input unchanged by key identity, value type and value; loud str/list/dict subclasses record any call), `test_malformed_precedes_content_rules`.
- R6: `test_emit_text_never_raises_and_never_emits_raw[*]`, `test_hostile_request_at_a_sink_emits_only_the_marker[*]` (every hostile row again through the sink).
- R8: `test_redaction_is_stable[*]`, `test_marker_is_emitted_even_when_it_contains_a_short_secret`.
- Discrimination: `MUTANTS` is an executable table of 51 one-edit mutants of the reference engine. They cover every type check, both edges of every bound (text length, secret count, secret length, character range, run length), each run character, casefold vs lower, search vs match, the marker, the sink fallback and the error code and chaining. `test_source_mutant_is_killed` runs each one on a copy of the battery (kill-check section stripped, no `-k`) and requires rc 1 with all 300 tests run; `test_identity_mutant_is_green` requires rc 0 with exactly 300 passed. `EQUIVALENT` (run green by `test_equivalent_edit_stays_green`): `text.casefold()` -> `text.lower()` for the folded text, since every character is in 0x20-0x7e by then, where the two agree.
