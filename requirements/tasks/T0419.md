# T0419 Contracts/OpenAPI/contract

## Normative requirements

1. data/contracts/openapi.yaml is the normative contract. tools/openapi_contract_lint.py pins it exactly, pins the merged mock (tools/control_plane_mock.py) by sha256, parses the mock's `_err` status literals and checks them against the status tables, checks the tables partition control-plane.yaml's closed enum, checks the control-plane error shape, and checks the error code example is in the closed enum, checks the additionalProperties grounding phrases are still in control-plane.yaml, and checks the chess-content (token list read from the pinned privacy rule), write_only and UTF-8 example rules over every source field at every depth.
2. `derive(source)` takes one control-plane contract (schema_version 2) and returns exactly one OpenAPI 3.1.0 document. It validates every section it reads with exact types and exact keys first; any failure is a fresh typed malformed_request error with retryable false, no partial document, and the source left bit-identical.
3. One path per op in source order. Security is bearer except on the public operations. Every mutating op carries the Idempotency-Key header parameter (schema string, minLength 1, pattern \S: the merged mock's reading of "nonempty", since it answers 400 to a whitespace-only key); no read-only op does. GET ops have no request body.
4. write_only fields become writeOnly and appear only in request schemas; no response schema (including Error) carries writeOnly.
5. Every object schema has additionalProperties true (control-plane.yaml: servers MUST ignore unknown request fields; payloads MAY carry extra fields).
6. The Error schema is control-plane.yaml's shape exactly, with code closed to the source closed enum in source order.
7. Statuses: 401 and 409 from the contract; every other status is the merged mock's reading (path and sha256 pinned in the rule text). Codes with no reading (entitlement_missing, provider_unavailable, cost_cap_exceeded, rate_limited, internal) are never given a status: they are listed per op in x-unmapped-errors and globally in x-unmapped-error-codes, for the owner batch.
8. No derived property name contains a chess-content token (split on underscore) at any depth.
9. derive is deterministic and detached from the source. canonical_bytes pins insertion key order, compact separators and UTF-8 with non-ASCII kept; the real control-plane.yaml has a golden sha256.

## Fail-closed readings (spec silent; stated in the contract rule text)

- An integer or number example lies within 2**53 - 1 in magnitude and a float example is finite, so the bytes stay interoperable JSON.
- Every string example and string array item is UTF-8 encodable (no lone surrogate), so canonical_bytes never raises.
- The error shape's code example is one of the closed-enum codes.
- An area may carry notes besides ops only as plain strings.
- A closed-enum code with no contract, mock or unmapped reading is refused.

## Flagged for the owner batch

The five unmapped codes above need statuses from the owner; the mock never emits them.
