# T0429 Contracts/events/fixture

## Requirements

1. tests/fixtures/control-plane-events/cases.json is a closed fixture for the
   landed v1 control-plane operation metadata event contract
   (data/contracts/events.yaml), generated deterministically by
   tools/events_fixture_generate.py: 84 happy, 9 boundary, 51 malformed and 9
   rollback rows, each section pinned by an ordered per-row sha256 manifest.
   It is contract-only: no shipped event emission is claimed or exercised.
2. Happy rows cover every one of the 14 pinned catalog operation IDs with a
   valid success envelope and an operation-scoped failure envelope for every
   error code the source contract declares for that operation (70 failure
   rows). Boundary rows pin occurred_at 0 and 253402300799999, 1- and
   64-character event/correlation identifiers and every allowed identifier
   character class.
3. Rollback rows pin replay semantics: an identical re-publish is a no-op in
   process and across a restart, an identical duplicate inside one batch
   publishes once, a same-id conflicting envelope is refused as a whole batch
   (against the ledger, inside the batch, and after a restart), a mixed
   valid+invalid batch and an injected publication fault leave the published
   sequence and dedupe ledger byte-identical (all-or-none), the caller's
   inputs stay type-exactly unchanged, and the pinned follow-up commits.
4. Malformed rows cover unknown name and version classes, absent and extra
   error_code, every missing required field, undeclared fields, and
   prohibited payloads (chess content, FEN, PGN, provider key material,
   credentials, request body, raw email): each is refused with its typed
   failure class, the refusal never echoes the prohibited value, and every
   row names a minimal repair that validates and publishes.
5. Hostile-type probes are derived from every accepted row at both public
   boundaries (validate and Ledger.publish): hostile containers, str-subclass
   / eq-raising / non-str keys on every field, and hostile str/int/bool/float
   values on every field, plus hostile batch containers. Each is refused with
   the typed class, runs no user code, leaves no partial ledger and leaves
   inputs unchanged. This requirement exposed a real hole in the landed T0428
   reference (str-subclass keys were hashed by set algebra, running user code
   and being accepted); the reference now refuses non-exact-str keys before
   any set algebra, a test-module change only - the contract text is
   unchanged.
6. The joint source+catalog edit test proves the v1 operation catalog
   baseline pin cannot be bypassed even when the catalog list and its digest
   are updated together: the baseline is pinned in the lint itself.
7. Identifier provenance: every fixture identifier is an independent
   synthetic value derived only from the case name (sha256 labels); the
   fixture claims no runtime provenance detection, matching the contract's
   value_policy. Regenerating the fixture reproduces the committed file
   byte-for-byte.
8. Every one of the 26 reference mutants turns the executed fixture red and
   the 3 equivalent edits keep it green; kills come only from executed rows
   (accepted, malformed, rollback and hostile probes), never from
   source-text or table-shape checks.
