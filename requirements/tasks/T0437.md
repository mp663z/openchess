# T0437 Contracts/versioning/contract

`data/contracts/control_plane_versioning.yaml` defines a pure compatibility verdict for two validated snapshots of the replaceable control-plane contract. It is distinct from `data/contracts/version.yaml`, which versions graph content, and from T0419, which derives an OpenAPI document. The normative source is `control-plane.yaml` schema_version 2, `contract.versioning`.

Same-major minor upgrades permit new optional request fields, new optional response fields, operations and provider_kind values, not changes or deletions of existing declarations. This reads the closed MINOR list and any-client-minor rule at control-plane.yaml lines 13-19: new required response fields, optional-to-required in either direction, and new required request fields all require MAJOR with a new base path. The server ignores unknown request fields; earlier-minor clients tolerate extra response fields. Cross-major compatibility is not claimed. A client's earlier MINOR works against a later same-major server without migration. The contract cannot infer semantic behavior from schema snapshots; runtime conformance is out of scope.

A malformed snapshot or minor is rejected as a fresh typed `malformed_request`, not a compatibility verdict. A validated but incompatible pair returns false. Both snapshots are unchanged even after rejection. Tests must cover happy, boundary, malformed, hostile-type, rollback and one-edit mutants; only behavioral rows count for kills. The source contract, lint, and T0419 derivation are linked rather than copied.
