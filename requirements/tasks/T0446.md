# T0446 Contracts/errors/contract

Source: `data/contracts/control-plane.yaml` schema_version 2, `contract.transport.errors`. The pure classifier reads the source closed_enum and exact declared error shape; it does not invent per-code HTTP statuses (T0419 owns status grouping). An HTTP 2xx is success even with an `error` property; an HTTP 4xx or 5xx has a declared error object with code, message and retryable of exact built-in types. Additional error fields may be carried, including at top level, but private content and key material cannot leak. A declared 2xx response field such as the identity operations' token is exempt only from the name-based secret check; it still passes structural and chess-content checks. Undeclared 2xx extras and all error-path fields get full secret checks. Unsupported 1xx/3xx have no contract payload semantics and are refused as a stated fail-closed reading. Malformed and hostile source/status/payload are fresh typed errors and leave inputs unchanged. A later implement task must independently implement the classifier.

The reference classifier uses T0419's strict derivation to validate the source error shape and reads its pinned chess-token rule; it does not duplicate the status table. The battery tests every declared operation's 200 example, the 8/9 nesting and 256/257 collection bounds, both infinities, case/hyphen secret and chess keys, hostile 2xx payloads, and behavioral reference mutants.

Privacy result: chess-content checks (key tokens, FEN values) apply to every response; secret-name checks apply to all but declared fields. Short SAN/move text (e.g. Nf3, e4) is not detected; a short-SAN detector would false-positive on ordinary text and is left for owner review. Key-shaped values remain a stated gap. Key tokenization splits punctuation (including dots), lowercase/digit-to-uppercase camelCase, and acronym-to-title-case boundaries. FEN placement searches every candidate window derived from `fen.yaml`, including glued prefixes and punctuation. Nine ranks containing a valid eight-rank window are refused. Invalid digit, rank count, or rank sum is a near miss only if no valid eight-rank window exists. The model has behavioral rows for nested lists, declared 2xx strings, undeclared 2xx extras, error messages, and clean declared 2xx data.

FEN substring rule: refused if ANY substring, at any start and end offset, is a valid 8-rank placement. No edge exclusions. This includes a valid placement glued to letter or digit suffix/prefix and the last eight ranks of a nine-rank run; `44/8/8/8/8/8/8/8` remains allowed because no eight-rank substring sums correctly. A zero-digit member mutation is equivalent for `08/...` and `0p7/...`: the strict model already rejects their valid suffix windows, and the relaxed mutant does too. Do not count that as a kill.

The FEN substring check runs in linear time in each value length. The reference splits once on slashes, slides an eight-segment window, and checks only bounded rank suffix/prefix candidates (at most eight characters each). A declared-size stress row covers 256 extras of 64k characters and a slash-dense 64k string within an eight-second CI budget. A quadratic offset-scan mutant is behaviorally red on the timing ratio; no production implementation should copy a quadratic scan.

Middle-rank and later-window checks: a bad rank in any of the six middle positions makes an eight-segment candidate a near miss unless another valid eight-rank window exists. The search must advance beyond the first window, including a slash-separated prefix (`x/` or `1/2 `) before a valid placement. Behavioral mutants that drop the last middle rank or restrict the scan to the first window are red; rank-length cap and fewer-than-eight-segments guards are documented equivalents behind the remaining checks.

T0392 token-run rule applies to string values and keys in error responses, including nested: 32 or more contiguous `[A-Za-z0-9+/=_%-]` characters are refused, 31 are allowed. CamelCase and digit boundaries do not break the run. It catches long encoded or split move/key runs, not short SAN. Success responses keep their declared token values subject to the existing chess-content and structural checks.
