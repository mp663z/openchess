# T0476 Control-plane consumer client

## Normative requirements

1. `server/control_plane_client.py` is the consumer-side client for the control-plane contract (`data/contracts/control-plane.yaml`). Operations, paths, methods, request/response fields, per-op error lists, the closed error enum, the self-destructive set, the entitlements TTL field and the reservation expiry field are all read from the YAML. Nothing outside the YAML is pinned. The transport is `transport(method, path, headers, body) -> (status, payload)`; paths are relative to `/cp/v1` and the transport owns the base.
2. Token lifecycle: the bearer token is refreshed through `identity.refresh` before a call once `now >= token_expires_at - refresh_skew_seconds` (default 60 s, inclusive edge). A locally expired token (`now >= token_expires_at`) raises `auth_expired` and clears the session without sending. No token raises `auth_invalid` without sending. A server `auth_expired` or `auth_invalid` clears the session. Auth errors are never retried and never masked by the entitlements cache.
3. Retries: a transport failure or an error with `retryable: true` is retried up to `max_attempts`, reusing the same `Idempotency-Key` for every attempt of one logical call. A non-retryable error is raised at once. Exhaustion raises a retryable `internal`.
4. Entitlements: a successful `entitlements.get` is cached with its `cache_ttl_seconds`. When the server is unreachable (transport failure or 5xx), a cache younger than the TTL is served; at exactly the TTL it is expired. With no usable cache the client degrades to the free tier: tier `free`, features `[]`, TTL 0, every cost cap 0.0. `identity.logout`/self-destructive ops drop the session and the cache.
5. Reservations: a reservation is treated as released at `expires_at` (inclusive). Releasing an expired reservation returns `{}` without sending; committing one raises `quota_reservation_expired` without sending.
6. Key material is never logged: the log hook gets only `(operation, status, code)`. A write-only request value echoed in a success payload makes the call `internal`; echoed in an error message, the message is replaced with `redacted`.
7. Closed errors: every raised error is a `ControlPlaneError` whose code is in the enum. A server error code must be in the enum AND declared for that op, with a str message and a bool `retryable`; otherwise `internal`. Responses are validated against the op's response fields (extra fields ignored, as the contract allows minor additions); malformed payloads are `internal`.
8. Hostile types: request bodies and nested objects must be plain `dict`, strings plain `str`, integers plain `int` (bool refused), arrays plain `list`; keys must be plain `str`. List, dict and str subclasses, keys whose `__eq__` raises and keys whose `__hash__` collides with a real key are refused as `malformed_request` with no send, an empty hostile-call log and the input unchanged. Transport results that are not a plain 2-tuple of an in-range plain `int` status and a plain `dict` payload are `internal`.
9. Untrusted callables (transport, clock, key factory) are caught with `BaseException` and map to a fresh `internal` (not the forged object, `__cause__` is None). A clock value that is not a plain finite int/float, or a key that is not a non-blank plain `str`, is `internal`. A raising log hook never changes the outcome.

## Fail-closed readings (spec silent; owner batch)

- Free-tier shape (R4): tier `free`, no features, TTL 0, caps 0.0.
- Cache and reservation boundaries are inclusive-expired (R4, R5); refresh skew edge is inclusive (R2), default 60 s.
- Local expiry is checked before sending and maps to `auth_expired`; no token maps to `auth_invalid` (R2).
- "Unreachable" for cache fallback means transport failure or 5xx; 4xx never falls back (R4).
- An error code in the enum but not declared for the op is `internal` (R7).
- A secret echoed in a success payload is `internal`, not redacted (R6).
- Release of an expired reservation is a local no-op returning `{}` (R5).
- Deferred, not implemented: T0293/T0302 idempotency-window and cancel semantics beyond key reuse inside one logical call.

## Requirement-to-test mapping

- R1-R7: `test_behaviour[*]` (one row per `check_*`), `test_reference_mock_is_certified_by_the_harness`, `test_every_mutant_server_never_yields_a_contract_violating_payload`, `test_extra_response_fields_are_ignored`.
- R8: `test_hostile_request_is_malformed_unsent`, `test_hostile_operation_name_is_malformed_unsent`, `test_hostile_transport_result_is_internal`.
- R9: `test_transport_raising_anything_is_a_fresh_internal`, `test_raising_clock_or_key_factory_is_a_fresh_internal`, `test_bad_clock_value_is_internal`, `test_bad_idempotency_key_is_internal_unsent`, `test_raising_log_hook_never_changes_the_outcome`, `test_bad_constructor_arguments_are_refused`.
- Discrimination: `test_source_mutant_is_killed` runs the executable `MUTANTS` table (one-edit production source mutants, each executed into a fresh module) against the whole battery, hostile rows included; each must go red. `EQUIVALENT` lists the two equivalents with reasons: dropping the enum check (every op's declared errors are a subset of the enum) and `isinstance` for nested objects (`_valid` re-checks the nested payload type). `test_equivalents_are_not_in_mutants` keeps the tables disjoint.
