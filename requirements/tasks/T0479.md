# T0479 Contracts/replaceable control plane/integration/restart

`tests/test_t0479_control_plane_integration_restart.py` exercises the shipped
consumer-side `server/control_plane_client.py` against the T0474 conforming
mock. It is additive to T0476 (declarative contract), T0477 (properties) and
T0478 (multi-attempt fault trajectories in one process): this suite owns
whole-surface integration and process restart. No production or contract
change.

## Normative requirements

1. Integration flow: one session across all 14 operations of
   `data/contracts/control-plane.yaml` (identity.register, identity.login,
   identity.refresh, identity.logout, identity.delete_account,
   entitlements.get, quota.reserve, quota.commit, quota.release,
   provider_routing.register_key, provider_routing.revoke_key,
   provider_routing.route, billing.create_checkout,
   billing.get_subscription). Every wire call matches the contract read from
   the YAML: bearer only on auth-required operations, exactly one fresh
   Idempotency-Key per logical mutating call, none on read-only operations,
   paths and methods from the contract; the set of wire routes equals the
   contract operation set. Server effects are asserted on the mock: quota
   arithmetic and reservation refunds, the key registry (present after
   register_key, empty after revoke_key, routing falls back to platform),
   token rotation on refresh, server-side credential revocation on logout
   (a revoked bearer answers 401), account and token removal on
   delete_account.
2. Consumer restart model: the client holds no durable state - token, token
   expiry, account, entitlements cache and reservation tracking are all
   per-instance attributes. A restart is therefore a fresh
   `ControlPlaneClient` over the same server. The equivalence is proven, not
   assumed: the identical scripted scenario runs in a fresh interpreter
   (subprocess) with the server's state handed over across the process
   boundary, byte-identical to the in-process run, and fresh-interpreter
   output is byte-identical across PYTHONHASHSEED values.
3. Resume after a consumer restart: a fresh client holds no token; authed
   calls are refused locally (`auth_invalid` preflight, nothing sent), and a
   preflight refusal is not an outage - `entitlements()` neither serves a
   cache nor degrades on it. After re-login (same persisted account, new
   token), a pre-restart reservation commits on the server's authority with
   exactly one send and correct quota arithmetic.
4. Persistence across a consumer restart: server-side idempotency replays a
   pre-restart mutating call (same key, byte-identical body) with the
   original outcome and exactly one effect; the replayed success
   re-establishes local reservation tracking. The same key with a different
   body answers typed `idempotency_conflict` with no retry. Local tracking
   does NOT cross the restart: no local expiry shortcut fires (the commit
   crosses the transport even when the injected client clock is past
   `expires_at`), and the entitlements cache is gone (a post-restart outage
   degrades to the free tier, never the stale cache). A server-side expired
   commit after a restart retries one key and refunds exactly once.
5. Control-plane restart: against a fresh plane the held token is unknown -
   a 401 `auth_invalid` clears the session in one final send (no retry, no
   cache fallback). Account, reservation and idempotency stores are lost:
   re-login fails `auth_invalid` until re-register; committing a pre-restart
   reservation answers typed `not_found`; replaying the old key re-executes
   (no cross-server-restart dedupe). A failed commit deletes no local
   tracking (conservative).
6. Malformed after restart: seeded malformed requests are refused before the
   transport with the fresh client's state unchanged; a malformed 2xx is a
   terminal `internal`, caches nothing, and is not retried.
7. Rollback after restart: failed mutating calls (a `not_found` commit, an
   exhausted `quota_exhausted` reserve) change no local state and no server
   state; a later valid call continues the flow.
8. In-place session restarts: logout forgets tracked reservations (a later
   commit crosses the transport even past local expiry) and re-login drops
   the entitlements cache (a later outage serves the free tier, not the
   stale cache).
9. Mutation check: four one-edit production source mutants, each executed
   into a fresh module, must fail their pinned restart probe with the
   recorded failure: class-shared reservation tracking, cold-cache outage
   degradation, logout retaining reservations, re-login retaining the cache.

## Fail-closed readings (spec silent; builder judgment calls, pending independent verification)

- The client has no durable form, so "malformed durable bytes" does not
  apply; malformed coverage is malformed requests and responses after a
  restart.
- The T0474 reference plane is in-memory: its idempotency and reservation
  stores survive a CONSUMER restart but not a control-plane restart. The
  contract is silent on server-side durability windows; no
  cross-server-restart dedupe and no server rollback is claimed (consistent
  with T0478's reading; T0293/T0302 idempotency-window and cancel semantics
  stay deferred).
- A preflight auth refusal is not an outage for `entitlements()`.
- Local reservation tracking is advisory only; once it is lost (restart),
  the server is the sole authority, including at the inclusive local expiry
  boundary (the server's own wall clock decides; the reference mock expires
  strictly after `expires_at`, so the exact-equality server boundary is not
  exercised by this suite).
- Failed mutating calls never delete local tracking: a server `not_found`
  leaves the local record in place.
