# T0542 Import/PGN/E2E restart

## Normative requirements

1. tests/test_t0542_import_pgn_e2e_restart.py crashes the shipped import-pgn CLI (`ingest.import_pgn.main`, run in a subprocess) at every persisted write step, then restarts it with the plain shipped command `python -m ingest.import_pgn` in a new process, and checks the persisted state on disk. The crash harness counts only the writes the import performs (`Path.write_text`, `os.replace`, telemetry appends) and exits the process with `os._exit(137)` at write N. There are two modes: just BEFORE the write, or after writing half the payload (a torn temp file). Nothing else in the shipped path changes.
2. Scenarios: a new import of 3 seeded games (19 writes: 19 before-crashes and 7 torn temps), and an update, where the same corpus with a non-identity tag added to game 2 is imported onto the committed 3-game store (2 duplicates and 1 recorded update). A clean single run of each gives the reference store.
3. In every crash window the store reads as pre-commit or fully committed:
   - the index is an in-order prefix of the clean run's index (for an update, membership and order don't change);
   - every entry names a present record that is byte-identical to a clean version;
   - no torn index.json is ever visible;
   - the telemetry never claims more stored or updated games than the index commits.
4. After the restart:
   - exit 0;
   - index and referenced records are byte-identical to the clean run;
   - no stale `.tmp` remains;
   - exactly the missing games are imported, and committed ones are already-imported no-ops (exact summary counts);
   - the restart's telemetry begins with import.started and ends with import.completed.
   One more run is a pure no-op that leaves only the clean committed state: every unreferenced candidate, including an update's superseded version, has been recovered away.
5. An update crashed just before its index rename leaves the OLD version indexed and readable, plus exactly one unreferenced candidate. The restart commits the update.
6. Adjacent negatives, each starting from a real crash residue:
   - a restart with an out-of-scenario source (`lichess-api`) is refused as unknown_rights before recovery, and the residue stays byte-identical; a proper restart then recovers;
   - a restart whose corpus corrupts game 3, after a crash that tore game 3's record temp: recovery removes the torn temp, game 3 is refused, games 1-2 stay committed, the restart telemetry is started, duplicate, duplicate, and no summary is written;
   - three restarts that commit nothing, after a crash that tore a store-ROOT temp: game 2's index.json temp (write 1+5+3) or the summary.json temp (write 1+5*3+1+1), each restarted on a corpus that corrupts game 2; and game 3's index.json temp (write 1+5+5+3), restarted on a corpus that corrupts game 3. Before the restart, the residue must hold exactly that root temp (index.json.tmp or summary.json.tmp). The committed games are duplicates and the corrupted game is refused as malformed_request. The index stays the clean prefix (1, 3 or 2 games), no `.tmp` remains anywhere under the store (root included), the telemetry is started then one duplicate per committed game before the refusal, and no summary is written. Nothing overwrites the stale root temp here, so only the recovery sweep can remove it;
   - a referenced record deleted after a crash: the restart is refused as partial_visibility (code internal) and the store is untouched.
7. Source mutants of ingest/import_pgn.py, each killed by the battery:
   - `recovery-keeps-tmp` (killed by the corrupted-game negative: the stale temp survives);
   - `recovery-root-sweep-dropped` (the sweep only globs games/*.tmp: the root-temp negatives see index.json.tmp or summary.json.tmp survive);
   - `recovery-keeps-candidates` (update sweep: the superseded version survives the no-op rerun);
   - `index-before-record` (commit order swapped: the index names a missing record, and the restart is refused);
   - `write-in-place` (no temp file: a torn index.json becomes visible);
   - `telemetry-before-commit` (import.game_stored is logged before the commit that it claims).

## Scope

This covers the local import-pgn CLI on one machine, one writer at a time, with process kills at write boundaries and torn temp writes. It does not cover power loss below the filesystem (no fsync is asserted), concurrent writers, or other import scenarios.

## Requirement-to-test mapping

All in tests/test_t0542_import_pgn_e2e_restart.py.

- R1, R2: `test_clean_run_shape` (write layout and counts pinned).
- R3, R4: `test_crash_at_every_write_of_a_new_import_then_restart`, `test_crash_at_every_write_of_an_update_then_restart`.
- R5: `test_update_crashed_before_its_commit_keeps_the_old_version`.
- R6: `test_restart_with_a_refused_source_leaves_the_crash_residue`, `test_restart_with_a_corrupted_later_game_recovers_and_keeps_the_prefix`, `test_restart_with_a_dangling_index_entry_is_refused_untouched`.
- R7: `test_source_mutant_is_killed` (5).
