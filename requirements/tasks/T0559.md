# T0559 Import/UTF8/contract

`tests/test_t0559_import_utf8_contract.py` is a pure reference battery for `import-utf8` in `data/contracts/import.yaml`. T0561 replaces only its named `PRODUCTION_BINDING` with an adapter around the shipped implementation. Do not bind T0559 to production yet. The reference uses T0548's pure game-store model under the T0559 source set (`pgn-file`, `pgn-multi`) and retains source ID in record and provenance.

Valid UTF-8 must preserve multibyte tag values exactly even when a code point straddles chunks; chunk size does not change summary, identity, stored record, or ordered started/stored/completed telemetry. Tests use sizes 1, 2, 3, 4, 7, 64 and 1024 bytes for both source IDs. A black-box mutant that replaces valid Unicode with U+FFFD is red.

The contract picks fail-closed: `failure_mapping.malformed_input.trigger: bytes-not-well-formed-for-source-kind` maps to `malformed_request`. Decode the whole byte stream strictly before any state or telemetry effect; invalid lead, truncated multibyte at EOF, overlong form, encoded surrogate and invalid continuation across a chunk boundary are refused with malformed_request and no records, index, telemetry or summary. A black-box replacement-decoder mutant is red. This is the coordinator's reading of import.yaml, not an attempt to canonize current behavior.

Production divergence for T0561 implement task: `ingest/streaming.py@edca013da68f34bfad9325a18a9ced368e5c4a53` uses `codecs.getincrementaldecoder("utf-8")(errors="replace")` and says invalid bytes become U+FFFD. It must reject malformed UTF-8 instead. When integrating, handle the error as `malformed_request` before any state, not a raw UnicodeDecodeError, and preserve valid split code points. `ingest/import_pgn.py@ea0c9f94f8b87107e7a51e82d620e7ecd0d15097` currently consumes that splitter, but this contract task makes no production edits.

Open: byte-order-mark treatment, Unicode normalization policy, and whether a later malformed byte after already committed games should roll back earlier per-game commits or merely reject the in-flight game. The fail-closed pre-state reading here intentionally takes no writes on malformed bytes; the implement task should flag a conflict if the per-game atomicity rule requires a different outcome for a later byte error. No special summary or telemetry event outside the merged T0537 shapes is inferred.
