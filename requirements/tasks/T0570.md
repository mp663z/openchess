# T0570 Import/bad tags/contract

`tests/test_t0570_import_bad_tags_contract.py` is a pure reference battery. T0572 (verified in tasks/dag.json) replaces its `PRODUCTION_BINDING` with the shipped bad-tags importer. The direct `import.yaml` scenario fields are `pgn-file`/`pgn-multi`, `refusal-with-location`, one `rejection-record`, `import.started`, `import.game_rejected`, `import.completed`, and `malformed_request`. The result is a refusal, not an imported game or partial record. Three tag failures include unclosed bracket, duplicate tag and unquoted tag value; both sources are checked. Three black-box mutants drop the rejection record, location or event and are red through the binding.

The contract names location and rejection record but does not define a shape. T0537 has only unstructured `ImportFailure.message`, not structured location. Fail-closed reading: the narrowest location is `{game_number: 1, line: N}`, where the line is the offending tag line and the game is one-based. A rejection record carries `kind`, `source_id`, `game_number`, `code`, `detail`, and `location`; this is a test-only reference shape, not a claim that the current production path emits it. The structural shape and line-base are flagged for owner review; no byte offset, column, filename, or absolute corpus line is invented.

Production divergence for T0572: `ingest/import_pgn.py@ea0c9f94f8b87107e7a51e82d620e7ecd0d15097` catches `MalformedPGN` and raises `ImportFailure(malformed_input)` rather than persisting a rejection record or emitting `import.game_rejected` and `import.completed`. `ingest/pgn.py` supplies tag validation and unstructured detail, but not the scenario's refusal output. The merged executable reading fills only the absent tag syntax, not the explicitly declared outcome.

The line (or ply for an illegal move) is relative to the rejected game, not the full file. A valid game 1 followed by rejected game 2 returns game_number 2 and a game-relative marker. Intake of an out-of-scenario source ID is Refusal(unknown_rights) with no state or telemetry.
A duplicate tag names its second occurrence as the offending line, including a non-adjacent repeat; the first occurrence is valid.

On a valid game 1 followed by a rejected game 2, game 1 remains committed and indexed while game 2 leaves no game record. The refusal marker is relative to game 2. This follows T0548's already-pinned per-game prefix-commit reading; T0572/T0583/T0594 inherit it. Telemetry for that mixed run includes game_stored between started and game_rejected/completed.

Reference location follow-up: an unterminated comment or open variation reports the line of the last unmatched opening `{` or `(`, not the last line of the rejected game. A multiline row pins the opener on line 11 with content continuing on line 12. This is the coordinator's narrow location reading, flagged for owner review. T0581 remains a separate truncated-at-EOF scenario whose location is the final line.

Unmatched-opener location follows the validator's movetext tokenization: a semicolon starts a line comment only outside variations; parentheses inside a variation are tracked. A depth-zero semicolon comment's parenthesis is ignored, while a parenthesis after a semicolon inside a variation remains a live opener. Whether this validator treatment of semicolons inside variations matches the broader PGN standard is an owner question, not changed by this test-only follow-up.
