# T0592 Import/illegal/contract

`tests/test_t0592_import_illegal_contract.py` is a pure reference battery. T0594 (verified in tasks/dag.json) swaps its `PRODUCTION_BINDING` to the shipped illegal-movetext importer. Import.yaml directly requires pgn-file/pgn-multi, `refusal-with-position`, one persisted rejection record, `import.started`, `import.game_rejected`, `import.completed`, and error code `illegal_move`. The game is not partially stored and no import summary is emitted. Two illegal SAN examples are checked for both sources. Four black-box mutants drop position, misclassify the code, lose the record or suppress the event, each red through a binding probe.

The contract names position but not its shape. T0537's validator emits an unstructured message `illegal SAN in position: 'Ke3'` but no board state or structured move coordinate. Fail-closed narrow reading: `{game_number: 1, san: 'Ke3'}` identifies the refused token within its game, without inventing a FEN, ply number, file offset or board coordinate. The rejection record contains kind, source_id, game_number, code, detail and position. This shape is flagged for owner review; the lack of a concrete board-position representation is open.

Production divergence for T0594: `ingest/import_pgn.py@ea0c9f94f8b87107e7a51e82d620e7ecd0d15097` catches IllegalMove and raises ImportFailure instead of emitting the scenario's refusal-with-position, persisted rejection record and game_rejected/completed telemetry. PGN syntax from `ingest/pgn.py` is reusable, not the conflicting failure outcome.
