# T0614 Import/updated/contract

`tests/test_t0614_import_updated_contract.py` is a pure reference battery. T0616 (verified in tasks/dag.json) swaps only its `PRODUCTION_BINDING` with the shipped updated-game importer. The direct `import.yaml` requirements are `visible_output: updated-summary`, a replaced record with provenance and index entries, ordered started/game_updated/completed telemetry, and source IDs pgn-file, pgn-multi, pgn-folder. A same-game_id/different-content_sha256 edit is a recorded replacement, not a duplicate and not an additional indexed game. The battery compares the old indexed record with the new, preserves the old version as a candidate while the index points to the new version, and tests the three sources. Three black-box mutants change kind, keep the old content hash or drop game_updated; each is red through the binding probe.

T0537 merged reading gives the `source_id`, `games_imported`, `games_already_imported`, `games_updated` payload count fields under `kind: updated-summary`, with 0/0/1 for a single updated game. The payload field choice is flagged because import.yaml names the output kind but not its payload keys. The complete six identity headers keep game_id stable across a legal move edit; index points to the content-addressed new record. This follows `ingest/import_pgn.py@ea0c9f94f8b87107e7a51e82d620e7ecd0d15097` and `tests/test_t0537_import_pgn_contract.py@c4ebc6de658210f63f6772613322ed7ac467dcdd`.

Its replacement/index/telemetry behavior supplies the merged details but does not override the explicit output label. No production changes here.

The test owns the seed import and snapshots its index, record dicts and encoded record bytes before the second call. The named production binding is used only for the second call, so T0605/T0616 can swap it without a test helper planting the expected state. Wrong source is Refusal(unknown_rights) with no effects. A black-box liar that rewrites a duplicate or fakes an update without moving the indexed record is red against the independently captured pre-state.

The update record-set invariant is exact: old record filenames plus only the new indexed record filename. An extra unreferenced junk record is a red black-box mutant.
