# T0625 Import/10k/contract

`tests/test_t0625_import_10k_contract.py` is a pure reference battery. T0627 replaces only its `PRODUCTION_BINDING`; this task does not change production dispatch. The test owns its deterministically generated legal PGN corpus with distinct full-header game identities, rather than committing a 10k-game blob. The `import.yaml` scenario pins pgn-file/pgn-multi/pgn-folder, `progress-and-summary` as the visible kind, game records with provenance and unique index entries, and the presence of started/progress/game_stored/completed telemetry. A 10,000-game row checks every indexed record and its provenance. T0537 fills the otherwise unspecified summary count shape: source_id, games_imported, games_already_imported and games_updated (10,000/0/0 for the full corpus). Seven black-box mutants cover wrong kind, missing progress, absent record, false count, completion before the last stored game, wrong malformed-input code and skipping a malformed game. A malformed middle game is refused with `malformed_request`; both a five-game case and a 10,000-game case (bad game 5,000) preserve only the fully formed prefix with no partial bad game, no later game and no summary.

Open owner details: `import.yaml` does not specify progress cadence, event payload, exact interleaving with game_stored, or a progress-and-summary payload beyond the visible kind. The battery requires at least one progress event and completion after the final game, but does not pin cadence, payload or exact interleaving. It uses T0537's count fields as the narrow merged payload reading, flagged for owner review. Whether `import.progress` must or may appear before a mid-run refusal is also unspecified, so the failure row allows it but does not require it. There is no stated time or memory bound, so the battery adds no arbitrary performance threshold.

Production divergence for T0627: the current `ingest/import_pgn.py` implements only the `import-pgn` scenario/source (`pgn-file`), returns `kind: import-summary`, and does not emit `import.progress`. It cannot presently fulfill the 10k scenario's three sources, visible kind or progress event. The pure reference must not canonize those gaps as expected behavior.

Open owner decision: the scenario lists only `malformed_request`, while the T0537 validator classifies an illegal SAN as `illegal_move`, and the shared T0548 reference importer carries that code through after prior games commit. The battery does not map illegal SAN to `malformed_request` or pin `illegal_move` for T0625 until the owner decides how the scenario closed error list applies. The malformed-structure case uses the listed code.
