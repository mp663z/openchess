# T0636 Import/folder/contract

`tests/test_t0636_import_folder_contract.py` is a pure reference battery; T0638 swaps only `PRODUCTION_BINDING`. The test owns the folder input and seeds each PGN in memory. `import.yaml` requires source `pgn-folder`, output kind `per-file-and-total-summary`, game records/provenance/index entries and rejection records, started/file_completed/game_stored/game_rejected/completed telemetry, and `malformed_request`. The mixed fixture has a good game, a malformed game and another good game in `a.pgn`, then a good game and malformed game in `b.pgn`, and a good game in `c.pgn`: the failed game is not indexed, valid games before and after it remain stored, a rejection is persisted, each file completes, and the folder completes. A malformed game is rejected and processing continues, as the scenario's rejection-records and completed event require. Malformed request shape and unknown source are refused before state.

Coordinator reading flagged for owner review: the rejection's narrow location is `{file, game_number, line}` with the path relative to the folder, game number within the file and line relative to that game, following T0570's malformed-location rule. The rows pin rejections at `a.pgn` game 2 and `b.pgn` game 2 line 11 (not a folder-global game number). A multiline unclosed comment proves that line 11 is its unmatched opening brace, not the last line of the game. The shared T0570 reference opener locator is amended separately ahead of this commit; T0581 keeps its scenario-specific EOF location. The file summaries use T0537's exact count fields (`kind: import-summary`, `source_id`, `games_imported`, `games_already_imported`, `games_updated`), identified by relative file path; the total uses the same count fields and equals the sum of the per-file counts. The outer kind is the explicit `per-file-and-total-summary`. The sample's 2+1+1 imported games give total 4, with no duplicate or update. Per-game atomicity means neither the rejected game nor a partial game record or index entry is visible. The record's provenance carries `source_id: pgn-folder`, rights class `user-own` and retrieval detail as the relative filename. Five black-box bindings lose rejection, falsify total, duplicate an index entry, omit a file_completed event or corrupt location; each goes red. Cross-file duplicate and update probes pin per-file and total count vectors 1/1/0 and 1/0/1, preserve one index entry per game_id, keep a no-op duplicate unchanged and point an update to a new content-addressed record. The folder event list is closed; duplicate and update emit no per-game event rather than a false game_stored or an undeclared game_duplicate/game_updated. This event suppression is a coordinator reading flagged for owner review.

Open owner details: `import.yaml` does not say whether folder iteration is sorted, so the fixture supplies its own deterministic order but does not mandate a filesystem sort rule. Non-PGN files and subdirectories have no stated inclusion policy; the reference fails closed before any state if either is present, also flagged. Summary wrapper field names `files` and `total`, a per-file kind, empty folders and empty `.pgn` files, case sensitivity of `.pgn`, symlinks, and the disposition of illegal SAN in this scenario are not explicit; the reference tests the narrow T0537-derived count payload but does not pin the other choices. An empty `.pgn` currently yields a zero-count file_completed in the reference; this is provisional. An illegal SAN currently raises `illegal_move` after any committed prefix without a folder summary or completion; because the folder error list names only `malformed_request`, this is likewise provisional and unpinned. No invented time or memory bound.

Production divergence for T0638: `ingest/import_pgn.py` currently implements the `import-pgn` scenario for `pgn-file` only, emitting `import-summary` and no folder-level `import.file_completed`/`import.game_rejected` events or per-file totals. This reference does not change production dispatch.
