# T0648 Import/cancel/rights fixture

`tests/test_t0648_import_cancel_rights_fixture.py` pins rights behavior for the T0647 cancel scenario against `data/contracts/import.yaml` and `data/contracts/rights_policy.yaml`:

- Each scenario source (pgn-file, pgn-multi, pgn-folder) resolves to the registry class `user-own` with the exact policy flags (never redistributed, no third-party storage, provenance required).
- Every source outside the scenario is refused as `unknown_rights` with no records, index, telemetry or summary. That includes `pgn-watch`, which is `user-own` in the registry but not a scenario source, so the adjacent-negative row shows that the scenario list, not the rights class, gates the run. Unknown ids and case or whitespace variants are refused the same way.
- A cancelled run persists committed games only, and every persisted record carries the scenario source id and `user-own` provenance. Index and record membership are compared, so a record for the in-flight game or an index entry without a record is red.
- The cancelled summary names the scenario source.

It runs against T0647's `PRODUCTION_BINDING`, so the implementation task (T0649) re-runs these rows without edits. It adds no fixture file; inputs come from the T0647 battery. Five black-box bindings (wrong rights class stamped, provenance dropped, outside source allowed, telemetry written before a refusal, in-flight game persisted) are each red through a behavioral probe.

Not asserted: counts, update/duplicate handling and refusal ordering (they stay with the T0647 contract battery).
